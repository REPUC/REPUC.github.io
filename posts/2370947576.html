# Ansible 常用模块详解（上）：文件与命令类

本文讲解 Ansible 中与"命令执行"和"文件管理"相关的常用模块：command、shell、script、copy、get_url、fetch、file、stat、unarchive、archive。这些模块是日常运维中用得最多的，掌握它们就能完成大部分批量操作。

# 模块概览

Ansible 模块数量众多（目前总量约 3387 个），但最常用的也就 2~30 个，针对特定业务通常只用 10 几个。可用 ansible-doc -l | wc -l 查看模块总数，ansible-doc -l 列出全部模块。

常用模块帮助文档：

  • https://docs.ansible.com/ansible/2.9/modules/modules_by_category.html
  • https://docs.ansible.com/ansible/2.9/modules/list_of_all_modules.html

幂等性提醒：command、shell、script 这三个模块不具有幂等性，重复执行会产生不同结果；而 copy、file、stat 等模块具备幂等性。优先能用幂等模块解决的问题，不要用命令类模块。

# 一、command 模块

功能：在远程主机执行命令，是默认模块（可省略 -m 选项）。

注意：

  • 不支持 $VARNAME、<、>、|、;、& 等符号，建议用 shell 模块实现；
  • 不具有幂等性。

示例：

# command 模块不支持重定向
ansible websrvs -m command -a 'echo hello > /root/hello.log'
ansible websrvs -m command -a 'cat /root/hello.log'

# 不支持变量引用
ansible websrvs -m command -a "echo $HOSTNAME"

# 不支持管道符
ansible websrvs -m command -a 'echo <密码> | passwd --stdin testuser'

# 仅支持简单 Shell 命令，且不具备幂等性
# 首行 WARNING 提示该操作可用其他模块代替
ansible websrvs -m command -a 'mkdir /data'
ansible websrvs -m command -a 'touch /data/1.log'
ansible websrvs -m command -a 'ls /data'

部分参数演示：

# chdir 参数：先切换到 /data 目录，再执行 ls -l
ansible websrvs -m command -a 'chdir=/data ls -l'

# creates 参数：若 /data/mysql 存在则跳过创建，不存在则创建
ansible websrvs -m command -a 'creates=/data/mysql mkdir /data/mysql'

# 二、shell 模块

功能：与 command 相似，用 Shell 执行命令，支持 *、$、> 等各种符号。

注意：不具有幂等性。

示例：

# 支持变量引用
ansible websrvs -m shell -a 'echo $HOSTNAME'

# 支持管道符
ansible websrvs -m shell -a 'useradd testuser'
ansible websrvs -m shell -a 'echo <密码> | passwd --stdin testuser'
ansible websrvs -m shell -a 'ls -l /etc/shadow'

# 支持重定向
ansible websrvs -m shell -a 'echo hello > /data/hello.log'
ansible websrvs -m shell -a 'cat /data/hello.log'

复杂命令注意：类似 cat /tmp/test.md | awk -F'|' '{print $1,$2}' &> /tmp/example.txt 这类复杂命令，即使使用 shell 模块也可能失败。解决办法：把命令写成脚本，copy 到远程执行，再把结果拉回。

将 shell 设为默认模块：

vim /etc/ansible/ansible.cfg
# 修改下面一行
module_name = shell

# 验证
ansible websrvs -a 'echo <密码> > /data/1.log'        # 默认是 shell 模块
ansible websrvs -m command -a 'echo <密码> > /data/1.log'   # 指定 command（不支持重定向）

# 三、script 模块

功能：在远程主机上运行 Ansible 服务器（主控端）上的脚本。

注意：不具有幂等性。

ansible websrvs -m script -a '/root/test.sh'

# 四、copy 模块

功能：从 Ansible 主控端复制文件到远程主机。

注意：src 若未指明绝对路径，则为当前目录或当前目录下 files 目录中的文件。

示例：

# backup 参数：目标存在时默认覆盖，此处指定先备份
ansible websrvs -m copy -a 'src=/root/test.sh dest=/root/test01.sh owner=testuser group=bin mode=600 backup=yes'

# content 参数：直接指定内容生成目标文件
ansible websrvs -m copy -a "content='test line1\ntest line2\n' dest=/tmp/test.txt"

复制目录的细节：

# 复制 /etc 目录自身（注意 /etc 后面没有 /）
ansible websrvs -m copy -a "src=/etc dest=/backup"

# 复制 /etc/ 下的文件，不包括 /etc 目录自身（注意 /etc/ 后面有 /）
ansible websrvs -m copy -a "src=/etc/ dest=/backup"

src 末尾带不带 / 决定了是"复制目录本身"还是"复制目录内容"，这是 copy 模块的常见易错点。

# 五、get_url 模块

功能：将文件从 http、https 或 ftp 下载到被管理节点。

常用参数：

参数说明
url下载文件的 URL，支持 HTTP/HTTPS/FTP
dest下载目标路径（绝对路径）；若目标是目录则用服务器上文件名
owner / group / mode属主/属组/权限
forceyes 则每次都下载并替换；no 则仅目标不存在时下载
checksum下载后计算摘要确保完整性，如 checksum="sha256:..."
url_username / url_passwordHTTP 基本认证的用户名/密码
validate_certsno 则不验证 SSL 证书，适用于自签名证书
timeoutURL 请求超时时间（秒）

示例（带 checksum 校验）：

# 主控端提前下载并计算哈希
[root@ansible ~] wget http://nginx.org/download/nginx-1.18.0.tar.gz
[root@ansible ~] md5sum nginx-1.18.0.tar.gz
b2d33d24d89b8b1f87ff5d251aa27eb8  nginx-1.18.0.tar.gz

# 下载到远程并校验 md5
[root@ansible ~] ansible websrvs -m get_url -a 'url=http://nginx.org/download/nginx-1.18.0.tar.gz dest=/usr/local/src/nginx.tar.gz checksum="md5:b2d33d24d89b8b1f87ff5d251aa27eb8"'

checksum 是保证下载文件完整性的重要手段，生产环境下载软件包应尽量带上。

# 六、fetch 模块

功能：从远程主机提取文件到 Ansible 主控端。与 copy 模块相反。

注意：目前不支持目录（可将目录打包，再把压缩包拷贝到主控端）。常用于复制客户端日志到主控端。

[root@ansible ~] ansible websrvs -m fetch -a 'src=/var/log/messages dest=/root/logs'

# 七、file 模块

功能：文件管理模块，用于对文件或文件夹进行操作——设置文件、链接、目录属性，或移除它们；创建/删除文件目录、设置属性、创建软链接等。

主要参数： path（文件绝对路径）、state（操作：touch 新建、absent 删除、link 软连接、hard 硬链接、directory 创建目录）、owner、group、mode、recurse（递归 yes/no）。

示例：

# 创建空文件
ansible all -m file -a 'path=/data/test.txt state=touch'
ansible all -m file -a "path=/root/test.txt state=touch owner=testuser mode=755"

# 创建目录 state=directory
ansible all -m file -a "path=/data/mysql state=directory owner=mysql group=mysql"

# 创建软链接 state=link
ansible all -m file -a 'src=/data/testfile dest=/data/testfile-link state=link'

# 递归修改目录及子目录属性
ansible all -m file -a "path=/data/mysql state=directory owner=mysql group=mysql recurse=yes"

# 删除文件或目录 state=absent
ansible all -m file -a "path=/data/mysql state=absent"

# 八、stat 模块

功能：检查文件或文件系统的状态。

注意：Windows 目标请改用 win_stat 模块。

选项：path（文件/对象完整路径，必须）。

常用返回值：exists（判断是否存在）、isuid（调用用户 ID 与所有者 ID 是否匹配）。

示例：

[root@ansible ~] ansible 127.0.0.1 -m stat -a 'path=/etc/passwd'

结合 register 与 when 实现条件推进：

- name: install | Check if file is already configured.
  stat: path=<!--swig￼0-->
  connection: local
  register: nginx_file_result

- name: install | Download nginx file
  get_url: url=<!--swig￼1--> dest=<!--swig￼2--> validate_certs=no
  connection: local
  when: not nginx_file_result.stat.exists
# 检查 websrvs 组所有主机上 /data/mysql 是否存在，不存在则输出调试信息
- hosts: websrvs
  tasks:
    - name: Check file
      stat: path=/data/mysql
      register: st
    - name: debug
      debug:
        msg: "/data/mysql is not exist"
      when: not st.stat.exists

stat + register + when 是 Ansible 实现"条件化执行"的经典组合，广泛用于"存在则跳过、不存在则执行"的幂等场景。

# 九、unarchive 模块

功能：解包解压缩。有两种用法：

  1. 将 Ansible 主机上的压缩包传到远程主机后解压，copy=yes（默认，可省略）；
  2. 将远程主机上的压缩包解压到指定路径，copy=no。

常见参数：

参数说明
copy默认 yes，源文件在 Ansible 主机；设为 no 则在远程主机寻找 src
remote_src与 copy 功能类似且互斥，yes 表示源在远程主机
src源路径（Ansible 主机或远程主机路径）
dest远程主机目标路径
mode解压后文件权限

示例：

# copy=yes（默认）：从控制主机复制到远程再解压
ansible all -m unarchive -a 'src=/root/nginx-1.18.0.tar.gz dest=/usr/local/src owner=testuser group=bin'

# copy=no：在远程被控主机上寻找 src 源文件
ansible all -m unarchive -a 'src=/root/nginx-1.18.0.tar.gz dest=/usr/local/src copy=no mode=0777'

# 直接下载并解压（需 copy=no）
ansible websrvs -m unarchive -a 'src=http://nginx.org/download/nginx-1.18.0.tar.gz dest=/usr/local/src/ copy=no'

# remote_src=yes：源在远程主机
ansible websrvs -m unarchive -a 'src=https://releases.ansible.com/ansible/ansible-2.1.6.0-0.1.rc1.tar.gz dest=/usr/local/src owner=root remote_src=yes'

# 十、archive 模块

功能：打包压缩并保存在被管理节点（与 unarchive 相反，是"压缩"而非"解压"）。

ansible websrvs -m archive -a 'path=/var/log/ dest=/data/log.tar.bz2 format=bz2 owner=testuser mode=0600'

# 小结

本文讲解了命令执行类（command、shell、script）与文件管理类（copy、get_url、fetch、file、stat、unarchive、archive）模块。核心要点：

  • command/shell/script 不幂等，能用幂等模块（file、copy 等）解决的优先用后者；
  • copy 的 src 末尾带不带 / 含义不同，是易错点；
  • get_url 的 checksum 保证下载完整性；
  • stat + register + when 是条件化执行的利器；
  • unarchive 的 copy/remote_src 决定源文件位置。
