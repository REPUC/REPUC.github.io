# 1. 网络基本概述

# 1.1 为何需要网络

  • 没有网络（所有计算机网络都关闭）：如果计算机上有不错的电影想要传输，会比较费事，因为可能处在不同的城市或不同的国家。
  • 有了网络（所有计算机通过网线连接在一起）：
    1. 打破了地域上数据传输的限制；
    2. 提高信息之间的传输效率，以便更好地实现资源共享。

# 1.2 什么是网络

  • 网络是由若干节点和连接这些节点的链路构成，表示诸多对象及其相互联系。
  • 网络是信息传输、接收、共享的虚拟平台，通过它把各个信息联系到一起，从而实现资源共享。

网络将节点连接在一起、实现信息传输（信息通信）有几个大前提：

  1. 使用物理连接介质将所有计算机连接在一起（网卡、网线、交换机、路由器）；
  2. 双方在通信过程中，必须使用统一的通信标准，也就是通讯协议（互联网通讯协议）。

# 2. 互联网通讯协议

  • 协议就是规定了一堆标准，用来定义计算机如何接入 Internet、以及接入 Internet 的计算机之间通信的标准。计算机都需要学习并遵循此标准来进行信息传输。
  • 国际标准化组织（ISO）推出了 OSI 七层参考模型，将互联网通讯协议分成不同的层，每一层都有专门的标准以及组织数据的格式：（应、表、会、传、网、数、物）
  • 对于写程序来说，通常将七层归纳为五层协议：（应、传、网、数、物）

OSI 七层模型与 TCP/IP 五层模型对应关系：

# 2.1 物理层

物理层：定义物理设备的标准，如网卡、网线、传输速率；最终实现数据转成电信号传输。

问题：如果只是单纯发送电信号是没有意义的，因为没有规定开头也没有规定结尾；要想变得有意义就必须对电信号进行分组，比如以若干位为一组的方式去传输，这就需要数据链路层来完成。

# 2.2 数据链路层

数据链路层：定义了电信号的分组标准方式，一组数据称之为一个数据帧，这个标准遵循 Ethernet 以太网协议。以太网规定了如下几件事：

  1. 数据帧分为 head 和 data 两部分，其中 head 长度固定 18 字节：
    • head：发送者/源地址、接收者/目标地址、数据类型（源地址 6 字节、目标地址 6 字节、数据类型 6 字节）；
    • 源地址：MAC 地址；
    • 目标地址：MAC 地址；
    • data：主要存放网络层整体的数据，最长 1500 字节，超过最大限制就分片发送。
  2. 但凡接入互联网的主机必须有一块网卡，网卡烧制了全世界唯一的 MAC 地址。
  3. 有了以太网协议规定后，它能对数据分组、区分数据的意义、找到目标主机的地址，就可以实现计算机通信；但计算机是"瞎"的，所以以太网通信采用的是广播方式。

什么是广播：假设大家都在一个小黑屋里面，互相通信靠吼。oldwang 让 laowang 买包烟：

  1. 数据：买烟（类型：干粮）
  2. 源地址：oldwang
  3. 目标地址：laowang

此时屋子里所有人都收到了该数据包，但只有目标者（laowang）会接收执行，其他人收到后会丢弃。

为什么不能全世界计算机直接互联：

  • 首先：无法将全世界计算机放在一个交换机上，因为没有这样的设备；
  • 其次：就算放在同一设备上，每台计算机都广播一下，那设备也无法正常工作。
  • 所以：应该将主机划区域，隔离在一个又一个的区域中，然后将多个区域通过网关/路由连接在一起。

# 2.3 网络层

网络层：用来划分广播域。如果广播域内主机要往广播域外的主机发送数据，一定要有一个网关/路由帮其将数据转发到外部计算机；网关和外界通信走的是路由协议。网络层协议规定了如下几件事：

  • 规定 1：数据包分成 head 和 data 两部分：
    • head：发送者/源地址、接收者/目标地址，该地址为 IP 地址；
    • data：主要存放传输层整体的数据。
  • 规定 2：IP 地址用来划分广播域，主要用来判断两台主机是否在同一广播域中。
  • 一个合法 IPv4 地址组成部分 = ip 地址/子网掩码（可借助在线子网计算器计算）。
  • 如果计算出两台地址的广播域一样，说明两台计算机处在同一个区域中。

计算两台计算机是否在同一局域网（牵扯到如何发送数据）：

  • 假设计算机 1 要与计算机 2 通信，计算机 1 必须拿到计算机 2 的 IP 地址。

情况一：它们处于同一网络（局域网），如 16.6.6.1 --> 16.6.6.168：

  1. 本地电脑根据数据包检查目标 IP，如果为本地局域网；
  2. 直接通过交换机广播 MAC 寻址，将数据包转发过去。

情况二：它们处于不同网络（跨局域网），如 186.8.8.1 --> 39.164.16.126：

  1. 本地根据数据包检查目标 IP，如果不为本地局域网，则尝试获取网关的 MAC 地址；
  2. 本地封装数据转发给交换机，交换机拆解发现目标 MAC 是网关，则送往网关设备；
  3. 网关收到数据包后，拆解至二层，发现请求目标 MAC 是网关本机 MAC；
  4. 网关则会继续拆解数据报文到三层，发现目标地址不为网关本机；
  5. 网关会重新封装数据包，将源地址替换为网关的 WAN 地址，目标地址不变；
  6. 出口路由器根据自身路由表信息将数据包发送出去，直到送到目标的网关。

# 2.4 传输层

传输层的由来：网络层帮我们区分子网，数据链路层帮我们找到主机，但一个主机有多个进程，进程之间进行不同的网络通信。当收到数据时，如何区分数据是哪个进程的？其实是通过端口来区分；端口即应用程序与网卡关联的编号。

传输层的定义：提供进程之间的逻辑通信。传输层也分成 head 和 data 两部分：

  • head：源端口、目标端口、协议（TCP、UDP）；
  • data：主要存放应用层整体的数据。

# 2.5 应用层

应用层：为终端应用提供的服务，如浏览器交互时用到的 HTTP 协议、邮件发送的 SMTP、文件传输的 FTP 等。

# 2.6 OSI 总结

OSI 七层模型中，数据从应用层向物理层逐层封装（每层添加各自的头部），从物理层向应用层逐层解封装。以太网封装与解封装的过程可理解为：各层协议负责在对应头部加入寻址信息（MAC、IP、端口等），接收方按相反顺序逐层剥离头部并处理数据。

# 3. TCP 协议

TCP 是可靠数据传输协议。为了实现可靠传输，在通信之前需要先建立连接，也叫双向通路——客户端与服务端要建立连接，服务端与客户端也需要建立连接。建立的双向通路只是一个虚拟链路，并不是用网线将两个设备真实捆绑在一起。

虚拟链路的作用：由于每次通信都需要拿到 IP 和 Port，意味着每次都需要查找；建立好虚拟通路后，下次两台主机之间就可以直接传递数据。

# 3.1 三次握手

  1. 第一次：客户端要与服务端建立连接，需要发送请求连接消息；
  2. 第二次：服务端接收到数据后，返回一个确认操作（至此客户端到服务端链路建立成功）；
  3. 第三次：服务端还需要发送要与客户端建立连接的请求；
  4. 第四次：客户端接收到数据后，返回一个确认操作（至此服务端到客户端的链路建立成功）。

由于建立连接时没有数据传输，所以第二次确认和第三次请求可以合并为一次发送，即形成"三次握手"。

序号（seq）与确认号（ack）：

  • TCP 为了实现可靠传输，通信双方需要判断自己发送的数据包是否都被接收方收到，如果没收到就需要重发。为此引出**序号（seq）和确认号（ack）**的使用。
  • 举例：发送方发送数据包时序列号假设为 123，接收方收到后回复一个确认号 124（= 123 + 1），告诉发送方"我已经收到了你的数据包，你可以发送下一个数据包，序号从 124 开始"。这样发送方就可以知道哪些数据被接收、哪些没被接收、需要重发。

# 3.2 四次挥手

  1. 第一次挥手：客户端（服务端也可以主动断开）向服务端说明想要关闭连接；
  2. 第二次挥手：服务端会回复确认。但不是立马关闭，因为此时服务端可能还有数据在传输中；
  3. 第三次挥手：待服务端数据传输都结束后，服务端向客户端发出消息——我要断开连接了；
  4. 第四次挥手：客户端收到服务端的断开信息后，给予确认。服务端收到确认后正式关闭。

# 3.3 转换状态

三次握手状态转换：

  1. 客户端发送 SYN 包向服务端请求建立 TCP 连接，客户端进入 SYN_SEND 状态；
  2. 服务端收到请求之后，向客户端发送 SYN+ACK 的合成包，同时自身进入 SYN_RECV 状态；
  3. 客户端收到回复之后，发送 ACK 信息，自身进入 ESTABLISHED 状态；
  4. 服务端收到 ACK 数据之后，进入 ESTABLISHED 状态。

四次挥手状态转换：

  1. 客户端发送完数据之后，向服务器请求断开连接，自身进入 FIN_WAIT_1 状态；
  2. 服务端收到 FIN 包之后，回复 ACK 包表示已经收到，但此时服务端可能还有数据没发送完成，自身进入 CLOSE_WAIT 状态，表示对方已发送完成且请求关闭连接，自身发送完数据之后就可以关闭连接；
  3. 服务端数据发送完成后，发送 FIN 包给客户端，自身进入 LAST_ACK 状态，等待客户端 ACK 回复；
  4. 客户端收到 FIN 包之后，回复一个 ACK 包，并进入 TIME_WAIT 状态。

注意：TIME_WAIT 状态比较特殊，当客户端收到服务端的 FIN 包时，理想状态下可以直接关闭连接，但存在几个问题：

  • 问题 1：网络是不稳定的，可能服务端发送的一些数据包，比服务端发送的 FIN 包还晚到；
  • 问题 2：如果客户端回复的 ACK 包丢失了，服务端就会一直处于 LAST_ACK 状态，如果客户端没有关闭，那么服务端还会重传 FIN 包，然后客户端继续确认。

所以客户端如果 ACK 后立即关闭连接，会导致数据不完整、也可能造成服务端无法释放连接。因此客户端需要等待 2 个报文生存最大时长（2MSL），确保网络中没有任何遗留报文了，再关闭连接。

如果机器 TIME_WAIT 过多，会造成端口耗尽，可以修改内核参数 tcp_tw_reuse=1 进行端口重用。

为什么必须等待 2MSL，而不是 4MSL、8MSL？

  • 一个 MSL 就是报文在网络中的最长生存时间。大白话讲，如果存在丢包，在 MSL 时间内也会触发重传。
  • 2MSL 相当于两次丢包：一次丢包概率是百分之一，连续两次丢包的概率是万分之一，这个概率实在太小，所以 2MSL 是足够的。

# 3.4 UDP 协议

  • UDP 是不可靠传输协议，"不可靠"指的是传输数据时不可靠；
  • UDP 协议不需要先建立连接，只需要获取服务端的 IP + Port，发送完毕也无需服务器返回 ACK；
  • UDP 协议如果在发送数据的过程中丢了，那就丢了。

# 4.2 修改网卡名称

  • CentOS 6 网卡名称是 eth0、eth1 ...
  • CentOS 7 网卡名称是 ens32、ens33 ...

由于这种无规则的命名方式给后期维护带来了困难，所以需要将网卡名称修改为 eth0、eth1。

场景示例 1：已经安装完操作系统，修改网卡命名规则为 eth0、eth1

  1. 修改网卡配置文件：
[root@oldwang ~]# cd /etc/sysconfig/network-scripts/
[root@oldwang network-scripts]# mv ifcfg-ens32 ifcfg-eth0
[root@oldwang network-scripts]# vim ifcfg-eth0
NAME=eth0
DEVICE=eth0
  1. 修改内核启动参数，禁用预测命名规则，将 net.ifnames=0 biosdevname=0 参数关闭：
[root@oldwang ~]# vim /etc/sysconfig/grub
GRUB_CMDLINE_LINUX="...net.ifnames=0 biosdevname=0 quiet"
[root@oldwang ~]# grub2-mkconfig -o /boot/grub2/grub.cfg
  1. 重启系统，然后检查网卡名称是否修改成功：
[root@oldwang ~]# reboot
[root@oldwang ~]# ifconfig

场景示例 2：在新安装系统时，修改网卡名称规则

  1. 在安装系统选择 Install CentOS 7 时按下 Tab 设定 kernel 内核参数；
  2. 增加内核参数：net.ifnames=0 biosdevname=0；
  3. 检查是否修改成功，成功后可继续安装系统。

# 4.3 配置网络地址

  • CentOS 7 系统默认采用 NetworkManager 来提供网络服务，这是一种动态管理网络配置的守护进程，能够让网络设备保持连接状态。
  • NetworkManager 提供的命令行和图形配置工具对网络进行设定，设定保存的配置文件在 /etc/sysconfig/network-scripts 目录下，工具有 nmcli、nmtui。

NetworkManager 有两个概念需要了解：

  • device：物理设备，例如 ens32、virbr0、team0；
  • connection：连接设置，具体网络配置方案。

一个物理设备 device 可以有多套逻辑连接配置，但同一时刻只能使用一个 connection 连接配置。

# 4.3.1 nmcli 查看网络状态

  1. 使用 nmcli device 命令查看设备情况：
[root@oldwang ~]# nmcli device
DEVICE  TYPE      STATE      CONNECTION
eth0    ethernet  connected  eth0
lo      loopback  unmanaged  --

[root@oldwang ~]# nmcli dev show eth0      # 查看设备详细信息
  1. 使用 nmcli connection 命令查看连接状态：
[root@oldwang ~]# nmcli connection
NAME    UUID                                  TYPE         DEVICE
eth0    a4319b27-80dc-4d63-a693-2927ea1018e7  802-3-ethernet eth0

[root@oldwang ~]# nmcli con show --active      # 查看活动连接
[root@oldwang ~]# nmcli con show "eth0"        # 查看指定连接

# 4.3.2 nmcli 配置 IP 地址

使用 nmcli 创建一个 static 的连接，配置 IP、掩码、网关等，步骤如下：

  1. 添加一个连接配置，并指定连接配置名称；
  2. 将连接配置绑定物理网卡设备；
  3. 配置网卡的类型、网卡是否开机启动；
  4. 配置网卡使用什么模式配置 IP 地址（静态、dhcp）；
  5. 配置网卡的 IP 地址、掩码、网关、DNS 等。
[root@oldwang ~]# nmcli connection add con-name eth0-static ifname eth0 \
type ethernet autoconnect yes \
ipv4.method manual \
ipv4.addresses 10.0.0.222/24 \
ipv4.gateway 10.0.0.254 \
ipv4.dns 223.5.5.5 \
ipv4.dns 8.8.8.8

# 启用连接
[root@oldwang ~]# nmcli connection up eth0-static
[root@oldwang ~]# nmcli connection show
NAME         UUID                                   TYPE          DEVICE
eth0-static  6fdebe6e-5ef0-4a05-8235-57e317fdada0  802-3-ethernet eth0

  1. 取消 eth0-static 连接开机自动激活网络：

  1. 给连接再增加 dns（有些设定值通过 + / - 可以增加或移除设定）：

# 6. 网关/路由

# 6.1 什么是路由

路由是指路由器从一个 LAN 接口上收到数据包，根据数据包的目的地址进行定向并转发到另一个 WAN 接口的过程（跨网络访问的路径选择）。

路由工作包含两个基本的动作：

  1. 确定最佳路径；
  2. 通过网络传输信息。

在路由的过程中，后者也称为（数据）交换。交换相对来说比较简单，而选择路径很复杂。如果没有路由，就没有办法实现不同地域的主机互联互通了。

# 6.2 为什么需要路由

不同网段（广播域）之间的主机无法直接通信，需要借助路由器（网关）根据目的地址转发数据包，实现跨网络的互联互通。

# 6.3 如何配置路由

Linux 系统配置路由使用 route 命令，可以使用 route 命令来显示和管理路由表。

route 命令语法示例：

route [add|del] [-host|-net|default] [address[/mask]] [netmask] [gw] [dev]

参数说明：

  • add|del：增加或删除路由条目；
  • -host：添加或删除主机路由；
  • -net：添加或删除网络路由；
  • default：添加或删除默认路由；
  • address：添加要去往的网段地址，由 ip + netmask 组成；
  • gw：指定下一跳地址，要求下一跳地址必须是能到达的，且一般是和本网段直连的接口；
  • dev：将添加路由与对应的接口关联，一般内核会自动判断路由应该关联哪个接口。

route 添加路由命令示例：

[root@oldwang ~]# route add -host 1.1.1.1/32 dev eth0
[root@oldwang ~]# route add -net 1.1.1.1/32 dev eth1
[root@oldwang ~]# route add -net 1.1.1.1/32 gw 1.1.1.2
[root@oldwang ~]# route add default gw 1.1.1.2

# 6.4 路由的分类

# 6.4.1 主机路由

主机路由作用：指明到某台主机具体应该怎么走，Destination 精确到某一台主机。

Linux 上如何配置主机路由：

# 去往 1.1.1.1 主机，从 eth0 接口发出
[root@oldwang ~]# route add -host 1.1.1.1/32 dev eth0
# 去往 1.1.1.1，下一跳走网关 10.0.0.2
[root@oldwang ~]# route add -host 1.1.1.1/32 gw 10.0.0.2

# 6.4.2 网络路由

网络路由作用：指明到某类网络怎么走，Destination 精确到某一个网段的主机。

Linux 上如何配置网络路由：

# 去往 2.2.2.0/24 网段，从 eth0 接口发出
[root@oldwang ~]# route add -net 2.2.2.0/24 dev eth0
# 去往 2.2.2.0/24 网段，下一跳走网关 10.0.0.2
[root@oldwang ~]# route add -net 2.2.2.0/24 gw 10.0.0.2

# 6.4.3 默认路由

默认路由：如果匹配不到主机路由、网络路由的，全部都走默认路由（网关）。

Linux 上如何配置默认路由：

[root@oldwang ~]# route add -net 6.6.6.6 gw 16.6.6.2
[root@oldwang ~]# route add default gw 10.0.0.2

# 6.4.4 永久路由

使用 route 命令添加的路由，属于临时添加。永久添加路由条目的方法：在 /etc/sysconfig/network-scripts 目录下创建 route-ethX（网卡名称）文件，添加路由条目。

[root@dns-master ~]# cat /etc/sysconfig/network-scripts/route-eth0

# 8. 内核参数调优

# 8.1 ip_local_port_range

主动连接方（客户端）会占用本地随机端口，TIME_WAIT 状态会占用本地端口，如果占用过多导致本地端口不足，TCP 连接不能成功建立，可以通过调整参数来增加本地端口的范围。

  1. 查看客户端默认可用端口范围：

[root@client ~]# sysctl -w net.ipv4.ip_local_port_range="19000 100082"
  1. 测试端口不够用情况：准备两台服务器，一台 nginx 服务器，客户端使用 curl 访问服务器并主动关闭连接，在客户端产生 TIME_WAIT 状态。服务器：10.0.0.100 nginx、客户端：10.0.0.99 client。

# 8.4 tcp_max_syn_backlog

一般将 ESTABLISHED 状态的连接称为全连接，而将 SYN_RECV 状态的连接称为半连接。backlog 定义了处于 SYN_RECV 的 TCP 最大连接数，当处于 SYN_RECV 状态的 TCP 连接数超过 tcp_max_syn_backlog 后，会丢弃后续的 SYN 报文（也就是半连接池最大可接受的请求）。

连接处理流程：服务器收到一个 SYN 后，创建一个子连接加入到 SYN_RECV 队列；在收到 ACK 后，将这个子连接移动到 ESTABLISHED 队列；最后当用户调用 accept() 时，将连接从 ESTABLISHED 队列取出。

  1. 调整服务端参数：
# 关闭 SYN cookies
[root@server ~]# sysctl -w net.ipv4.tcp_syncookies=0
[root@server ~]# sysctl -w net.ipv4.tcp_max_syn_backlog=2
  1. 客户端执行如下操作，让 SYN 请求进入 SYN_RECV 状态：
[root@client ~]# iptables -t filter -I OUTPUT -p tcp --sport 22 -j ACCEPT
[root@client ~]# iptables -t filter -A OUTPUT -p tcp -m tcp --tcp-flag SYN,ACK ACK -j DROP
# 然后使用 telnet 连接服务端端口
[root@client ~]# telnet 10.0.0.100 22 &
[1] 11913
[root@client ~]# telnet 10.0.0.100 22 &
[2] 11916
[root@client ~]# telnet 10.0.0.100 22 &
[3] 11917
[root@client ~]# telnet 10.0.0.100 22 &
[4] 12012
[root@client ~]# Trying 10.0.0.100...

# 8.6 tcp_syn_retries

net.ipv4.tcp_syn_retries 表示应用程序进行发送 SYN 包时，在对方不返回 SYN + ACK 的情况下，内核默认重试发送 6 次 SYN 包，也就是说如果一直收不到对方返回 SYN + ACK，那么应用程序最大的超时时间就是 1+2+4+8+16+32+64 = 127 秒，这对于很多客户端而言是很难以接受的。

重试等待时间（指数退避）：

  • 第 1 次发送 SYN 报文后等待 1s（2^0），如果超时，则重试；
  • 第 2 次发送后等待 2s（2^1），如果超时，则重试；
  • 第 3 次发送后等待 4s（2^2），如果超时，则重试；
  • 第 4 次发送后等待 8s（2^3），如果超时，则重试；
  • 第 5 次发送后等待 16s（2^4），如果超时，则重试；
  • 第 6 次发送后等待 32s（2^5），如果超时，则重试；
  • 第 7 次发送后等待 64s（2^6），如果超时，则超时失败。
  1. 服务端配置 iptables 丢弃 syn 报文，并使用 tcpdump 抓包：
# 丢弃 22 端口的 SYN 报文
[root@server ~]# iptables -A INPUT -p tcp --dport 22 --syn -j DROP
# 使用 tcpdump 抓包
[root@server ~]# tcpdump -i eth0 -n src 10.0.0.99 and dst 10.0.0.100 and port 22
  1. 客户端使用 telnet 连接服务端指定端口：
[root@client ~]# date '+ %F %T'; telnet 10.0.0.100 22; date '+ %F %T';
2021-07-29 23:32:57    # 开始时间
Trying 10.0.0.100...
telnet: connect to address 10.0.0.100: Connection timed out
2021-07-29 23:35:05    # 结束时间，耗时约 2 分多钟
  1. 分析抓包结果：从 tcpdump 的输出可以看到，一共发了 7 次 SYN 包（都是同一个 seq 号码），第一次是正常请求，后面 6 次是重试，正是该内核参数设置的值：
[root@server ~]# tcpdump -i eth0 -n src 10.0.0.99 and dst 10.0.0.100 and port 22

# 8.8 内核参数示例

综合示例（写入 /etc/sysctl.conf，执行 sysctl -p 生效）：

[root@oldwang ~]# vim /etc/sysctl.conf
# tcp 优化
net.ipv4.ip_local_port_range = 1024 65000
net.ipv4.tcp_tw_reuse = 1
net.ipv4.tcp_max_tw_buckets = 5000
net.ipv4.tcp_syncookies = 1       # 开启 SYN Flood 防御，减少 tcp_max_syn_backlog 影响
net.ipv4.tcp_max_syn_backlog = 8192  # SYN 半连接队列，服务端可接受的最大半连接数
net.core.somaxconn = 32768        # 服务端全连接队列大小

# 缩短 TCP TIME-WAIT 时长，参考 https://help.aliyun.com/document_detail/155476.html
net.ipv4.tcp_tw_timeout = 5

# 连接
net.ipv4.tcp_syn_retries=2        # 重试发送 SYN 包次数，减少等待
net.ipv4.tcp_synack_retries = 2    # 发送 synack 包重试次数，减少等待

# 路由
# net.ipv4.ip_forward = 1
# net.ipv4.ip_nonlocal_bind = 1
# net.ipv4.tcp_keepalive_time = 600
# 开启 keepalive 探测，TCP 保活相关参数

# 文件系统
fs.file-max = 204800

# 内存
vm.swappiness = 0

参考：内核参数 tcp_syncookies、内核参数 backlog 相关说明。
