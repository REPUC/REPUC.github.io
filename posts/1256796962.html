# Playbook 进阶：Handlers、Tags 与变量

本文深入 Playbook 的三个进阶特性：Handlers 与 notify（条件触发任务）、Tags（任务标签与选择性执行）、变量（多种来源、优先级与 register 注册变量）。这三者是编写健壮、灵活、可复用剧本的关键。

# 一、Handlers 与 notify

# 1.1 概念

Handlers 本质是 task list，类似数据库中的触发器。其中的 task 与普通 task 没有本质不同，主要用于当关注的资源发生变化时才采取操作。

Notify 对应的 action 在每个 play 的最后被触发，这样可避免多次发生变化时每次都执行指定操作，而是在所有变化发生完成后一次性执行。notify 中列出的操作称为 handler，即 notify 调用 handler 中定义的操作。

注意要点：

  • 如果多个 task 通知了相同的 handlers，此 handlers 仅会在所有 tasks 结束后运行一次；
  • 只有 notify 对应的 task 发生了改变（changed）才会通知 handlers，没有改变则不会触发；
  • handlers 在所有前面的 tasks 都成功执行后才会执行；如果前面任一 task 失败，handler 会跳过。可用 force_handlers: yes 强制执行 handler。

# 1.2 示例：安装 httpd 并配置

---
- hosts: websrvs
  remote_user: root
  gather_facts: no

  tasks:
    - name: Install httpd
      yum: name=httpd state=present
    - name: Install configure file
      copy: src=files/httpd.conf dest=/etc/httpd/conf/
      notify:
        - restart httpd
        - wall
    - name: ensure apache is running
      service: name=httpd state=started enabled=yes

    handlers:
    - name: restart httpd
      service: name=httpd state=restarted
    - name: wall
      command: wall "The config file is changed"

场景：当"Install configure file"任务完成且状态发生变化时，触发名为 restart httpd 的 handler，重启服务以应用新配置。

# 1.3 示例：安装 nginx 配置变更触发重启

# install_nginx.yml
---
- hosts: websrvs
  remote_user: root
  gather_facts: no

  tasks:
    - name: "Add Nginx Group"
      group: name=nginx state=present
    - name: "Add Nginx User"
      user: name=nginx state=present group=nginx
    - name: "Install Nginx"
      yum: name=nginx state=present
    - name: "Copy Nginx Config File"
      copy: src=files/nginx.conf dest=/etc/nginx/nginx.conf
      notify: Restart Nginx Service    # 定义 notify 触发器
    - name: "Copy Web Page File"
      copy: src=files/index.html dest=/usr/share/nginx/html/index.html
    - name: "Start Nginx Service"
      service: name=nginx state=started enabled=yes

  handlers:    # 触发如下操作
    - name: "Restart Nginx Service"
      service: name=nginx state=restarted enabled=yes
ansible-playbook install_nginx.yml

# 1.4 强制执行 handlers

- hosts: websrvs
  force_handlers: yes     # 无论 task 中任一 task 失败，仍强制执行 handlers
  tasks:
    - name: config file
      copy: src=nginx.conf dest=/etc/nginx/nginx.conf
      notify: restart nginx
    - name: install package
      yum: name=no_exist_package     # 此任务会失败

  handlers:
    - name: "restart nginx"
      service: name=nginx state=restarted

Handlers 是"配置变更 → 重启服务"这类场景的标准做法，比在每个 task 后都写 service: restarted 更优雅、更高效。

# 二、Tags：任务标签

# 2.1 概念

如果写了一个很长的 PlayBook，实际使用时可能只想执行其中一部分任务，或只执行某一类任务。此时可借助 tags 标签：

  • 在 PlayBook 中用 tags 组件为特定 task 打标签；
  • 执行时可用标签指定执行哪些任务，或不执行哪些任务；
  • 一个 task 可对应多个 tag，多个 task 也可对应一个 tag；
  • 另有 3 个特殊关键字：tagged（仅运行已标记）、untagged（仅运行未标记）、all（所有任务）。

# 2.2 示例

# httpd.yml
---
- hosts: websrvs
  remote_user: root
  gather_facts: no

  tasks:
  - name: "Install httpd"
    yum: name=httpd state=present
  - name: "Install configure file"
    copy: src=files/httpd.conf dest=/etc/httpd/conf/
    tags: [ conf,file ]       # 写在一行
    # 也可写成多行：
    # tags:
    #   - conf
    #   - file
  - name: "start httpd service"
    tags: service              # 写在一行
    service: name=httpd state=started enabled=yes
# 查看标签
ansible-playbook --list-tags httpd.yml

# 仅执行指定标签的动作
ansible-playbook -t conf,service httpd.yml

# 跳过指定标签的动作
ansible-playbook --skip-tags conf httpd.yml
ansible-playbook httpd.yml --skip-tags untagged

Tags 常用于将 PlayBook 按"安装/配置/启动"等阶段划分，便于按需执行，也常配合 Roles 使用（见第 11 篇）。

# 三、变量

# 3.1 变量定义与调用

变量名规则：仅能由字母、数字和下划线组成，且只能以字母开头。

# 变量定义
variable: value    # 建议写法（variable=value 也可）

调用方式：通过 {{ variable_name }} 调用，变量名前后建议加空格，有时需用 "{{ variable_name }}" 才生效。

# 3.2 变量来源

  1. setup facts：远程主机的所有变量都可直接调用；
  2. 命令行指定变量：ansible-playbook -e varname=value test.yml，优先级最高；
  3. PlayBook 文件中定义：vars: 段；
  4. 独立的变量 YAML 文件：vars_files:；
  5. 主机清单文件中定义：主机（普通）变量、组（公共）变量；
  6. 项目目录的 host_vars / group_vars 目录：针对主机和主机组定义；
  7. role 中定义。

# 3.3 变量优先级（从高到低）

-e 命令行变量 > playbook 中 vars_files > playbook 中 vars > host_vars/主机名 > 主机清单主机变量
> group_vars/主机组名 > group_vars/all > 主机清单组变量

# 3.4 使用 setup 模块的变量（facts）

setup 模块自动在 PlayBook 调用（不要用 ansible 命令单独调用生成），生成系统状态信息存放在 facts 变量中，包括主机名、IP、CPU、内存、网卡等。

实际使用场景：

  • 通过 facts 获取被控端 CPU 个数，生成不同的 Nginx 配置文件；
  • 通过 facts 获取内存大小，生成不同的 memcached 配置文件；
  • 通过 facts 获取主机名，生成不同的 Zabbix 配置文件。

示例：

ansible 192.168.80.18 -m setup -a "filter=ansible_nodename"
ansible 192.168.80.18 -m setup -a 'filter="ansible_default_ipv4"'

PlayBook 中使用 facts：

# var.yml
---
- hosts: websrvs
  remote_user: root
  gather_facts: yes     # 注意：需 yes 启用才能收集 facts

  tasks:
    - name: "create log file"
      file: name=/root/<!--swig￼2-->.log state=touch owner=testuser mode=600

显示网卡 IP：

# show_ip.yml
- hosts: websrvs
  tasks:
    - name: show eth0 ip address <!--swig￼3-->
      debug:
        msg: IP address <!--swig￼4-->
        # 也可写成：
        # msg: IP address <!--swig￼5-->
        # msg: IP address <!--swig￼6-->
        # msg: IP address <!--swig￼7-->  # 取 IP 最后一段

用 facts 生成文件名：

- hosts: websrvs
  tasks:
    - name: test var
      file: path=/root/<!--swig￼8-->.log state=touch
      # 等价：file: path=/root/<!--swig￼9-->.log state=touch

# 3.5 在命令行定义变量

# var2.yml
---
- hosts: websrvs
  remote_user: root
  tasks:
    - name: "install package"
      yum: name=<!--swig￼10--> state=present
# 命令行定义变量
ansible-playbook -e pkname=vsftpd var2.yml

# 也可将多个变量放在一个文件中
cat vars
pkname1: memcached
pkname2: redis

# 方式一：逐个 -e
ansible-playbook -e pkname1=memcached -e pkname2=redis var2.yml

# 方式二：指定变量文件
ansible-playbook -e '@vars' var2.yml

# 3.7 使用变量文件（vars_files）

在独立文件中定义变量，在 PlayBook 中引用，优先级高于 PlayBook 中 vars 定义的变量。

# vars.yml
---
package_name: mariadb-server
service_name: mariadb
# var5.yml
---
- hosts: dbsrvs
  remote_user: root
  vars_files:            # 调用变量文件
    - vars.yml

  tasks:
    - name: "install package"
      yum: name=<!--swig￼26-->
      tags: install
    - name: "start service"
      service: name=<!--swig￼27--> state=started enabled=yes

# 3.8 针对主机和主机组定义变量

# 在主机清单中定义（全局有效）

主机变量（针对指定主机）：

[websrvs]
www1.example.com http_port=80 maxRequestsPerChild=808
www2.example.com http_port=8080 maxRequestsPerChild=909

组公共变量（针对组内所有主机，优先级低于主机变量）：

[websrvs:vars]
http_port=80
ntp_server=ntp.example.com
nfs_server=nfs.example.com

综合示例：

[websrvs]
192.168.80.18 hname=www1 domain=example.io    # 主机变量（优先级高）
192.168.80.28 hname=www2

[websrvs:vars]        # 分组变量
mark="-"

[all:vars]            # 公共变量（优先级低）
domain=example.org
# 调用变量修改主机名
ansible websrvs -m hostname -a 'name=<!--swig￼28--><!--swig￼29--><!--swig￼30-->'

# 命令行指定变量优先级更高，会覆盖清单中的变量
ansible websrvs -e domain=example.cn -m hostname -a 'name=<!--swig￼31--><!--swig￼32--><!--swig￼33-->'

K8S 等复杂场景中，常在 [all:vars] 定义全局变量（容器运行时、网络插件、CIDR 等），各角色主机再定义自身变量。

# 针对当前项目的 host_vars / group_vars（官方推荐）

上面的方式对所有项目都生效，官方更建议在项目目录中创建 host_vars 和 group_vars 目录，条理更清晰。

  • host_vars/主机名：针对单个主机定义变量；
  • group_vars/组名：针对单个组定义变量；
  • group_vars/all：对所有组有效的公共变量。

推荐做法：主机清单只存放分组信息，变量统一放在项目变量目录中。

# 创建项目目录
mkdir /data/ansible/test_project -p
cd /data/ansible/test_project

# 编写项目主机清单（仅分组信息）
vim hosts
[websrvs]
192.168.80.18
192.168.80.28

# 创建主机变量目录和分组变量目录
mkdir host_vars
mkdir group_vars

# 定义项目主机变量
vim host_vars/192.168.80.18
id: 1
vim host_vars/192.168.80.28
id: 2

# 定义项目分组变量
vim group_vars/websrvs
name: web
vim group_vars/all
domain: example.org

# 3.9 register：注册变量（重要）

功能：在 PlayBook 中用 register 将命令的输出保存到临时变量中，再用 debug 模块显示输出。

注意：Ansible 执行结果一般返回字典类型数据，包含很多不关心的字段，可通过指定字典的 key（如 stdout、stdout_lines）只看关心的数据。

# register1.yml
- hosts: 192.168.80.18
  tasks:
    - name: "get variable"
      shell: hostname
      register: name

    - name: "print variable"
      debug:
        msg: "<!--swig￼38-->"                   # 输出全部信息（变量要加引号）
        # msg: "<!--swig￼39-->"             # 显示命令
        # msg: "<!--swig￼40-->"              # 显示命令成功与否
        # msg: "<!--swig￼41-->"          # 输出结果（字符串）
        # msg: "<!--swig￼42-->"    # 输出结果（列表）
        # msg: "<!--swig￼43-->" # 列表第一个元素
        # msg: "<!--swig￼44-->" # 列表形式

name 实际是个字典，包含 cmd、rc、stdout、stdout_lines 等键值对，按需取用。

用 register 创建文件：

# register2.yml
- hosts: websrvs
  tasks:
    - name: "get variable"
      shell: hostname
      register: name
    - name: "create file"
      file: dest=/root/<!--swig￼45-->.log state=touch

register + debug（用 var 自定义输出）：

- hosts: 192.168.80.8
  tasks:
    - shell: echo "hello world"
      register: say_hi
    - shell: "awk -F: 'NR==1{print $1}' /etc/passwd"
      register: user
    - debug:
        var: say_hi.stdout
    - debug:
        var: user.stdout

实战：安装启动服务并检查状态：

- hosts: websrvs
  vars:
    package_name: nginx
    service_name: nginx
  tasks:

    host: web

# 小结

本文深入了 Playbook 的三个进阶特性：

  • Handlers/notify：配置变更后在 play 末尾一次性触发重启等操作，避免重复执行；
  • Tags：为任务打标签，实现选择性执行；
  • 变量：掌握 7 种来源与优先级，熟练使用 facts、命令行变量、vars、vars_files、host_vars/group_vars，并用 register 捕获命令输出驱动后续任务。

变量与 register 是让 Playbook 灵活、动态的核心。下一篇将讲解更高级的特性：模板（Jinja2）、循环迭代、条件判断、block、changed_when、滚动执行等。
