# Roles 角色与 Ansible Tower

本文是系列的收官篇，介绍 Ansible 的复用利器——Roles 角色：其目录结构、创建方式、调用方法，并通过多个实战案例演示角色的组织与复用；最后介绍 Ansible Tower 管理平台与推荐学习资料。掌握 Roles，就能将复杂的 Playbook 模块化、可复用，是大规模运维编排的关键。

# 一、Roles 角色概述

Roles 是 Ansible 自 1.2 版本引入的新特性，用于层次性、结构化地组织 PlayBook。Roles 能够根据层次结构自动装载变量文件、Tasks 以及 handlers 等，使用 Roles 只需在 PlayBook 中用 include 指令即可。

简单来讲，Roles 就是通过将变量、文件、任务、模板及处理器分别放置于单独的目录中，并可便捷地 include 它们的一种机制。角色一般用于基于主机构建服务的场景，也可用于构建守护进程等场景。

运维复杂场景建议使用 Roles，代码复用度高。

多个角色的集合目录 roles/，可将多个 role 分别放至独立子目录：

roles/
    mysql/
    nginx/
    tomcat/
    redis/

默认 roles 存放路径：

  • /root/.ansible/roles
  • /usr/share/ansible/roles
  • /etc/ansible/roles

官方文档：https://docs.ansible.com/ansible/latest/user_guide/playbooks_reuse_roles.html

# 二、Ansible Roles 目录编排

每个角色以特定的层级目录结构组织：

roles/                角色总目录
roles/mysql           某个角色目录
roles/mysql/files            角色文件目录（copy/script 调用的文件）
roles/mysql/vars             角色变量文件目录
roles/mysql/tasks            角色任务文件目录
roles/mysql/handlers         角色触发文件目录
roles/mysql/templates        角色模板文件目录

完整目录结构示例：

playbook1.yml
playbook2.yml
roles/
    project1/
        tasks/
        files/
        vars/
        templates/
        handlers/
        defaults/
        meta/
    project2/
        tasks/
        files/
        vars/
        templates/
        handlers/
        defaults/
        meta/

Roles 各目录作用：

目录作用
tasks/定义 task，role 的基本元素，至少包含 main.yml；其它文件需在 main.yml 中通过 include 包含
files/存放由 copy 或 script 等调用的文件
templates/template 模块查找模板文件的目录
handlers/至少包含 main.yml；其它文件需在 main.yml 中 include
vars/定义变量，至少包含 main.yml；其它变量文件需 include
meta/定义角色的特殊设定及依赖关系，至少包含 main.yml
defaults/设定默认变量，优先级低于 vars

tasks/main.yml、handlers/main.yml、vars/main.yml、meta/main.yml 是各目录的入口文件，其它文件在其中用 include 组织，实现任务的模块化拆分。

# 三、创建 role

创建 role 的步骤：

  1. 创建 role 的目录结构：在 roles 目录下创建以角色名命名的目录（如 mysql），在其中创建 tasks、files、handlers、templates、vars 等目录；用不到的目录可创建为空或不创建。
  2. 编写和准备 role 的功能文件。
  3. 编写 PlayBook 文件，调用需要的角色应用于指定主机。

用 ansible-galaxy 快速创建角色目录结构：

[root@ansible ansible] ansible-galaxy init test_role
- Role test_role was created successfully

[root@ansible ansible] tree test_role/
test_role/
├── defaults
│   └── main.yml
├── files
├── handlers
│   └── main.yml
├── meta
│   └── main.yml
├── README.md
├── tasks
│   └── main.yml
├── templates
├── tests
│   ├── inventory
│   └── test.yml
└── vars
    └── main.yml

ansible-galaxy init 会自动生成完整的角色骨架，省去手动建目录的麻烦。

# 四、PlayBook 调用角色

# 方法 1：直接列出角色名

- hosts: websrvs
  remote_user: root
  roles:
    - mysql
    - memcached
    - nginx

# 方法 2：用 role 键指定角色名，后续 k/v 传递变量

- hosts: all
  remote_user: root
  roles:
    - role: mysql
      username: mysql
    - { role: nginx, username: nginx }

# 方法 3：基于条件测试调用角色

- hosts: all
  remote_user: root
  roles:
    - { role: nginx, username: nginx, when: ansible_distribution_major_version == '7' }

# 多次调用同一角色并传不同变量/标签

- hosts: webservers
  roles:
    - common
    - role: foo_app_instance
      vars:
        dir: '/opt/a'
        app_port: 5000
      tags: typeA
    - role: foo_app_instance
      vars:
        dir: '/opt/b'
        app_port: 5001
      tags: typeB

- hosts: webservers
  roles:
    - { role: foo, vars: { message: "first" } }
    - { role: foo, vars: { message: "second" } }

# 五、Roles 中 tags 使用

在调用角色时可为角色打 tags，配合 ansible-playbook --tags 选择性执行。

# app-role.yml
---
- hosts: lbserver
  roles:
    - role: haproxy
    - role: keepalived

- hosts: appsrvs
  remote_user: root
  roles:
    - { role: nginx ,tags: [ 'nginx', 'web' ], when: ansible_distribution_major_version == "6" }
    - { role: httpd ,tags: [ 'httpd', 'web' ] }
    - { role: mysql ,tags: [ 'mysql', 'db' ] }
    - role: mariadb
      tags:
        - mariadb
        - db
  tags: app  # play 的 tag
ansible-playbook --tags="nginx,mysql" app-role.yml

# 六、实战案例

# 6.1 案例 1：实现 httpd 角色

创建角色目录与文件：

mkdir -pv /data/ansible/roles/httpd/{tasks,handlers,files}
cd /data/ansible/roles/httpd/

tasks/main.yml（任务入口，include 各子任务）：

- include: group.yml
- include: user.yml
- include: install.yml
- include: config.yml
- include: index.yml
- include: service.yml

tasks/group.yml：

- name: create apache group
  group: name=apache system=yes gid=80

tasks/user.yml：

- name: create apache user
  user: name=apache system=yes shell=/sbin/nologin home=/var/www/ uid=80 group=apache

tasks/install.yml：

- name: install httpd package
  yum: name=httpd

tasks/config.yml：

- name: config file
  copy: src=httpd.conf dest=/etc/httpd/conf/ backup=yes
  notify: restart

tasks/index.yml：

- name: index.html
  copy: src=index.html dest=/var/www/html/

tasks/service.yml：

- name: start service
  service: name=httpd state=started enabled=yes

handlers/main.yml：

- name: restart
  service: name=httpd state=restarted

在 files/ 下准备 httpd.conf 和 index.html。

目录结构：

/data/ansible/roles/httpd/
├── files
│   ├── httpd.conf
│   └── index.html
├── handlers
│   └── main.yml
└── tasks
    ├── config.yml
    ├── group.yml
    ├── index.yml
    ├── install.yml
    ├── main.yml
    ├── service.yml
    └── user.yml

调用角色：

# role_httpd.yml
---
- hosts: websrvs
  remote_user: root
  roles:
    - httpd
ansible-playbook /data/ansible/role_httpd.yml

# 6.2 案例 2：实现 nginx 角色

创建目录与 task 文件：

mkdir -pv /data/ansible/roles/nginx/{tasks,handlers,templates,vars}
cd /data/ansible/roles/nginx/

tasks/main.yml：

- include: install.yml
- include: config.yml
- include: index.yml
- include: service.yml

tasks/install.yml：

- name: install
  yum: name=nginx

tasks/config.yml（按系统版本用不同模板）：

- name: config file for centos7
  template: src=nginx7.conf.j2 dest=/etc/nginx/nginx.conf
  when: ansible_distribution_major_version=="7"
  notify: restart
- name: config file for centos8
  template: src=nginx8.conf.j2 dest=/etc/nginx/nginx.conf
  when: ansible_distribution_major_version=="8"
  notify: restart

tasks/index.yml（跨角色调用文件）：

- name: index.html
  copy: src=roles/httpd/files/index.html dest=/usr/share/nginx/html/    # 拷贝 httpd 角色的 html 文件

tasks/service.yml：

- name: start service
  service: name=nginx state=started enabled=yes

handlers/main.yml：

- name: restart
  service: name=nginx state=restarted

templates/nginx7.conf.j2（关键行）：

user <!--swig￼0-->;
worker_processes <!--swig￼1-->;   # 修改此行
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

templates/nginx8.conf.j2（关键行）：

user <!--swig￼2-->;
worker_processes <!--swig￼3-->;  # 修改此行
error_log /var/log/nginx/error.log;
pid /run/nginx.pid;

vars/main.yml：

user: daemon

调用角色：

# role_nginx.yml
---
- hosts: websrvs
  roles:
    - role: nginx
ansible-playbook /data/ansible/role_nginx.yml
# 验证
ansible websrvs -m shell -a 'ps -ef | grep nginx'

亮点：用 when 按系统版本选择模板；用变量 user 传入模板；跨角色复用 httpd 角色的 index.html。

# 6.3 案例 3：实现 memcached 角色

mkdir -pv /data/ansible/roles/memcached/{tasks,templates}
cd /data/ansible/roles/memcached

tasks/main.yml：

- include: install.yml
- include: config.yml
- include: service.yml

tasks/install.yml：

- name: install
  yum: name=memcached

tasks/config.yml：

- name: config file
  template: src=memcached.j2 dest=/etc/sysconfig/memcached

tasks/service.yml：

- name: service
  service: name=memcached state=started enabled=yes

templates/memcached.j2（缓存大小按总内存计算）：

PORT="11211"
USER="memcached"
MAXCONN="1024"
CACHESIZE="<!--swig￼4-->"        # 基于服务器总内存整除 4
OPTIONS=""

调用角色：

- hosts: appsrvs
  roles:
    - role: memcached
ansible-playbook /data/ansible/role_memcached.yml
# 验证
ansible appsrvs -m shell -a 'cat /etc/sysconfig/memcached | grep CACHESIZE'

# 6.4 案例 4：实现 MySQL 5.7 / 8.0 角色

vars/main.yml：

mysql_version: 8.0.23
mysql_file: mysql-<!--swig￼5-->-linux-glibc2.12-x86_64.tar.xz
mysql_root_password: <root密码>

tasks/main.yml（入口，按顺序 include）：

- include: install.yml
- include: group.yml
- include: user.yml
- include: unarchive.yml
- include: linkfile.yml
- include: data.yml
- include: config.yml
- include: script.yml
- include: path.yml
- include: service.yml
- include: secure.yml

各子任务文件示例：

# install.yml
- name: install packages
  yum:
    name:
      - libaio
      - numactl-libs

# group.yml
- name: create mysql group
  group: name=mysql gid=306

# user.yml
- name: create mysql user
  user: name=mysql uid=306 group=mysql shell=/sbin/nologin system=yes create_home=no home=/data/mysql

# unarchive.yml
- name: copy tar to remote host and file mode
  unarchive: src=<!--swig￼6--> dest=/usr/local/ owner=root group=root

# linkfile.yml
- name: create linkfile /usr/local/mysql
  file: src=/usr/local/mysql-<!--swig￼7-->-linux-glibc2.12-x86_64 dest=/usr/local/mysql state=link

# data.yml
- name: data dir
  shell: /usr/local/mysql/bin/mysqld --initialize-insecure --user=mysql --datadir=/data/mysql
  tags: data

# config.yml
- name: config my.cnf
  copy: src=/data/ansible/files/my.cnf dest=/etc/my.cnf

# script.yml
- name: service script
  shell: /bin/cp /usr/local/mysql/support-files/mysql.server /etc/init.d/mysqld

# path.yml
- name: PATH variable
  copy: content='PATH=/usr/local/mysql/bin:$PATH' dest=/etc/profile.d/mysql.sh

# service.yml
- name: enable service
  shell: chkconfig --add mysqld;/etc/init.d/mysqld start
  tags: service

# secure.yml
- name: change password
  shell: /usr/local/mysql/bin/mysqladmin -uroot password <!--swig￼8-->

调用角色：

# role_mysql.yml
---
- hosts: dbsrvs
  remote_user: root
  gather_facts: no
  roles:
    - mysql
ansible-playbook role_mysql.yml

# 6.5 案例 5：实现 MySQL 5.6 角色

与 5.7/8.0 类似，区别在于 5.6 用 mysql_install_db 初始化、用 mysql_secure_installation 脚本设置安全。

files/secure_mysql.sh：

#!/bin/bash
/usr/local/mysql/bin/mysql_secure_installation <<EOF
y
<密码>
<密码>
y
y
y
y
EOF

tasks/main.yml：

- include: install.yml
- include: group.yml
- include: user.yml
- include: unarchive.yml
- include: link.yml
- include: data.yml
- include: config.yml
- include: service.yml
- include: path.yml
- include: secure.yml

关键差异：

# data.yml（5.6 用 mysql_install_db）
- name: data dir
  shell: chdir=/usr/local/mysql/ ./scripts/mysql_install_db --datadir=/data/mysql --user=mysql

# secure.yml（用 script 模块调用安全脚本）
- name: secure script
  script: secure_mysql.sh

带标签调用多个角色：

- hosts: dbsrvs
  remote_user: root
  roles:
    - {role: mysql,tags: ["mysql","db"]}
    - {role: nginx,tags: ["nginx","web"]}
ansible-playbook -t mysql /data/ansible/mysql_roles.yml

# 6.6 案例 6：调用变量（按系统家族加载不同变量文件）

# roles/test_role/tasks/main.yml
- name: Include OS-specific variables
  include_vars: <!--swig￼9-->.yml
# vars/ 下按系统家族准备变量文件
ls /data/ansible/roles/test_role/vars/
Archlinux.yml    Debian.yml    FreeBSD.yml    OpenBSD.yml    RedHat.yml

include_vars 可根据 ansible_os_family 动态加载对应系统的变量文件，实现跨平台角色。

# 6.7 案例 7：实现多角色的选择

# role_httpd_nginx.yml
---
- hosts: websrvs
  roles:
    - {role: httpd,tags: [httpd,web], when: ansible_distribution_major_version=="7" }
    - {role: nginx,tags: [nginx,web], when: ansible_distribution_major_version=="8" }
ansible-playbook -t nginx /data/ansible/role_httpd_nginx.yml

系统版本为 7 装 httpd，为 8 装 nginx，实现按条件选择角色。

# 6.8 案例 8：依赖其它角色

角色可通过 meta/main.yml 声明对其它角色的依赖，调用该角色时会自动先执行其依赖角色。

# roles/wordpress/meta/main.yml
dependencies:
  - role: nginx
  - role: php-fpm
  - role: mysql

# 七、Ansible Tower 介绍

公司中实现运维自动化主要用到 Ansible，但 Ansible 脚本在服务器命令行中显得不太直观。Ansible Tower（最早以前叫 AWX） 是帮助 IT 团队更容易使用 Ansible 的解决方案。

Ansible Tower 是一个图形化、基于 WEB 的任务调度、复杂服务部署、IT 自动化的管理平台，属于发布配置管理系统，支持 API 及界面操作，基于 Django 编写。

主要能力：

  • 权限控制：可对用户进行权限控制，即使某用户不能传递某 SSH 凭证，也可通过 Tower 对该用户共享该凭证；
  • 图形化管理 Inventory：通过图形界面管理主机清单，也可对各类云资源做同步；
  • 日志与集成：记录所有 job 的日志，可与 LDAP 集成，拥有强大的可浏览 REST API；
  • 命令行与 CI：提供命令行工具，可与 Jenkins 轻松集成；
  • 自动伸缩：Provisioning 回调对自动伸缩拓扑提供支持。

获取与使用：可在 Ansible Tower 页面（https://ansible.com/tower）了解功能与下载。**Tower 的免费版本最多支持 10 个节点**，Ansible 公司提供支持，也可用 Ansible Playbook 来安装 Tower。安装完成后需订阅获取 License 文件才能使用。

Tower 适合需要图形化界面、权限管理、任务调度与审计的中大型团队，是对命令行 Ansible 的有力补充。

# 小结

本文介绍了 Ansible 的 Roles 角色机制：

  • 目录结构：tasks/files/handlers/templates/vars/meta/defaults 七大目录，各司其职，入口文件统一用 main.yml + include 组织；
  • 创建：用 ansible-galaxy init 快速生成角色骨架；
  • 调用：直接列名、传变量、条件调用、多次调用传不同参数；
  • 实战：httpd、nginx、memcached、MySQL 等角色，覆盖模板、变量、条件、依赖、跨角色复用；
  • Tower：图形化管理平台，适合团队化运维。

至此，Ansible 从基础概念、安装配置、命令行、模块、Playbook、进阶特性、综合实战到 Roles 与 Tower，已形成完整的知识体系。结合前 10 篇文章，你已具备用 Ansible 进行批量自动化运维的完整能力，建议在测试环境中动手实践，逐步沉淀自己的角色库与剧本库。
