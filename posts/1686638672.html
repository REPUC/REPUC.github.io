# Playbook 与 YAML 基础

本文是进入 Ansible 核心的门槛：介绍 Playbook 剧本的概念，系统讲解 YAML 语言的语法与数据类型，并拆解 Playbook 的核心组件（hosts、remote_user、tasks 等）。掌握这些，才能编写出结构清晰、可复用的自动化剧本。

# 一、Playbook 介绍

Playbook 是 Ansible 的核心编排方式。

  • PlayBook 剧本由一个或多个 "play" 组成的列表；
  • play 的主要功能是将预定义的一组主机，装扮成事先通过 task 定义好的角色。Task 实际是调用 Ansible 的模块（module），将多个 play 组织在一个 PlayBook 中，即可让它们联合起来，按编排的机制执行预定义动作；
  • Playbook 文件采用 YAML 语言编写。

简单理解：Play → 针对一组主机执行一批任务；PlayBook → 多个 Play 组成的剧本。每个 task 调用一个模块，在目标主机上执行具体操作。

# 二、YAML 语言

# 2.1 YAML 介绍

YAML：YAML Ain't Markup Language（YAML 不是标记语言）。不过开发这种语言时，其意思其实是 "Yet Another Markup Language"（仍是一种标记语言）。

YAML 是一个可读性高的、用来表达数据序列的格式，参考了 XML、C、Python、Perl 及 RFC2822 等多种语言，由 Clark Evans 于 2001 年首次发表。目前很多软件采用 YAML 存放配置信息，如 Ubuntu、Ansible、Docker、Kubernetes 等。

  • YAML 官网：http://www.yaml.org
  • Ansible YAML 语法：https://docs.ansible.com/ansible/latest/reference_appendices/YAMLSyntax.html

# 2.2 YAML 特性

优点：

  • 可读性好；
  • 与脚本语言交互性好；
  • 使用实现语言的数据类型；
  • 有一致的信息模型；
  • 易于实现；
  • 可基于流处理；
  • 表达能力强，扩展性好。

缺点：

  • 缩进敏感（建议用 VS Code 等编辑器编写）。

# 2.3 YAML 语法规则

  • 文件第一行可用连续三个连字符 --- 开始；
  • 也可用连续三个点号 ... 表示文件结尾；
  • 次行开始正常写内容，建议写明功能描述；
  • 使用 # 号注释；
  • 缩进必须统一，不能空格和 Tab 混用（建议用两个空格缩进）；
  • 缩进级别一致，同样缩进代表同样级别，程序通过缩进+换行判别配置级别；
  • 内容区别大小写，key/value 均需大小写敏感；
  • 多个 key/value 可同行写（用逗号分隔）也可换行写；
  • key 后面冒号要加一个空格，如 key: value；
  • value 可以是字符串，也可以是另一个列表；
  • 文件扩展名通常为 yml 或 yaml。

# 2.4 支持的数据类型

YAML 支持以下常用数据类型：

  • 标量（scalar）：单个的、不可再分的值。示例：age: 18
  • 对象（字典/mapping/hashes/dictionary）：键值对的集合。示例：account: { name: user1, age: 30 }
  • 数组（序列/sequence/list）：一组按次序排列的值。示例：course: [ linux, golang, python ]

# 标量 scalar

方式一：键值对

name: user1
age: 18

方式二：缩进方式

name:
  user1
age:
  18

标量是最基本的、不可再分的值，包括：字符串、布尔值、整数、浮点数、Null、时间、日期。

# 字典 Dictionary

字典由多个 key 与 value 构成，key 和 value 之间用 : 分隔且后面有一个空格。所有 k/v 可放一行，也可分别放不同行。

# 同一行，用 {} 表示，逗号分隔
account: { name: user1, age: 30 }

# 缩进方式
account:
  name: user1
  age: 18

# 不同行
name: Example Developer
job: Developer
skill: Elite

# 同一行，用 {} 表示
{name: "Example Developer", job: "Developer", skill: "Elite"}

# 列表 List

列表由多个元素组成，每个元素放在不同行且以 - 打头（- 后有一个空格）；或用 [] 括起来放同一行。

# 格式：用 [] 括起
course: [ linux, golang, python ]

# 以 - 开头的多行
course:
 - linux
 - golang
 - python

# 列表里也可包含字典
course:
 - linux: manjaro
 - golang: gin
 - python: django

# 不同行，行以 - 开头
- Apple
- Orange
- Strawberry
- Mango

# 同一行
[Apple, Orange, Strawberry, Mango]

YAML 表示一个家庭（综合示例）：

name: John Smith
age: 41
gender: Male
spouse: { name: Jane Smith, age: 37, gender: Female }   # 写在一行
# 也可以写成多行：
#   name: Jane Smith
#   age: 37
#   gender: Female

children: [ {name: Jimmy Smith, age: 17, gender: Male},
            {name: Jenny Smith, age: 13, gender: Female},
            {name: hao Smith, age: 20, gender: Male} ]   # 写在一行

# 写在多行，更为推荐的写法：
# - name: Jimmy Smith
#   age: 17
#   gender: Male
# - {name: Jenny Smith, age: 13, gender: Female}
# - {name: hao Smith, age: 20, gender: Male}

# 2.5 三种常见数据格式对比

格式全称特点
XMLExtensible Markup Language可扩展标记语言，可用于数据交换和配置
JSONJavaScript Object NotationJavaScript 对象表示法，用于数据交换或配置，不支持注释
YAMLYAML Ain't Markup Language用于配置，大小写敏感，不支持 Tab，支持注释

三者可用工具互相转换，如 https://www.json2yaml.com/ 、http://www.bejson.com/json/json2yaml/

YAML 相比 JSON 最大的优势是支持注释，便于在配置文件中说明，这是 Ansible 选择 YAML 的重要原因。

# 三、Playbook 核心组件

官方文档：https://docs.ansible.com/ansible/latest/reference_appendices/playbooks_keywords.html

一个 PlayBook 由多个组件组成，常见组件如下：

  • Hosts：执行的远程主机列表；
  • Tasks：任务集，由多个 task 元素组成的列表。每个 task 是一个字典，一个完整的代码块至少需包含 name 和任务本身，一个 name 只能包含一个 task；
  • Variables：内置变量或自定义变量在 playbook 中调用；
  • Templates：模板，可替换模板文件中的变量并实现简单逻辑的文件；
  • Handlers：与 notify 结合使用，由特定条件触发的操作，满足条件才执行；
  • Tags：标签，指定执行某条任务，用于选择运行 playbook 中的部分代码。Ansible 具有幂等性，会自动跳过无变化的部分，但有些代码检测变化的时间很长，此时可确信其无变化后通过 tags 跳过。

# 3.1 hosts 组件

hosts 用于指定要执行任务的主机，须事先定义在主机清单中。支持主机清单中的所有匹配模式：

- hosts: websrvs:appsrvs          # 两个组的并集
- hosts: websrvs:&dbsrvs          # 与，两个组的交集
- hosts: webservers:!dbsrvs       # 在 websrvs 组但不在 dbsrvs 组

# 3.2 remote_user 组件

remote_user 可用于 Host 和 task 中，也可通过 sudo 方式在远程主机执行任务，可用于 play 全局或某任务，甚至可在 sudo 时用 sudo_user 指定切换的用户。

- hosts: websrvs
  remote_user: root                 # 方式一：play 级

  tasks:
   - name: test connection
     ping:
       remote_user: testuser        # 方式二：task 级
       sudo: yes                     # 默认 sudo 为 root
       sudo_user: appuser            # sudo 为 appuser

# 3.3 task 列表和 action 组件

play 的主体是 task list，其中有一个或多个 task，各 task 按次序逐个在 hosts 指定的所有主机上执行：即在所有主机完成第一个 task 后，再开始第二个 task。

task 的目的是使用指定参数执行模块，模块参数中可使用变量。模块执行是幂等的，多次执行结果一致，安全。

每个 task 都应有 name，用于输出执行结果，建议内容清晰描述任务步骤；未提供 name 时，action 结果将用于输出。

task 两种格式：

action: module arguments     # 示例：action: shell wall hello
module: arguments            # 建议使用，示例：shell: wall hello

注意：Shell 和 Command 模块后面跟命令，而非 key=value。

示例：

---
# hello.yaml
- hosts: websrvs
  remote_user: root
  gather_facts: no              # 不收集系统信息，提高执行效率

  tasks:
    - name: test network connection
      ping:
    - name: wall
      shell: wall "hello world!"

检查与模拟执行：

# 检查语法
ansible-playbook --syntax-check hello.yaml

# 验证脚本（不真实执行）：模拟执行，不会在被控节点应用任何更改
ansible-playbook -C hello.yaml

# 真实执行
ansible-playbook hello.yaml

多 play 的 Playbook：

---
- hosts: websrvs
  remote_user: root
  gather_facts: no

  tasks:
    - name: install httpd
      yum: name=httpd
    - name: start httpd
      service: name=httpd state=started enabled=yes

---
- hosts: websrvs
  remote_user: root
  gather_facts: no

  tasks:
    - name: ping
      ping:
    - name: wall
      shell: wall hello

# 3.4 其它组件说明

  • 某任务状态在运行后为 changed 时，可通过 notify 通知相应的 handlers 任务；
  • 可通过 tags 给 task 打标签，在 ansible-playbook 命令上用 -t 指定调用。

# 四、Shell 脚本 vs Playbook

对比同一个"安装 Apache"任务的两种实现，能直观感受 Playbook 的优势。

Shell 脚本实现：

#!/bin/bash
# 安装 Apache
yum install --quiet -y httpd

# 复制配置文件
cp /tmp/httpd.conf /etc/httpd/conf/httpd.conf
cp /tmp/vhosts.conf /etc/httpd/conf.d/

# 启动 Apache 并设置开机启动
systemctl enable --now httpd

Playbook 实现：

---
- hosts: dbsrvs
  remote_user: root
  gather_facts: no        # 取消收集能提高执行速度

  tasks:
    - name: "安装Apache"
      yum: name=httpd
    - name: "复制配置文件"
      copy: src=/tmp/httpd.conf dest=/etc/httpd/conf/
    - name: "复制配置文件"
      copy: src=/tmp/vhosts.conf dest=/etc/httpd/conf.d/
    - name: "启动Apache, 并设置开机启动"
      service: name=httpd state=started enabled=yes

Playbook 的优势：结构化、幂等、可读性强、支持变量/条件/循环/通知，远比 Shell 脚本更适合大规模、可复用的自动化。

# 小结

本文讲解了 Playbook 的概念、YAML 的语法与数据类型（标量/字典/列表）、Playbook 核心组件（hosts、remote_user、tasks、handlers、tags、templates、variables），并通过 Shell 脚本与 Playbook 的对比体现了 Playbook 的价值。下一篇将介绍 ansible-playbook 的命令选项，并通过实战案例上手编写 Playbook。
