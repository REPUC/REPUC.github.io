# Nginx 架构、安装与运维管理

本文讲解 Nginx 的整体架构、模块体系，以及从安装到日常运维的完整流程：包安装与编译安装两种方式、命令与信号机制、平滑升级与回滚。掌握这些，才能在生产环境中正确部署与维护 Nginx。

# 一、Nginx 概述

Nginx（engine X），2002 年开始开发，分为社区版和商业版（Nginx Plus）。2019 年 3 月 F5 Networks 以 6.7 亿美元收购。Nginx 是免费、开源、高性能的 HTTP 和反向代理服务器、邮件代理服务器，以及 TCP/UDP 代理服务器，解决了 C10K（万级并发）乃至 C1000K（百万级并发）问题。

Nginx 的二次发行版：

  • Tengine：由淘宝网发起的 Web 服务器项目，在 Nginx 基础上针对大访问量网站添加高级功能与特性，性能与稳定性已在淘宝、天猫等大型网站得到验证，2011 年 12 月成为开源项目。
  • OpenResty：基于 Nginx 与 Lua 语言的高性能 Web 平台。

Nginx 功能：

  • 静态的 Web 资源服务器；
  • HTTP/HTTPS 协议的反向代理；
  • 结合 FastCGI/uWSGI/SCGI 等协议反向代理动态资源请求；
  • TCP/UDP 协议的请求转发（反向代理）；
  • IMAP4/POP3 协议的反向代理。

关键认知：标准 Nginx 是纯静态的，不能直接处理 PHP 等动态程序。Apache 是通过安装 PHP 模块扩展了动态处理能力（如 LAMP 架构）；Nginx 天生与后期都不直接支持 PHP，但可通过 FastCGI 协议将 PHP 请求转发给后端 PHP-FPM 处理。Nginx 处理动态资源的思路与 Apache 不同。

# 基础特性

  • 模块化设计，较好的扩展性；
  • 高可靠性；
  • 支持热部署：不停机更新配置文件、升级版本、更换日志文件；
  • 低内存消耗：10000 个 keep-alive 连接模式下的非活动连接，仅需 2.5M 内存；
  • event-driven、aio、mmap、sendfile。

# Web 服务相关功能

虚拟主机（Server）、支持 keep-alive 和管道连接（一个连接做多次请求）、访问日志（支持基于日志缓冲提高性能）、URL rewrite、路径别名、基于 IP 及用户的访问控制、支持速率限制及并发数限制、重新配置和在线升级而不中断客户工作进程。

# 二、Nginx 架构和进程

# 2.1 Nginx 架构

Nginx 采用与 Apache 相似的主进程 + 子进程双层架构：主进程称 Master 进程，子进程称 Worker 进程，由 Worker 进程处理用户请求。Worker 进程没有多线程，就一个进程，但可采用 IO 多路复用技术（select/poll/epoll，epoll 性能更好），即使只有一个进程也能同时处理大量网络并发。

Nginx 由众多子模块构成，是模块化程序，每个模块提供特定功能。如添加 http_proxy 模块提供反向代理功能，添加 http_fastcgi 模块提供处理 HTTP 请求的能力。模块通过编译时的 configure 选项启用（./configure 后跟选项决定程序特性，最终体现在模块上）。Nginx 支持 sendfile、mmap（零拷贝技术）、epoll（IO 多路复用）——这些都是 Nginx 性能好的原因。

# 2.2 Nginx 进程结构

Web 请求处理机制有两种：

  • 多进程方式：每接收一个客户端请求由主进程生成一个子进程响应，直到用户关闭连接。优势是处理速度快、子进程相互独立；但访问过大会导致服务器资源耗尽而无法提供请求。
  • 多线程方式：每收到一个请求派生一个线程与客户端交互，线程开销远小于进程，减轻对系统资源的要求；但多线程在同一进程内共享内存地址空间相互影响，主进程挂掉则所有子线程不能工作，IIS 采用此方式需定期重启才能稳定。

Nginx 是多进程组织模型，由 Master 主进程和 Worker 工作进程组成。

Master 进程（老板）功能：

  • 对外接口：接收外部操作（信号）；
  • 对内转发：根据外部操作通过信号管理 Worker；
  • 监控：监控 Worker 运行状态，Worker 异常终止后自动重启；
  • 读取 Nginx 配置文件并验证其有效性与正确性；
  • 建立、绑定和关闭 socket 连接；
  • 按配置生成、管理和结束工作进程；
  • 接受外界指令（重启、升级、退出等）；
  • 不中断服务实现平滑升级、重启服务并应用新配置；
  • 开启日志文件、获取文件描述符；
  • 升级失败进行回滚处理；
  • 编译和处理 perl 脚本。

Worker 进程（员工）功能：

  • 所有 Worker 进程平等；
  • 实际处理网络请求；
  • Worker 进程数量一般设置为核心数，充分利用 CPU 资源，同时避免进程过多导致竞争 CPU、增加上下文切换损耗；
  • 接受处理客户请求，将请求依次送入各功能模块处理；
  • I/O 调用、获取响应数据；
  • 与后端服务器通信，接收后端处理结果；
  • 缓存数据、访问缓存索引、查询调用缓存数据；
  • 发送请求结果、响应客户请求；
  • 接收主程序指令（重启、升级、退出等）。

# 2.3 Nginx 进程间通信

工作进程由主进程通过 fork() 生成。主进程根据配置文件决定 Worker 数量，建立一张全局工作表存放未退出的 Worker，生成后将新 Worker 加入工作表，并建立一条单向管道（主进程指向 Worker）传递给 Worker。该管道包含主进程向 Worker 发出的指令、Worker ID、在工作表中的索引及必要的文件描述符。

主进程与外界通过信号机制通信，接收到需处理的信号时，通过管道向相关 Worker 发送正确指令。每个 Worker 都能捕获管道中的可读事件，管道有可读事件时 Worker 从管道读取并解析指令，采取相应动作，完成主进程与 Worker 的交互。

# 2.4 Nginx 启动和 HTTP 连接建立

  • Nginx 启动时，Master 进程加载配置文件；
  • Master 初始化监听的 socket（创建 socket → 设置地址复用等选项 → 绑定到指定 IP 端口 → listen）；
  • Master fork 出多个 Worker 进程；
  • Worker 进程竞争新的连接，获胜方通过三次握手建立 Socket 连接并处理请求。

客户端向 Nginx 发起连接：

  • 客户端与 Nginx 三次握手建立连接后，某个 Worker accept 成功，得到建立好的 socket，创建 Nginx 对连接的封装（ngx_connection_t 结构体）；
  • 设置读写事件处理函数并添加读写事件，与客户端进行数据交互；
  • Nginx 或客户端主动关闭连接，至此一个连接寿终正寝。

# 2.5 HTTP 处理过程

Nginx 处理 HTTP 请求的步骤：

  1. 读取请求：通过 socket 接口读取请求，包括请求头和请求体；
  2. 解析请求：解析请求方法、请求路径、查询参数，以及请求头（Host、User-Agent、Content-Type 等）；
  3. 处理请求：静态文件直接返回文件内容；动态页面将请求转发给后端应用服务器；
  4. 处理请求体：将请求体读取到内存供后续处理；
  5. 处理响应：根据处理结果生成响应，将响应头和响应体发送给客户端；
  6. 关闭连接：处理完成后关闭连接、释放资源，等待下一个请求。

# 三、Nginx 模块介绍

Nginx 高度模块化，模块分类：

模块类型说明
核心模块Nginx 正常运行必不可少，提供错误日志、配置文件解析、事件驱动、进程管理等核心功能
标准 HTTP 模块HTTP 协议解析相关功能，如端口配置、网页编码、HTTP 响应头设置
可选 HTTP 模块扩展标准 HTTP 功能，如 Flash 多媒体传输、GeoIP 解析、网络压缩、SSL 支持
邮件服务模块支持 POP3、IMAP、SMTP 协议
Stream 服务模块实现反向代理功能，包括 TCP 协议代理
第三方模块扩展 Nginx 应用，完成开发者自定义功能，如 Json、Lua 支持

模块命名规则：核心模块 core module；HTTP 模块 ngx_http_*（分 HTTP Core 默认功能与 HTTP Optional 需编译指定）；Mail 模块 ngx_mail_*；Stream 模块 ngx_stream_*。

Nginx 模块早期不支持 DSO（动态装载）机制，1.9.11 版本开始支持动态装载和卸载。

# 四、Nginx 安装

# 4.1 版本与安装方式

版本类型：

  • Mainline Version（主线版）：主要开发版本，一般为奇数版本号，如 1.19.x；
  • Stable Version（稳定版）：当前最新稳定版，一般为偶数版本，如 1.20.x；
  • Legacy Versions（旧稳定版）：一般为偶数版本，如 1.18.x。

安装方式：推荐源码编译安装。

  • Yum/apt 系统仓库版本较旧；
  • 编译安装可方便自定义相关路径与功能，更贴合业务；
  • Docker 容器可直接运行。

# 4.2 软件包安装

# 4.3 编译安装

Nginx 由 C 语言编写，源码安装需准备编译器 GCC，以及 Automake 工具（自动创建 Makefile）。部分模块依赖第三方库：pcre（支持 rewrite）、zlib（支持 gzip 模块）、openssl（支持 ssl 模块）。

# 编译安装步骤

# 1) 安装依赖包
# Ubuntu22.04 / Ubuntu20.04
apt update && apt -y install gcc make libpcre3 libpcre3-dev openssl libssl-dev zlib1g-dev
# 红帽系统
yum -y install gcc pcre-devel openssl-devel zlib-devel
# Rocky8
yum -y install gcc make gcc-c++ libtool pcre pcre-devel zlib zlib-devel openssl openssl-devel perl-ExtUtils-Embed

# 2) 创建 nginx 用户
useradd -s /sbin/nologin nginx

# 3) 下载源码包并解压
cd /usr/local/src/ && wget http://nginx.org/download/nginx-1.18.0.tar.gz
tar xzvf nginx-1.18.0.tar.gz
cd nginx-1.18.0/

# 4) configure 配置（通过选项指定支持的特性）
./configure --help
./configure --prefix=/apps/nginx \
--user=nginx \
--group=nginx \
--with-http_ssl_module \
--with-http_v2_module \
--with-http_realip_module \
--with-http_stub_status_module \
--with-http_gzip_static_module \
--with-pcre \
--with-stream \
--with-stream_ssl_module \
--with-stream_realip_module

# 5) 编译安装
make && make install

# 6) 修改站点目录权限
chown -R nginx.nginx /apps/nginx

编译安装后生成四个主要目录：

  • conf：保存所有配置文件，nginx.conf 是核心主配置文件，其他 .conf 配置相关功能（如 fastcgi 的 fastcgi.conf、fastcgi_params），样板文件以 .default 为后缀；
  • html：保存 Web 文件，含默认错误页面 50x.html；
  • logs：保存访问日志、错误日志等；
  • sbin：保存 nginx 二进制启动脚本。

# 创建软链接与环境变量

# 创建软链接（便于命令行直接使用）
ln -s /apps/nginx/sbin/nginx /usr/sbin/

# 配置 PATH 环境变量
vim /etc/profile.d/nginx.sh
NGINX_HOME=/apps/nginx
export PATH=$NGINX_HOME/sbin:$PATH
source /etc/profile

# 验证
nginx -v
nginx -V        # 查看编译参数

平滑升级前提：启动 nginx 时使用二进制文件的绝对路径，而非在命令行直接输入 nginx（后者依赖环境变量）。不通过绝对路径启动，发送升级信号时 nginx 进程可能找不到新二进制程序，导致 execve() failed while executing new binary process "nginx" (2: No such file or directory)。

# 启动方式

方式一：直接用 nginx 命令启动/停止（测试用）

nginx                      # 启动
ss -ntl                    # 查看监听
nginx -s stop              # 关闭

方式二：创建 Nginx 自启动文件（推荐）

[Unit]
Description=nginx - high performance web server
Documentation=http://nginx.org/en/docs/
After=network-online.target remote-fs.target nss-lookup.target
Wants=network-online.target

[Service]
Type=forking
PIDFile=/apps/nginx/run/nginx.pid
ExecStart=/apps/nginx/sbin/nginx -c /apps/nginx/conf/nginx.conf
ExecReload=/bin/kill -s HUP $MAINPID
ExecStop=/bin/kill -s TERM $MAINPID
LimitNOFILE=100000

[Install]
WantedBy=multi-user.target
mkdir /apps/nginx/run/
vim /apps/nginx/conf/nginx.conf   # pid /apps/nginx/run/nginx.pid;

systemctl daemon-reload
systemctl enable --now nginx
netstat -nltp                  # 验证 0.0.0.0:80 监听

注意：启动与关闭方式要成对使用，不要混合。nginx 命令启动的用 nginx -s stop 关闭；systemctl 启动的用 systemctl 关闭，避免冲突。原因：Linux 下仅 Root 身份的程序可使用特权端口（1024 以下端口），普通用户使用会报错。

# 4.4 自动化部署

# 一键安装脚本（Linux 通用，支持 CentOS/Ubuntu/Rocky）

核心脚本逻辑（去除个人信息）：

#!/bin/bash
NGINX_VERSION=1.22.1
NGINX_FILE=nginx-${NGINX_VERSION}.tar.gz
NGINX_URL=http://nginx.org/download/
NGINX_INSTALL_DIR=/apps/nginx
SRC_DIR=/usr/local/src
CPUS=`lscpu | awk '/^CPU\(s\)/{print $2}'`

. /etc/os-release

# color / check / install 函数：彩色输出、检查文件、按系统安装依赖并编译
install() {
    # 创建 nginx 用户
    id nginx &> /dev/null || useradd -s /sbin/nologin -r nginx
    # 按系统安装依赖包（centos7/8、rocky、ubuntu 分别处理）
    # 下载、解压、configure（同上编译选项）、make -j $CPUS && make install
    chown -R nginx.nginx ${NGINX_INSTALL_DIR}
    ln -s ${NGINX_INSTALL_DIR}/sbin/nginx /usr/local/sbin/nginx
    echo "PATH=${NGINX_INSTALL_DIR}/sbin:${PATH}" > /etc/profile.d/nginx.sh
    # 生成 systemd service 文件
    cat > /lib/systemd/system/nginx.service <<EOF
[Unit]
Description=The nginx HTTP and reverse proxy server
After=network.target remote-fs.target nss-lookup.target
[Service]
Type=forking
PIDFile=${NGINX_INSTALL_DIR}/logs/nginx.pid
ExecStartPre=/bin/rm -f ${NGINX_INSTALL_DIR}/logs/nginx.pid
ExecStartPre=${NGINX_INSTALL_DIR}/sbin/nginx -t
ExecStart=${NGINX_INSTALL_DIR}/sbin/nginx
ExecReload=/bin/kill -s HUP \$MAINPID
KillSignal=SIGQUIT
TimeoutStopSec=5
KillMode=process
PrivateTmp=true
LimitNOFILE=100000
[Install]
WantedBy=multi-user.target
EOF
    systemctl daemon-reload
    systemctl enable --now nginx &> /dev/null
}
check
install
# 永久关闭防火墙和 SELinux（演示环境）
systemctl disable --now firewalld
setenforce 0
bash install_nginx.sh

# 验证
nginx
netstat -nltp

也可利用 Ansible 的 playbook 或 role 实现 nginx 编译安装的自动化批量部署。

# 五、Nginx 命令和信号

# 5.1 nginx 命令

nginx 命令支持向其发送信号实现不同功能（选项同上 -h 输出）。重点选项：

  • -? -h：打开帮助；
  • -v：显示版本信息并退出；
  • -V：显示版本和配置选项信息（重要，查看编译参数）；
  • -t / -T：检测配置文件语法（常用，语法检查）；
  • -q：检测配置时屏蔽非错误信息；
  • -s signal：给主进程发送信号：stop、quit、reopen、reload；
  • -p prefix：设置前缀路径；
  • -c filename：设置配置文件；
  • -e filename：设置错误日志文件；
  • -g directives：设置配置文件外的全局指令（如 nginx -g 'worker_processes 10;'）。

# 5.2 信号说明

信号/指令等价信号作用
stopSIGTERM / SIGINT立刻停止服务
quitSIGQUIT平滑停止服务
reloadSIGHUP平滑重启，重新加载配置文件
reopenSIGUSR1重新开始记录日志文件（日志切割时用途大）
USR2SIGUSR2平滑升级可执行程序（升级版本时使用）
WINCHSIGWINCH优雅停止工作进程（升级版本时使用）

# Quit 优雅关闭

通过 quit 实现 worker 进程优雅关闭：设置定时器 worker_shutdown_timeout → 关闭监听句柄 → 关闭空闲连接 → 在循环中等待全部连接关闭 → 退出所有 nginx 进程。

nginx -s quit

# Reload 流程

利用 reload 实现平滑修改配置并生效：

  1. 向 master 进程发送 HUP 信号（reload 命令）；
  2. master 校验配置语法是否正确；
  3. master 打开新的监听端口；
  4. master 用新配置启动新的 worker 子进程；
  5. master 向老 worker 子进程发送 QUIT 信号，老 worker 对已建立连接继续处理，处理完才优雅退出，未关闭的旧 worker 不再处理新请求；
  6. 老 worker 关闭监听句柄，处理完当前连接后结束进程。

# 六、Nginx 平滑升级和回滚

有时需要升级 Nginx 版本（如添加新模块、获取新功能），而 Nginx 正在跑业务无法停止，这时可选择平滑升级：在不停掉老进程的情况下启动新进程，老进程负责处理未完成的请求但不再接受新请求，新进程接受新请求，老进程处理完所有请求、关闭所有连接后停止。

# 6.1 平滑升级流程（四个阶段）

  1. 第一阶段：只有旧版 nginx 的 master 和 worker 进程；
  2. 第二阶段：旧版和新版 nginx 的 master 和 worker 进程并存，由旧版接收处理用户新请求；
  3. 第三阶段：旧版和新版并存，由新版接收处理用户新请求；
  4. 第四阶段：只有新版 nginx 的 master 和 worker 进程。

二、三阶段中，老版本 worker 进程慢慢关闭，直至请求都指向新版本 worker 进程。

# 6.2 平滑升级步骤

  1. 编译新版本，生成新版本的二进制文件（只 make，不 make install）；
  2. 用新 Nginx 程序文件替换旧 Nginx 二进制文件（先备份旧版本二进制）；
  3. 向旧版本 master 进程发送 USR2 信号启动新 nginx 进程：
    • master 修改 pid 文件名加后缀 .oldbin，成为 nginx.pid.oldbin；
    • 新 master 进程的 PID 存放至新 nginx.pid；
    • master 用新二进制启动新 master 及 worker 子进程，成为旧 master 的子进程；
    • 系统有新旧两个 master 及对应 worker 并存，当前新请求仍由旧 Nginx worker 处理；
  4. 向旧 Nginx 服务进程发送 WINCH 信号，使旧 worker 平滑停止，不再接收新请求：
    • 新请求由新 Nginx worker 处理；
    • 旧 master 进程仍存在；
    • 测试访问确认新版本是否正常工作；
  5. 升级正常：向旧 master 发送 QUIT 信号，关闭旧 master，删除 nginx.pid.oldbin，旧版本彻底下线，新版本正式上线；
  6. 升级有问题需回滚：向旧 master 发送 HUP，旧版本 worker 开始接收新请求；向新 master 发送 QUIT。

# 6.3 平滑升级与回滚实战

# 0) 模拟客户端持续连接：在站点目录生成大文件，客户端限速下载
dd if=/dev/zero of=/apps/nginx/html/test.img bs=1M count=10
wget --limit-rate=1k http://192.168.80.8/test.img   # 另开终端持续连接

# 第一阶段：下载最新稳定版并编译（只 make 不 install）
cd /usr/local/src
wget http://nginx.org/download/nginx-1.20.1.tar.gz
tar xzvf nginx-1.20.1.tar.gz
cd nginx-1.20.1
# 查看旧版本编译选项（configure arguments），新编译用相同参数
/apps/nginx/sbin/nginx -V
./configure --prefix=/apps/nginx --user=nginx --group=nginx --with-http_ssl_module ... 
make                        # 只编译
objs/nginx -v               # 验证新版本主程序

# 备份旧版本，覆盖新二进制（需 -f 强制覆盖，否则 Text file busy）
cp /apps/nginx/sbin/nginx /opt/nginx.old
cp -f ./objs/nginx /apps/nginx/sbin

# 检测新版本与配置文件语法兼容性
/apps/nginx/sbin/nginx -v
/apps/nginx/sbin/nginx -t
# 此时客户端访问仍是旧版本

# 第二阶段：发送 USR2 平滑升级
kill -USR2 `cat /apps/nginx/run/nginx.pid`
# 生成 nginx.pid.oldbin（存放旧版本 PID），新旧两个 master 并存，新请求仍由旧版本处理
ps auxf | grep nginx

# 第三阶段：发送 WINCH 关闭旧版本 worker（主进程不退出，便于回滚）
kill -WINCH `cat /apps/nginx/run/nginx.pid.oldbin`
# 新请求由新版本处理，旧 worker 平滑关闭（有旧请求则等待处理完）
curl -I http://192.168.80.8   # 返回 Server: nginx/1.20.1

# 第四阶段：测试正常后，发送 QUIT 退出旧 master
kill -QUIT `cat /apps/nginx/run/nginx.pid.oldbin`
# 直到所有旧连接断开，旧版本进程全部关闭

回滚：

# 1) 发送 HUP 重新拉起旧版本 worker
kill -HUP `cat /apps/nginx/run/nginx.pid.oldbin`
# 2) 发送 QUIT 平滑关闭新版 master 和 worker
kill -QUIT `cat /apps/nginx/run/nginx.pid`
# 3) 中断客户端连接请求
# 4) 新版本进程全部关闭
# 5) 恢复旧版主程序文件
nginx -s quit
cp /opt/nginx.old /apps/nginx/sbin/nginx -f
# 6) 客户端验证已回滚至老版本
curl http://192.168.80.8 -I

多机负载均衡场景：当 Nginx 站点基于多台主机实现负载均衡时，可在 LVS 调度器上调整——如对 Nginx-A 升级时，临时停止 LVS 将请求调度至 A 主机，从而实现从用户访问角度考虑的平滑升级，用户访问不受影响。

# 小结

本文覆盖了 Nginx 的架构与运维管理：Master/Worker 双层架构与进程间通信、模块分类体系、包安装与编译安装两种方式、命令与信号机制、平滑升级与回滚的完整流程。关键要点：启动用绝对路径以支持平滑升级、启动与关闭方式成对使用、升级依赖 USR2/WINCH/QUIT 三个信号。下一篇将深入 Nginx 的配置体系与核心模块（重点讲解 location 指令）。
