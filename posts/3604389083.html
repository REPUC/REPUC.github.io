# Linux 用户管理

本篇系统讲解 Linux 用户与用户组的管理：从用户的概念与分类、用户和组的配置文件，到 useradd/usermod/userdel/passwd、groupadd/groupmod/groupdel 等核心命令，以及普通用户提权的 su 与 sudo 两种方案，覆盖日常运维所需的全部知识点。

# 一、用户基本概述

# 1.1 什么是用户

用户指的是能够正常登录 Linux 或 Windows 系统的账号，例如登录 QQ 的账号、登录荣耀（手机/云服务）的账号等等。

# 1.2 为什么需要用户

  • 系统上的每一个进程（运行的程序），都需要一个特定的用户来运行；
  • 公司中通常使用普通用户管理服务器，因为 root 权限过大，容易造成故障。

# 1.3 用户有哪些分类

Linux 系统对用户 UID 有如下约定：

用户 UID系统中约定的含义
0超级管理员，最高权限，有着极强的破坏能力
1~200系统用户，用来运行系统自带的进程，默认已创建
201~999系统用户，用来运行用户安装的程序，此类用户无需登录系统
1000+普通用户，正常可以登录系统的用户，权限比较小，能执行的任务有限

# 1.4 查询用户 ID 信息

使用 id 命令可以查询当前登录用户的信息：

[root@web ~]# id        # 查看当前登录用户的信息
uid=6(root) gid=6(root) groups=6(root)

[root@web ~]# id xu     # 查询指定用户的信息
uid=1000(xu) gid=1000(xu) groups=1000(xu)

# 1.5 用户相关配置文件

创建新用户时，系统会将用户信息存放在 /etc/passwd 中，而密码单独存储在 /etc/shadow 中。这两个文件非常重要，不要轻易删除与修改。

# 1.5.1 passwd 文件

/etc/passwd 以 : 作为分隔符，总共七列，可使用 man 5 passwd 获取帮助：

[root@bgx ~]# head -1 /etc/passwd
root:x:0:0:root:/root:/bin/bash
列字段说明
第一列用户名称登录用户名
第二列密码占位符密码在 shadow 文件中，此处为 x
第三列用户 UID用户唯一编号
第四列组 GID用户所属的基本组
第五列注释信息用户备注
第六列用户家目录用户登录后的默认目录
第七列登陆 shell登录后使用的 shell，如 /bin/bash

# 1.5.2 shadow 文件

/etc/shadow 保存密码等安全信息，可使用 man 5 shadow 获取帮助：

[root@bgx ~]# head -1 /etc/shadow
bgx:!!:16312:0:99999:7:2:66275:
列字段说明
第一列用户名称对应 passwd 中的用户
第二列密码一长串字符（加密后的密码），! 表示无密码
第三列最近一次变更密码从 1970 年到现在，过了多少天
第四列密码最少使用天数0 表示无限制
第五列密码最长使用天数默认 99999，即不过期
第六列密码到期提醒密码到期前 7 天提醒变更密码
第七列密码过期宽限密码过期后 2 天强制提示变更用户密码
第八列账户失效时间从 1970 年起，账户在这个日期前可使用，到期后失效

补充：使用 chage 命令可以修改密码过期时间。

# 二、用户相关命令

# 2.1 添加用户 useradd

添加 Linux 系统普通用户使用 useradd 命令，需要以 root 账号登录系统后执行。

选项功能描述
-u指定要创建用户的 UID，不允许冲突
-g指定要创建用户的基本组
-G指定要创建用户的附加组，逗号隔开可添加多个附加组
-d指定要创建用户的家目录
-s指定要创建用户的 bash shell
-c指定要创建用户的注释信息
-M创建用户时不创建家目录
-r创建系统账户，默认无家目录

# 示例 1：创建 oldwang 用户

需求：用户 ID 为 6969，基本组为 ops，附加组为 dev，注释 "2000 student"，登陆 shell 为 /bin/bash。

[root@web ~]# groupadd ops
[root@web ~]# groupadd dev
[root@web ~]# useradd -u 6969 -g ops -G dev -c "2000 student" -s /bin/bash oldwang

# 示例 2：创建 mysql 系统用户

需求：创建一个 mysql 系统用户，不需要家目录，也不需要登录系统。

[root@web ~]# useradd -r dba -M -s /sbin/nologin

# 2.2 修改用户 usermod

修改 Linux 系统普通用户使用 usermod 命令，需要 root 账号登录系统后执行。

选项功能描述
-u指定修改用户的 UID
-g指定修改用户的基本组
-G指定修改用户的附加组，使用逗号隔开多个附加组，覆盖原有的附加组
-aG追加附加组，不覆盖原有附加组
-d指定修改用户的家目录
-s指定修改用户的 bash shell
-c指定修改用户的注释信息
-l指定修改用户的登陆名
-L指定要锁定的用户
-U指定要解锁的用户

# 示例 1：修改 oldwang 用户

需求：uid 为 5668，基本组为 network，附加组为 ops,dev,sa，注释信息为 student，登陆名称为 new_oldwang。

[root@web ~]# groupadd network
[root@web ~]# usermod oldwang -c "student" -g network -aG sa -l new_oldwang

# 示例 2：为 new_oldwang 配置密码、锁定与解锁

[root@web ~]# echo "123" | passwd --stdin new_oldwang   # 配置密码
[root@web ~]# usermod -L new_oldwang                   # 锁定用户
[root@web ~]# usermod -U new_oldwang                   # 解锁用户

# 2.3 删除用户 userdel

删除 Linux 系统普通用户使用 userdel 命令，需要 root 账号登录系统后执行。

# 示例 1：删除 new_oldwang 用户（连同家目录一起删除）

[root@web ~]# userdel -r new_oldwang

# 示例 2：批量删除系统中此前创建的所有无用用户

思路：使用 awk 提取无用的用户名称，使用 sed 拼接删除用户的命令，再调用 bash 执行。

[root@web ~]# awk -F ':' '$3>1000{print $1}' /etc/passwd |sed -r 's#(.*)#userdel -r \1#g' | bash

# 2.4 设定密码 passwd

创建用户后，如需使用该用户进行远程登录系统，则需要为其设定密码。

  • 普通用户只允许变更自己的密码，无法修改其他人密码，且密码长度必须 8 位字符；
  • 管理员用户允许修改任何人的密码，无论密码长度多长或多短。

注意事项：

  • 必须为普通用户设定密码，普通用户才能正常登录系统；
  • 普通用户不可以变更系统的状态（权限不够）；
  • 只有将"软件/系统"的权限分配给该普通用户，普通用户才可以变更相应的配置状态。

# 2.4.1 交互设定密码

[root@web ~]# passwd            # 为当前用户设定密码
[root@web ~]# passwd root       # 为 root 用户设定密码
[root@web ~]# passwd oldwang      # 为 oldwang 用户设定密码

# 2.4.2 非交互设定密码

# 非交互式设定简单密码
[root@web ~]# echo "123" | passwd --stdin jaxxwang

# 非交互式设定随机密码
[root@web ~]# yum install -y expect
[root@web ~]# echo $(mkpasswd -L 10 -d 2 -c 2 -C 2 -s 4) | tee pass.txt | passwd --stdin oldwang

# 2.5 系统创建用户流程

系统创建用户时，会参考如下两个配置文件；如果创建用户时指定了参数，则会覆盖系统默认配置；未指定参数则遵循默认配置。

  • /etc/login.defs
  • /etc/default/useradd

# 2.5.1 /etc/login.defs

主要定义创建用户时 UID 划分规则、密码加密类型、是否创建家目录 等：

[root@web ~]# grep -Ev "*#/*$" /etc/login.defs
MAIL_DIR            /var/spool/mail
PASS_MAX_DAYS       99999
PASS_MIN_DAYS       0
PASS_MIN_LEN        5
PASS_WARN_AGE       7
UID_MIN             1000
UID_MAX             60000
SYS_UID_MIN         201
SYS_UID_MAX         999
GID_MIN             1000
GID_MAX             60000
SYS_GID_MIN         201
SYS_GID_MAX         999
CREATE_HOME         yes
UMASK               077
USERGROUPS_ENAB     yes
ENCRYPT_METHOD      SHA512

# 2.5.2 /etc/default/useradd

主要定义：创建家目录的位置、默认用户的 shell 类型、默认从哪个位置拷贝环境变量、是否创建用户同名邮箱等：

[root@web ~]# cat /etc/default/useradd
GROUP=166
HOME=/home              # 家目录默认创建在 /home 下
INACTIVE=-1             # 账户过期宽限，-1 表示不过期
EXPIRE=                 # 账户失效时间，空表示永不失效
SHELL=/bin/bash         # 默认登陆 shell
SKEL=/etc/skel          # 默认环境变量模板目录
CREATE_MAIL_SPOOL=yes   # 是否创建用户同名邮箱（/var/spool/mail）

# 2.5.3 用户环境变量丢失案例

现象：不小心在当前用户家目录下执行 rm -rf .* 后，再次登录系统发现提示符变成了 -bash-4.1$，这是因为删除了当前用户的环境变量文件。

恢复方法：

-bash-4.1$ cp -a /etc/skel/.bash* ./
-bash-4.1$ exit
[root@web ~]#

原因：默认创建 Linux 用户时，会从 /etc/skel 目录中拷贝对应的环境变量（由 /etc/default/useradd 配置文件定义），所以只需从该目录拷贝相应的环境变量文件即可恢复故障。

# 三、用户组基本概述

# 3.1 什么是用户组

  • 组是一种逻辑层面的定义；
  • 逻辑上将多个用户归纳至一个组，当我们对组进行操作时，其实就相当于对组中的所有用户进行操作。

# 3.2 组有几种类别

对于用户来说，组分为如下几类：

  • 默认组：创建用户时不指定组，则默认创建与用户同名的组；
  • 基本组：用户有且只能有一个基本组，创建时可通过 -g 指定；
  • 附加组：用户可以有多个附加组，创建时通过 -G 指定。

# 3.3 组相关配置文件

组账户信息保存在 /etc/group 和 /etc/gshadow 两个文件中，重点关注 /etc/group。

# 3.3.1 group 文件

/etc/group 以 : 作为分隔符，总共 4 列：

[root@bgx ~]# head -1 /etc/group
root:x:0:
列字段说明
第一列组的名称组名
第二列组的密码密码在 gshadow 文件中，此处为 x
第三列组 GID组的唯一编号
第四列组成员组内的附加组成员（不显示基本成员）

# 3.3.2 gshadow 文件

/etc/gshadow 以 : 作为分隔符，总共 4 列：

[root@bgx ~]# head -1 /etc/gshadow
root:*:0:
列字段说明
第一列组的名称组名
第二列组的密码组密码（加密存储）
第三列组管理员可管理该组的成员
第四列组成员组内的附加组成员（不显示基本组成员）

# 四、用户组相关命令

# 4.1 添加组 groupadd

添加 Linux 用户组使用 groupadd 命令，需要 root 账号登录系统后执行。

选项功能描述
-f组已经存在时，不报错，直接返回成功创建的状态
-g为新组设置 GID，若 GID 已经存在会提示 GID 已经存在
-r创建一个系统组

# 示例 1：添加 salary 组，并指定 GID 为 10000

[root@web ~]# groupadd salary -g 10000
[root@web ~]# tail -1 /etc/group
salary:x:10000:

# 示例 2：添加 salary_2 系统组

[root@web ~]# groupadd -r salary_2
[root@web ~]# tail -1 /etc/group
salary_2:x:988:

# 4.2 修改组 groupmod

修改 Linux 用户组使用 groupmod 命令，需要 root 账号登录系统后执行。

选项功能描述
-g修改组的 GID，若 GID 已存在会提示 GID 已存在
-r创建系统组（保留用法）
-n改名为新的组名

# 示例 1：修改 salary 用户组组名为 system

[root@web ~]# groupmod -n system salary
[root@web ~]# tail -1 /etc/group
system:x:10000:

# 示例 2：修改 system 用户组 GID 为 56868

[root@web ~]# groupmod system -g 56868
[root@web ~]# tail -1 /etc/group
system:x:56868:

# 4.3 删除组 groupdel

删除 Linux 用户组使用 groupdel 命令，需要 root 账号登录系统后执行。

# 示例 1：删除 salary_2 系统用户组

[root@web ~]# groupdel salary_2

# 示例 2：删除有用户作为基本组的系统组

创建 tom 用户，设置主组为 system，然后测试删除 system 组：

[root@web ~]# useradd tom -g system
[root@web ~]# groupdel system
groupdel: cannot remove the primary group of user 'tom'
# 提示：存在以该组为基本组的用户，无法删除
[root@web ~]# userdel -r tom
[root@web ~]# groupdel system

# 4.4 用户与用户组场景实战

需求：

  1. 创建 dev 与 ops 两个组；
  2. 创建 bob 用户，设定基本组为 dev，密码为 123；
  3. 创建 alice 用户，设定基本组为 ops，密码为 123；
  4. 创建 /opt/resource 文件，修改属组为 ops、权限为 664；
  5. 测试发现 alice 用户可以读写，而 bob 用户仅可以查看；
  6. 希望 bob 也能对文件进行读写，快速实现的方式是为 bob 添加 ops 附加组。

步骤 1：创建组与用户

[root@web ~]# groupadd dev
[root@web ~]# groupadd ops
[root@web ~]# useradd bob -g dev
[root@web ~]# useradd alice -g ops

步骤 2：为用户设定登录密码

[root@web ~]# echo "123" | passwd --stdin bob
[root@web ~]# echo "123" | passwd --stdin alice

步骤 3：建立文件，分配权限

[root@web ~]# echo "data" > /opt/resource
[root@web ~]# chgrp ops /opt/resource
[root@web ~]# chmod 664 /opt/resource

步骤 4：使用 ops 组的 alice 用户测试读写权限

[alice@web ~]$ echo "alice-data" >> /opt/resource
[alice@web ~]$ cat /opt/resource
data
alice-data

步骤 5：使用 dev 组的 bob 用户测试读写权限（只有读权限）

[bob@web ~]$ echo "bob-data" >> /opt/resource
-bash: /opt/resource: 权限不够

[bob@web ~]$ cat /opt/resource
data
alice-data

步骤 6：为 bob 用户添加 ops 附加组，借助 ops 组权限实现读写

[root@web ~]# usermod bob -G ops
[root@web ~]# id bob
uid=1002(bob) gid=202(dev) groups=202(dev),2021(ops)

# 再次测试，bob 用户可以正常写入
[bob@web ~]$ echo "bob-data" >> /opt/resource
[bob@web ~]$ cat /opt/resource
data
alice-data
bob-data

# 五、普通用户无权限如何提权

公司服务器对外通常禁止 root 用户直接登录，日常使用普通用户管理服务器。当普通用户执行 /sbin 目录下的命令时，会因没有权限而无法正常管理服务器。如何在不使用 root 登录系统的前提下，让普通用户完成日常工作？

两种提权方式：

  • su：switch user 身份切换。使用普通用户登录，然后使用 su 命令切换到 root。
    • 缺点：需要知道 root 密码。
  • sudo：提权。当需要使用 root 权限时进行提权，无需切换至 root 用户。
    • 优点：无需知道 root 密码，安全性高；
    • 缺点：需要预先定义规则，较为复杂。

# 5.1 su 命令身份切换

# 5.1.1 su 切换身份

  • su - username：切换身份，属于登陆式 shell；
  • su username：切换身份，属于非登陆式 shell。

示例 1：普通用户使用 su 切换到 root 用户，需要输入 root 超级管理员密码

[oldwang@web ~]$ su - root
密码:
[root@node1 ~]# pwd
/root

示例 2：以某个用户的身份执行某个命令，使用 su -c

[root@web ~]# su - oldwang -c 'ifconfig'
[root@web ~]# su - oldwang -c 'ls ~'

# 5.1.2 Shell 登陆分类

  • 登陆 shell：需要输入用户名和密码才能进入 shell，是日常接触最多的一种；
  • 非登陆 shell：不需要输入用户名和密码就能进入 shell，比如运行 bash 会开启一个新的会话。

登陆式 shell 与非登陆式 shell 最大的区别就在于加载的环境变量不一样：

  • 登录式 shell 配置文件加载顺序：/etc/profile → /etc/profile.d/*.sh → ~/.bash_profile → ~/.bashrc → /etc/bashrc
  • 非登录式 shell 配置文件加载顺序：~/.bashrc → /etc/bashrc → /etc/profile.d/*.sh

# 5.1.3 环境变量配置文件

  • profile 类文件：设定环境变量，登陆前运行的脚本和命令；
  • bashrc 类文件：设定本地变量，定义命令别名。

用户配置文件：

  • ~/.bash_profile
  • ~/.bashrc

全局环境变量：

  • /etc/profile
  • /etc/profile.d/*.sh
  • /etc/bashrc

# 5.2 sudo 命令提权

# 5.2.1 sudo 的由来

su 命令在用户身份切换时需要拿到 root 管理员密码；多人协作时，如果某个用户不小心泄露了 root 密码，系统会变得非常不安全。为改进这个问题，就有了 sudo。

sudo 就是给某个普通用户埋下了"浩克（hulk）"的种子：当需要执行特权操作时进行"唤醒"，获取最高权限，但正常情况下仍然是普通用户，依然受到系统的约束与限制。

# 5.2.2 sudo 快速起步

快速配置 sudo 方式：

步骤 1：将用户加入 wheel 组（默认 wheel 组拥有 sudo 权限）

[root@node1 ~]# usermod oldwang -G wheel

步骤 2：切换到普通用户身份

[root@web ~]# su - oldwang

步骤 3：普通用户正常情况下无法删除 /opt 目录

[oldwang@web ~]$ rm -rf /opt/
rm: cannot remove '/opt': Permission denied

步骤 4：使用 sudo 提权，输入普通用户密码即可删除无权限的 /opt 目录

[oldwang@web ~]$ sudo rm -rf /opt

步骤 5：后期可通过审计日志查看普通用户提权执行了什么操作

[root@web ~]# tail -f /var/log/secure

# 5.2.3 sudo 权限分配

快速提权方式下 sudo 什么操作都可以执行，能否限制只开启某些命令的使用权限、其他命令不允许？实现架构为：用户 → 组 → 命令集。

步骤 1：创建用户并设定密码

[root@www ~]# useradd ops1
[root@www ~]# useradd ops2
[root@www ~]# useradd dev1
[root@www ~]# useradd dev2
[root@www ~]# echo "1" | passwd --stdin ops1
[root@www ~]# echo "1" | passwd --stdin ops2
[root@www ~]# echo "1" | passwd --stdin dev1
[root@www ~]# echo "1" | passwd --stdin dev2

步骤 2：编辑 /etc/sudoers 文件配置规则（使用 visudo 编辑，避免语法错误）

# 1. 定义用户别名，将用户划分到一个组
User_Alias OPS = ops1,ops2
User_Alias DEV = dev1,dev2

# 2. 将局部命令划分到命令集中
Cmnd_Alias NETWORKING = /sbin/ifconfig, /bin/ping
Cmnd_Alias SOFTWARE = /bin/rpm, /usr/bin/yum
Cmnd_Alias SERVICES = /sbin/service, /usr/bin/systemctl start
Cmnd_Alias STORAGE = /bin/mount, /bin/umount
Cmnd_Alias DELEGATING = /bin/chown, /bin/chmod, /bin/chgrp
Cmnd_Alias PROCESSES = /bin/nice, /bin/kill, /usr/bin/kill, /usr/bin/killall

# 3. 配置权限：OPS 组可执行网络、软件、服务、存储、委派、进程命令；DEV 组可执行软件、进程命令
OPS ALL=(ALL) NETWORKING, SOFTWARE, SERVICES, STORAGE, DELEGATING, PROCESSES
DEV ALL=(ALL) SOFTWARE, PROCESSES

步骤 3：登录对应用户，检查 sudo 权限

# ops 组用户测试 sudo 权限
[ops1@web ~]# sudo -L
[sudo] password for ops1:
User ops1 may run the following commands on web:

# 5.2.4 sudo 执行流程

  1. 普通用户执行 sudo 命令时，会检查 /var/db/sudo 是否存在时间戳缓存；
  2. 如果存在则不需要输入密码，否则需要输入用户与密码；
  3. 输入密码后检测该用户是否拥有该权限；
  4. 如果有则执行，否则报错退出。

流程简示：普通用户运行 sudo →（时间戳未过期则直接执行，否则）输入用户自己的口令 → 执行命令并返回结果。

注意：sudo 不支持系统内置命令。

# 5.2.5 sudo 相关练习

练习 1：授予 jack 用户能通过 sudo 执行 ls、sed、awk 命令权限

jack ALL=(ALL) /bin/ls,/bin/sed,/bin/awk

练习 2：授予 alice 用户 sudo 执行 Linux 所有命令并且不用输入密码

alice ALL=(ALL) NOPASSWD:ALL

练习 3：授权 oldwang 用户 sudo 执行 passwd 命令修改任何用户的密码，但唯独不能修改 root 用户的密码

oldwang ALL=(ALL) /bin/passwd [a-z]*, !/bin/passwd root
