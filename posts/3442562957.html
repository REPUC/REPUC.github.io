# Playbook 高级特性

本文讲解 Playbook 的高级特性：template 模板与 Jinja2、循环迭代、when 条件判断、block 分组、changed_when、滚动执行 serial、委派与本地执行、run_once、环境变量、wait_for、以及 YAML 文件间的相互调用。这些特性让 Playbook 能处理动态、复杂、规模化的场景。

# 一、template 模块与 Jinja2

# 1.1 概念

template 是 Ansible 的一个模块，功能是根据模板文件动态生成配置文件。

  • 模板文件必须存放于 templates 目录下，且命名为 .j2 结尾；
  • yaml/yml 文件需和 templates 目录平级，这样调用模板时无需写路径，template 模块会自动去 templates 目录查找；
  • Jinja2 是 Python 下广泛应用的模板引擎，设计思想来源于 Django，扩展了语法与功能。Ansible 的模板配置文件就是用 Jinja2 编写的。

template 与 copy 的区别：copy 模块原样复制文件，而 template 在复制时对模板文件进行渲染后再复制。

# 1.2 Jinja2 语言

Jinja2 是现代的、设计者友好的、仿照 Django 模板的 Python 模板语言，特性包括：沙箱执行、HTML 自动转义防 XSS、模板继承、及时编译、易于调试、可配置语法。

Jinja2 支持的数据类型与操作：

  • 字面量：字符串（单/双引号）、整数、浮点数；
  • 列表：[item1, item2, ...]；
  • 元组：(item1, item2, ...)；
  • 字典：{key1:value1, key2:value2, ...}；
  • 布尔：true/false；
  • 算术运算：+、-、*、/、//（整除）、%（取余）、**（幂）；
  • 比较：==、!=、>、>=、<、<=；
  • 逻辑：and、or、not；
  • 流表达式：for、if、when。

# 1.3 template 模板示例

利用 templates 同步 nginx 配置文件，将 worker_processes 设为由远程主机 CPU 个数决定。

# 创建 templates 目录，准备模板文件
mkdir templates
cp files/nginx.conf templates/nginx.conf.j2
vim templates/nginx.conf.j2
#   worker_processes <!--swig￼8-->;
# temnginx2.yml
---
- hosts: websrvs
  remote_user: root

  tasks:
  - name: install nginx
    yum: name=nginx
  - name: "template config to remote hosts"
    template: src=nginx.conf.j2 dest=/etc/nginx/nginx.conf
  - name: start service
    service: name=nginx state=started enabled=yes
ansible-playbook temnginx2.yml
# 验证节点端 nginx 进程数
ansible websrvs -m shell -a 'ps -aux | grep nginx'

注意：template 模块不能在 ad-hoc 命令行使用，只能在 PlayBook 中使用，且模板文件必须以 .j2 结尾。

# 二、循环迭代

当需要重复执行任务时，使用循环迭代机制。写 PlayBook 时常有多个 Task 重复引用同一模块（如启动 10 个服务、拷贝 10 个文件），用循环可避免代码臃肿。

# 2.1 with_items 迭代

  • 对迭代项的引用，固定变量名为 item；
  • 用 with_items 或 loop 关键字给定要迭代的元素列表；
  • Ansible 2.5 后可用 loop 代替 with_items；
  • 列表元素可为字符串或字典。

创建多个用户：

- hosts: websrvs
  remote_user: root
  tasks:
    - name: add several users
      user: name=<!--swig￼20--> state=present groups=wheel
      with_items:
        - testuser1
        - testuser2
        - testuser3

（等价于写 3 个独立 user task，循环写法更简洁。）

卸载 mariadb（循环删除多个文件目录）：

- hosts: appsrvs:!10.0.0.8
  remote_user: root
  tasks:
    - name: stop service
      shell: /etc/init.d/mysqld stop
    - name: "delete files and dir"
      file: path=<!--swig￼21--> state=absent
      with_items:
        - /usr/local/mysql
        - /usr/local/mariadb-10.2.27-linux-x86_64
        - /etc/init.d/mysqld
        - /etc/profile.d/mysql.sh
        - /etc/my.cnf
        - /data/mysql
    - name: delete user
      user: name=mysql state=absent remove=yes

安装多个软件包、复制多个文件：

- hosts: websrvs
  remote_user: root
  tasks:
    - name: install some packages
      yum: name=<!--swig￼22--> state=present
      with_items:
        - nginx
        - memcached
        - php-fpm

    - name: copy file
      copy: src=<!--swig￼23--> dest=/tmp/<!--swig￼24-->
      with_items:
        - file1
        - file2
        - file3

# 2.2 迭代嵌套子变量

迭代中可嵌套子变量，关联多个变量。

创建组 + 创建用户（带 uid）：

- hosts: websrvs
  remote_user: root
  tasks:
    - name: add some groups
      group: name=<!--swig￼25--> state=present
      with_items:
        - nginx
        - mysql
        - apache
    - name: add some users
      user: name=<!--swig￼26--> group=<!--swig￼27--> uid=<!--swig￼28--> state=present
      with_items:
        - { user: 'nginx', group: 'nginx', uid: "80" }
        - { user: 'mysql', group: 'mysql', uid: "3306"}
        - { user: 'apache', group: 'apache', uid: "8080"}

带家目录的用户：

- name: add some users
  user: name=<!--swig￼29--> group=<!--swig￼30--> home=<!--swig￼31--> create_home=yes state=present
  with_items:
    - { name: 'user1', group: 'g1', home: '/data/user1' }
    - { name: 'user2', group: 'g2', home: '/data/user2' }
    - { name: 'user3', group: 'g3', home: '/data/user3' }

# 2.3 until 循环

启动某服务可能需要一段时间才完全起来，可用 until 循环多次探测，直到成功才判定启动成功。until 为 false 时执行循环，为 true 则退出。

- hosts: localhost
  gather_facts: false
  tasks:
    - debug: msg="until"
      until: false
      retries: 4      # 默认 3 次
      delay: 1

# 2.4 with_lines 逐行处理

with_lines 将命令输出结果按行迭代。lookup 插件 lines 用于从命令执行结果读取每一行，with_lines 迭代其每一行。实用场景：find 找出一堆文件后逐个操作（如 copy）。

- hosts: localhost
  gather_facts: no
  tasks:
    - copy:
        src: "<!--swig￼41-->"
        dest: /tmp/shell_script/
      with_lines:
        - find ~ -maxdepth 1 -type f -name "a*.sh"

# 三、when 条件判断

很多任务只有在特定条件下才能执行，when 语句实现条件测试。当需要根据变量、facts 或此前任务的执行结果作为某 task 执行与否的前提时，在 task 后添加 when 子句即可（Jinja2 语法格式）。

判断操作系统：

- hosts: websrvs
  remote_user: root
  tasks:
    - name: "shutdown RedHat flavored systems"
      command: /sbin/shutdown -h now
      when: ansible_os_family == "RedHat"

对主机名判断：

- name: install nginx
  yum: name=nginx
  when: ansible_fqdn is match ("web*")

判断服务状态决定是否重启：

- hosts: websrvs
  tasks:
    - name: Check nginx Service
      command: systemctl is-active nginx
      ignore_errors: yes
      register: check_nginx
    - name: Httpd Restart
      service: name=nginx state=restarted
      when: check_nginx.rc == 0

组合判断（或关系）：

- name: "shut down CentOS 6 and Debian 7 systems"
  command: /sbin/shutdown -t now
  when: (ansible_facts['distribution'] == "CentOS" and ansible_facts['distribution_major_version'] == "6") or (ansible_facts['distribution'] == "Debian" and ansible_facts['distribution_major_version'] == "18")

when 的列表形式（表示 and 关系）：

- hosts: all
  tasks:
  - name: "shut down CentOS 7 systems"
    reboot:
    when:
      - ansible_facts['distribution'] == "CentOS"
      - ansible_facts['distribution_major_version'] == "7"

判断是否定义：

- hosts: localhost
  tasks:
  - debug: msg="undefined"
    when: bar is undefined

与循环一起使用：

- hosts: localhost
  tasks:
  - debug: msg="item > 3"
    with_items: [1,2,3,4,5]
    when: item > 3

判断执行状态（failed/succeeded/skipped）：

- hosts: localhost
  tasks:
  - command: /bin/true
    register: result
    ignore_errors: True
  - debug: msg="failed"
    when: result is failed
  - debug: msg="succeeded"
    when: result is succeeded
  - debug: msg="skipped"
    when: result is skipped

failed_when（与 when 相反，满足条件时使任务失败）：

- hosts: localhost
  tasks:
    - command: echo failed
      register: result
      failed_when: "'failed' in result.stdout"
      # failed_when: false  不满足条件，任务正常执行
      # failed_when: true   满足条件，任务失败
    - debug: msg="echo failed_when"

按系统版本选择不同模板：

- hosts: websrvs
  remote_user: root
  tasks:
    - name: install conf file to centos7
      template: src=nginx.conf.c7.j2 dest=/etc/nginx/nginx.conf
      when: ansible_distribution_major_version == "7"
    - name: install conf file to centos6
      template: src=nginx.conf.c6.j2 dest=/etc/nginx/nginx.conf
      when: ansible_distribution_major_version == "6"

# 四、block 分组

当想在满足一个条件下执行多个任务时，用 block 分组，避免每个任务都写 when。

- hosts: localhost
  tasks:
    - block:
        - debug: msg="first"
        - debug: msg="second"
      when:
        - ansible_facts['distribution'] == "CentOS"
        - ansible_facts['distribution_major_version'] == "8"

（等价于给 first、second 两个 debug 分别加同样的 when，block 写法更简洁。）

# 五、changed_when

# 5.1 关闭 changed 状态

当确定某个 task 不会对被控端做修改时，默认结果可能显示为黄色 changed 状态，可用 changed_when: false 关闭，显示为绿色。

- hosts: websrvs
  tasks:
    - name: check sshd service
      shell: ps aux | grep sshd
      changed_when: false

# 5.2 利用 changed_when 检查返回结果

changed_when 可检查 task 返回结果，决定是否继续向下执行。

- hosts: websrvs
  tasks:
    - name: install nginx
      yum: name=nginx
    - name: config file
      template: src="nginx.conf.j2" dest="/etc/nginx/nginx.conf"
      notify: restart nginx
    - name: check config
      shell: /usr/sbin/nginx -t
      register: check_nginx_config
      changed_when:
        - (check_nginx_config.stdout.find('successful'))  # 结果含 successful 则继续
        - false                                            # 关闭 changed 状态
    - name: start service
      service: name=nginx state=started enabled=yes
  handlers:
    - name: restart nginx
      service: name=nginx state=restarted

# 六、滚动执行（serial）

# 6.1 默认执行逻辑

Ansible 默认执行逻辑：

  • 对于每一个 task，Ansible 都在所有主机之间并行执行；
  • 在开始下一个 task 之前，等待所有主机都完成上一个 task；
  • 按指定顺序运行 task。

# 6.2 serial 滚动更新

管理节点过多时可能超时。对于滚动更新用例，可用 serial 关键字定义一次管理多少主机，也可指定为百分比。

滚动更新的好处：

  • 同一时刻只有部分服务器在更新，其他服务器仍对外提供服务；
  • 若本批更新失败，其他服务器仍可提供服务。
# 每次只同时处理 2 个主机，将所有 task 执行完成后，再选下 2 个主机执行
- hosts: all
  serial: 2
  gather_facts: False
  tasks:
    - name: task one
      command: hostname
    - name: task two
      command: hostname
# 每次处理 20% 的主机
- name: test serial
  hosts: all
  serial: "20%"

典型场景：对负载均衡器后面的应用服务器更新时，逐台从负载均衡摘除、更新、再添加回去。

- hosts: websrvs
  serial: 1
  tasks:
    - name: task1
      shell: wall "<!--swig￼42--> is running task1"
    - name: task2
      shell: wall "<!--swig￼43--> is running task2"
    - name: task3
      shell: wall "<!--swig￼44--> is running task3"

# 七、委派与本地执行

# 7.1 delegate_to：委派至其它主机执行

利用委托技术，可在非当前被控主机的其它主机上执行指定操作。

# 在 10.0.0.8 上执行 hostname -I，而非当前主机 localhost
- hosts: localhost
  tasks:
    - name: show ip address
      command: hostname -I
      delegate_to: 10.0.0.8

# 7.2 local_action：在本地执行

# 在本地执行 ifconfig，而非 10.0.0.8
- hosts: 10.0.0.8
  tasks:
    - name: show ip address
      local_action: command ifconfig

# 八、run_once：只执行一次

利用 run_once 指令可只执行一次，而非在所有被控主机都执行。

- hosts: websrvs
  tasks:
    - command: hostname
      run_once: true
ansible-playbook run_once.yml --list-hosts

# 九、环境变量

Ansible 支持通过 environment 关键字临时定义环境变量。适用场景：运行 shell 时需设置 PATH、需加载非标准库路径的库等。

- hosts: localhost
  tasks:
    - shell: echo $PATH
      environment:
        PATH: /usr/local/app/bin:<!--swig￼45-->
ansible-playbook environment.yml -v

# 十、wait_for：等待条件再执行

有些任务需等待状态恢复，如主机重启后需等待端口开启。wait_for 暂停任务直到状态满足要求。

# 等待端口可用
wait_for: port=80 delay=10

# 等待直到锁定文件被删除
wait_for: path=/var/lock/file.lock state=absent

# 十一、YAML 文件的相互调用

# 11.1 include / include_tasks

用 include 或 include_tasks 可在某个 task 中调用其它只含 task 内容的 yaml 文件。

# a.yml
---
- hosts: websrvs
  tasks:
    - name: run a job
      command: wall run a job
    - name: execute b.yml
      include: b.yml
      # include_tasks: b.yml  # 另一种写法
# b.yml
- name: run b job
  command: wall run b job

# 11.2 import_playbook

将多个包含完整内容的 yml 文件由一个 yml 统一调用。

# total_tasks.yml
- import_playbook: task1.yml
- import_playbook: task2.yml
# task1.yml
---
- hosts: websrvs
  tasks:
    - name: run task1 job
      command: wall run task1 job
# task2.yml
---
- hosts: websrvs
  tasks:
    - name: run task2 job
      command: wall run task2 job
ansible-playbook total_tasks.yml

# 小结

本文覆盖了 Playbook 的高级特性：

  • template + Jinja2：动态生成配置，支持 for/if 流程控制与算术运算；
  • 循环：with_items/loop、嵌套子变量、until、with_lines，消除重复 task；
  • when：基于 facts/register/item 的条件测试，含 failed_when；
  • block：条件分组，避免重复写 when；
  • changed_when：控制 changed 状态与结果判断；
  • serial：滚动执行，适合大规模更新与灰度；
  • delegate_to / local_action / run_once / environment / wait_for：精细控制执行目标与时机；
  • include / import_playbook：拆分与复用 YAML。

掌握这些，就能编写出动态、健壮、可复用的复杂剧本。下一篇进入综合实战：用 Playbook 部署 httpd、Docker、Harbor、MySQL。
