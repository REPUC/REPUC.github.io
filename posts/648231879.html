# Linux 系统服务

本篇围绕 Linux 系统服务展开，涵盖系统启动流程、运行级别、Systemd 服务管理、救援模式（忘记密码、数据备份、grub 修复）以及系统优化（yum 源、防火墙、ulimit 资源限制）等运维核心知识点。

# 1. 系统启动流程

# 1.1 CentOS 6

CentOS 6 采用 SysV init 的串行启动方式，开机启动流程可参考相关文档（启动过程为：加电自检 → 加载 BIOS → 加载 MBR 引导 → 加载 init 进程 → 按运行级别启动服务）。

# 1.2 CentOS 7

CentOS 7 采用 systemd 管理启动，开机流程大致为：

按下电源 → 开机自检（BIOS）→ 加载内核 → systemd 初始化 → 启动各服务（并行）→ 显示 login 登录界面

# 2. 启动运行级别

# 2.1 什么是运行级别

运行级别：指操作系统当前正在运行的功能级别。System V init 运行级别与 systemd 目标名称对应关系如下：

运行级别systemd 目标名称作用
0runlevel0.target、poweroff.target关机
1runlevel1.target、rescue.target单用户模式
2runlevel2.target、multi-user.target多用户（无图形）
3runlevel3.target、multi-user.target多用户的文本界面
4runlevel4.target、multi-user.target多用户（自定义）
5runlevel5.target、graphical.target多用户的图形界面
6runlevel6.target、reboot.target重启

# 2.2 调整运行级别

systemd 使用 targets 而不是 runlevels，主要有两个目标：

  • multi-user.target：类似于运行级别 3
  • graphical.target：类似于运行级别 5

常用操作命令：

# 1. 查看系统默认运行级别
[root@oldwang ~]# systemctl get-default

# 2. 设置默认目标
[root@oldwang ~]# systemctl set-default TARGET.target

# 3. Systemd 管理

# 3.1 systemd 的由来

Linux 一直以来都采用 init 进程作为祖先进程，但 init 有两个缺点：

  1. 启动时间长：init 进程是串行启动，只有前一个进程启动完，才会启动下一个进程。
  2. 启动脚本复杂：初始化系统后会加载很多脚本，脚本多而杂，各自处理各自的情况。

各版本启动方式演进：

  • CentOS 5：启动速度慢，串行启动过程，无论进程相互之间有无依赖关系。
  • CentOS 6：启动速度有所改进，有依赖的进程之间依次启动，与之没有依赖关系的则并行同步启动。
  • CentOS 7：所有进程无论有无依赖关系都是并行启动（很多时候进程没有真正启动，只是有一个信号或标记，真正利用时才会真正启动）。

Systemd 即为 system daemon（系统守护进程），为解决上述问题而诞生。systemd 的目标是：为系统的启动和管理提供一套完整的解决方案。

# 3.2 systemd 的优势

  1. 最新系统都采用 systemd 管理：RedHat 7、CentOS 7、Ubuntu 15.04 等。
  2. CentOS 7 支持开机并行启动服务，显著提高开机启动效率。
  3. CentOS 7 关机只关闭正在运行的服务，而 CentOS 6 会全部关闭一次。
  4. CentOS 7 服务的启动与停止不再使用脚本管理，即 /etc/init.d 下不再有脚本。
  5. CentOS 7 使用 systemd 解决原有模式缺陷，比如原有 service 命令不会关闭程序产生的子进程。

# 3.3 systemd 相关命令

服务启停文件位于 /usr/lib/systemd/system/，通过 systemctl 命令对其进行启动、停止、重载等操作。常用命令：

systemctl start crond        # 启动服务
systemctl stop crond         # 停止服务
systemctl restart crond      # 重启服务
systemctl reload crond       # 重载服务
systemctl enable crond       # 设置服务开机运行
systemctl disable crond      # 设置服务开机不运行
systemctl daemon-reload crond  # 创建服务启动文件后需要重载配置
systemctl list-unit-files    # 查看各个级别下服务的启动与禁用
systemctl is-enabled crond.service  # 查看特定服务是否为开机自启动
systemctl is-active crond    # 查看服务是否在运行

# 3.4 systemd 管理 Nginx

第 1 步：编译 Nginx

wget http://nginx.org/download/nginx-1.21.1.tar.gz
tar xf nginx-1.21.1.tar.gz
cd nginx-1.21.1
./configure --prefix=/usr/local/nginx-1.21.1 \
--with-http_ssl_module \
--with-http_stub_status_module
make && make install
ln -s /usr/local/nginx-1.21.1 /usr/local/nginx

第 2 步：常规启动 Nginx 方式

/usr/local/nginx/sbin/nginx             # 启动
/usr/local/nginx/sbin/nginx -s reload   # 重载
/usr/local/nginx/sbin/nginx -s stop     # 停止

第 3 步：使用 systemd 管理 Nginx

单元文件字段说明：

  • Before/After：定义启动顺序。Before=xxx.service 代表本服务在 xxx.service 启动之前启动；After=xxx.service 代表本服务在 xxx.service 启动之后启动。
  • Wants：声明依赖关系，希望某服务启动时本服务也随之启动。

配置文件 /usr/lib/systemd/system/nginx.service：

[Unit]
Description=nginx
After=network-online.target remote-fs.target nss-lookup.target
Wants=network-online.target

[Service]
Type=forking
#Environment="PATH=$PATH:/usr/local/nginx/sbin"
ExecStart=/usr/local/nginx/sbin/nginx
ExecReload=/usr/local/nginx/sbin/nginx -s reload
ExecStop=/usr/local/nginx/sbin/nginx -s stop
PrivateTmp=true

[Install]
WantedBy=multi-user.target

# 4. 救援模式

# 4.1 场景 1：忘记超级管理员密码

以 CentOS 7 为例，使用单用户模式修改系统密码：

  1. 第 1 步：重启 Linux 系统主机，出现引导界面时，按下键盘上的 e 键进入内核编辑界面。
  2. 第 2 步：在 linux16 这行的后面添加 enforcing=0 init=/bin/bash，然后按 Ctrl + X 进入。
  3. 第 3 步：进入系统的单用户模式，依次执行以下命令，然后重启操作系统，使用新密码登录：
# 默认 / 分区只读，重新挂载为读写模式
mount -o rw,remount /

# 非交互式修改密码
echo "123" | passwd --stdin root

# 重新引导系统
exec /sbin/init

# 4.2 场景 2：系统损坏需备份数据

当系统损坏无法登录，但需要把数据复制出来时：

  1. 第 1 步：挂载 ISO 镜像文件，修改 BIOS，调整光盘为第一引导。
  2. 第 2 步：选择 Troubleshooting，继续选择 Rescue a CentOS system 救援模式。
  3. 第 3 步：输入 1，然后执行 chroot /mnt/sysimage，挂载真实系统。
  4. 第 4 步：备份系统中的数据文件至其他磁盘。

# 4.3 场景 3：误删除 grub 文件修复

以 CentOS 7 为例，grub 文件损坏后的修复流程：

  1. 第 1 步：模拟误删除故障：
rm -rf /boot/grub && reboot
  1. 第 2 步：系统无法正常启动（提示 grub 找不到）。
  2. 第 3 步：按上述方式进入救援模式，执行 chroot /mnt/sysimage 挂载真实的操作系统。
  3. 第 4 步：使用 grub2 相关命令修复：
grub2-install /dev/sda                              # 重新添加 MBR 引导
grub2-mkconfig -o /boot/grub2/grub.cfg             # 重新生成配置
ls /boot/grub2/grub.cfg                             # 验证

# 5. 系统优化

# 5.1 调整 yum 源

默认安装系统对外提供的 yum 仓库为国外站点，可以将站点修改为国内站点，加速软件包下载。

配置 base 源（CentOS 7）

[root@oldwang ~]# wget -O /etc/yum.repos.d/CentOS-Base.repo https://mirrors.aliyun.com/repo/Centos-7.repo

配置 epel 源

[root@oldwang ~]# wget -O /etc/yum.repos.d/epel.repo http://mirrors.aliyun.com/repo/epel-7.repo

# 5.2 关闭防火墙

默认情况下建议关闭防火墙，以避免影响后期服务的使用：

  • 云主机：有硬件提供的安全组产品来提供防护。
  • 物理机：一般公司在入口层面都会有硬件防火墙。

关闭 firewalld

[root@oldwang ~]# systemctl stop firewalld
[root@oldwang ~]# systemctl disable firewalld

关闭 SELinux

[root@oldwang ~]# setenforce 0
[root@oldwang ~]# sed -i 's/^SELINUX=/SELINUX=disabled/' /etc/selinux/config

# 5.3 ulimit 资源限制

ulimit 命令可以对系统资源进行控制，常用参数：

  • -u：限制普通用户所能打开的最大进程数目（每个用户）。
  • -n：限制用户能分配到的文件描述符数量。

# 5.3.1 限制进程最大数量

  1. 限制每个用户最大能打开 3 个进程：
[root@oldwang ~]# ulimit -u 3
  1. 登录用户启动多个进程测试：
[root@oldwang ~]# su - oldwang
[oldwang@oldwang ~]$ sleep 1000 &
[1] 10857
[oldwang@oldwang ~]$ sleep 1000 &
[2] 10858
[oldwang@oldwang ~]$ sleep 1000 &
-bash: fork: retry: 资源暂时不可用
-bash: fork: retry: 资源暂时不可用
-bash: fork: retry: 资源暂时不可用

# 5.3.2 限制打开文件数量

  1. 限制进程最多打开文件描述符为 10：
[root@oldwang ~]# ulimit -n 10
  1. 用 Python 程序模拟打开多个文件：
[root@oldwang ~]# cat open_file.py
#!/usr/bin/env python
import time, os
from threading import Thread

print(os.getpid())

def new_file(n):
    with open('%s.file' % n, mode='wt') as f:
        time.sleep(2000)

if __name__ == "__main__":
    count = 1
    while True:
        Thread(target=new_file, args=(count,)).start()
        count += 1
        time.sleep(2)
  1. 等待一段时间，当程序打开文件超过限制，则会提示异常：
Exception in thread Thread-9:
Traceback (most recent call last):
  File "/usr/lib64/python2.7/threading.py", line 812, in __bootstrap_inner
  File "/usr/lib64/python2.7/threading.py", line 765, in run
  File "open_file.py", line 9, in new_file
IOError: [Errno 24] Too many open files: '9.file'

# 5.3.3 调整 ulimit 限制参数

通过 ulimit 方式调整打开文件数量和进程数量都是临时操作，需要进行永久配置。

  • 配置文件：/etc/security/limits.conf
  • 调整模式：
    • soft：软限制，超过则提示。
    • hard：硬限制，超过则停止。

配置文件示例：

# max user processes
* soft nproc 60000
* hard nproc 60000

# open files
* soft nofile 100000
* hard nofile 100000

查看系统文件数量限制日志

[root@oldwang ~]# tail -f /var/log/dmesg
[    7.876830] VFS: file-max limit 200 reached
[   32.910679] VFS: file-max limit 200 reached
[   32.992003] VFS: file-max limit 200 reached
[   33.009073] VFS: file-max limit 200 reached

调整系统级文件数量限制（fs.file-max）

[root@oldwang ~]# echo "fs.file-max = 20000" >> /etc/sysctl.conf
[root@oldwang ~]# sysctl -p
