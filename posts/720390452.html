# Linux 计划任务

本篇主题：Linux 计划任务（crond）。讲解 crond 概念与应用场景、crontab 时间周期与编写范例，并通过时间同步、定时 sync、每日备份文件三个实战场景演示 crond 的使用，同时总结注意事项、备份方法与拒绝特定用户使用的方案。

# 1. 计划任务基本概述

# 1.1 什么是 crond

crond 就是计划任务，类似于生活中的闹钟，定点执行。

# 1.2 为什么需要 crond

crond 主要用来做一些周期性的任务，常见场景：

  • 场景 1：定期备份重要的文件或数据
  • 场景 2：促销活动，准点开启抢购接口，准点关闭抢购接口
  • 场景 3：每分钟检测超时订单，超过 30 分钟未支付的订单进行取消
  • 场景 4：每隔 5 分钟到各个电商平台刷取订单信息，写入自己公司的系统中

# 1.3 计划任务两大类

  • 1. 系统级别的定时任务：临时文件清理、系统信息采集、日志文件切割
  • 2. 用户级别的定时任务：定时备份数据、同步时间、订单超时自动取消、按时间段统计信息等

# 2. 计划任务基本应用

# 2.1 计划任务时间周期

crontab 配置文件记录了时间周期的含义：

[root@jaxxwang ~]# vim /etc/crontab
SHELL=/bin/bash                        # 指定 shell
PATH=/sbin:/bin:/usr/sbin:/usr/bin      # 环境变量
MAILTO=root                          # 邮件收件人
# Example of job definition:
# .---------------- minute (0 - 59)    # 分钟
# |  .------------- hour  (0 - 23)      # 小时
# |  |  .---------- day of month (1 - 31) # 日期
# |  |  |  .------- month (1 - 12) OR jan,feb,mar,apr # 月份
# |  |  |  |  .---- day of week (0 - 6) (Sunday=0 or 7) OR sun,mon,tue,wed,thu,fri,sat # 星期
# |  |  |  |  |
# *  *  *  *  *  command to be executed
# 分 时 日 月 周 要执行的命令

# 2.2 计划任务编写范例

已编写好的计划任务示例：

33 62 * * * ls     # 该示例中时间字段取值超出合法范围，仅作格式演示

常见编写范例：

30 2 1 * * ls     # 每月 1 号 2 点 30 分执行
30 2 14 2 * ls    # 每年 2 月 14 号 2 点 30 分执行
30 2 * 7 ls       # 每周日 2 点 30 分执行
33 2 * 6 5 ls     # 每周五 6 点 33 分执行
30 2 14 27 * ls   # 每月 27 号 14 点 30 分执行
*/10 2 * * * ls   # 每天 2 点开始，每隔 10 分钟执行一次
* * * * * ls      # 每分钟都执行
30 2 14 2 * ls    # 每年 2 月 14 号 2 点 30 分执行
30 2 * 1,5,8 * ls # 每月 1、5、8 号 2 点 30 分执行
00 02 1-8 * * ls  # 每月 1 到 8 号 2 点整执行
* 21 * * * ls     # 每天 21 点的每一分钟都执行
45 4 1,10,22 * * ls # 每月 1、10、22 号 4 点 45 分执行
45 4 1-10 * * ls  # 每月 1 到 10 号 4 点 45 分执行
3,15 8-11 */2 * * ls # 每 2 天的 8 到 11 点，8 点 03 分和 15 分执行
00 23-7/1 * * * ls # 每天 23 点到次日 7 点，每隔 1 小时执行
15 21 * * 1-5 ls # 周一到周五 21 点 15 分执行

# 2.3 使用 crond 实现计划任务

crond 命令及相关选项：

参数含义
-e编辑定时任务
-l查看定时任务
-r删除定时任务
-u指定其他用户

# 2.3.1 场景 1 - 定时时间同步

使用 root 用户每 5 分钟执行一次时间同步。

# 1. 先测试时间同步命令
[root@jaxxwang ~]# ntpdate time.windows.com &>/dev/null

# 2. 编写计划任务
[root@jaxxwang ~]# crontab -e -u root
[root@jaxxwang ~]# crontab -l -u root
*/5 * * * * ntpdate time.windows.com &>/dev/null

# 2.3.2 场景 2 - 每半小时 sync

每天的下午 3、5 点，每隔半小时执行一次 sync 命令。

[root@jaxxwang ~]# crontab -l
*/30 15,17 * * * sync &>/dev/null

# 2.3.3 场景 3 - 每天备份文件

每天凌晨 3 点做一次备份，备份 /etc/ 目录到 /backup 下面。

    1. 将备份命令写入一个脚本中
    1. 每天备份文件名要求格式：YYYY-MM-DD_hostname_etc.tar.gz
    1. 在执行计划任务时，不要输出任务信息
    1. 存放备份内容的目录要求只保留三天的数据
# 1. 准备目录，测试备份命令与清理命令
[root@jaxxwang ~]# mkdir /backup
[root@jaxxwang ~]# tar zcf $(date +%F) $(hostname)_etc.tar.gz /etc
[root@jaxxwang ~]# find /backup -name "*.tar.gz" -mtime +3 -exec rm -f {} \;

# 2. 编写备份脚本
[root@jaxxwang ~]# vim /opt/backup.sh
mkdir /backup
tar zcf $(date +%F) $(hostname)_etc.tar.gz /etc
find /backup -name "*.tar.gz" -mtime +3 -exec rm -f {} \;

# 3. 编写计划任务
[root@jaxxwang ~]# crontab -l
00 3 * * * bash /opt/backup.sh &>/dev/null

# 2.4 计划任务注意事项

    1. 给定时任务添加注释
    1. 将需要定期执行的任务写入 shell 脚本中，避免直接使用命令出现无法执行的情况
    1. 定时任务的结尾一定要有 &>/dev/null，或者将结果追加重定向到 >>/tmp/date.log 文件
    1. 注意有些命令是无法成功执行的，需要测试，如 echo "123" >>/tmp/test.log &>/dev/null
    1. 如果一定要直接使用命令，命令必须使用绝对路径

# 2.5 计划任务如何备份

备份计划任务：

    1. 所有计划任务编写完毕后都存储至 /var/spool/cron/{username} 中
    1. 只需要通过 cp、scp 的方式进行备份即可

如果计划任务没有备份，还不小心执行了 crontab -r：

    1. 通过查找 /var/log/cron 中执行的记录，然后过滤相关的内容行
    1. 通过执行任务的时间推算执行的频率，据此恢复计划任务

# 2.6 拒绝特定用户使用

crond 拒绝某个用户使用的方法：

  1. 使用 root 将需要拒绝的用户加入 /etc/cron.deny
[root@jaxxwang ~]# echo "jaxxwang" >> /etc/cron.deny
  1. 登录该普通用户，测试是否能编写定时任务（将无法使用 crontab）：
[oldboy@jaxxwang ~]$ crontab -e
You (jaxxwang) are not allowed to use this program (crontab)
See crontab(1) for more information
