# Linux 磁盘管理

本篇主题：Linux 磁盘管理。从磁盘物理结构讲起，覆盖磁盘接口与设备命名、分区管理（fdisk/gdisk/mkfs）、挂载管理（mount/umount/fstab）、SWAP 虚拟磁盘、文件系统原理与修复，再到 LVM 逻辑卷与 RAID 磁盘阵列的完整实践，是一块完整的磁盘运维知识体系。

# 1. 磁盘概述

# 1.1 什么是磁盘

硬盘通过高速运转的圆盘存储数据：圆盘表面附着一圈金属颗粒，每个颗粒有各自的磁化程度，用于存储 0 和 1。

数据写入时，磁头通电产生磁场，数据在磁场作用下转变成电流，使金属颗粒磁化，从而把信息记录在圆盘上。海量颗粒组成的信息，就是存在硬盘里的数据。

磁盘、软盘、硬盘：软盘为早期可移动介质，硬盘为当前主流存储设备，二者都属于块存储设备。

# 1.2 磁盘物理结构

# 1.2.1 什么是盘片

硬盘一般有一个或多个盘片，每个盘片有两面：第一个盘片的正面为 0 面，反面为 1 面，依次类推。

# 1.2.2 什么是磁道

每个盘片的盘面在出厂时被划分出多个同心圆环，数据存储在这些同心圆环上，这样的圆环称为磁道（Track）。每个盘面可划分多个磁道，但肉眼不可见。

# 1.2.3 什么是扇区

硬盘出厂时会对磁盘进行一次低格（低级格式化），即把每个磁道划分为若干个弧段，每个弧段就是一个扇区（sector）。扇区是硬盘存储的物理单位，目前每个扇区可存储 512 字节，这已成为业界约定。

# 1.2.4 什么是柱面

柱面是抽象出来的一个逻辑概念：处于同一垂直区域的磁道称为柱面，即各盘面相同位置磁道的集合。数据存储到相同半径磁道上的同一扇区，可以实现并行读取，主要减少磁头寻道时间。

# 1.2.5 什么是磁头

磁头负责读取磁盘磁道上的金属块，主要负责数据的读取或写入。

# 3. 分区管理

# 3.1 为什么要分区

  • 分区便于数据分门别类地存储，分区有 MBR、GPT 两种方式。
  • 分区表：记录分区的编号、每个编号从哪个扇区开始、到哪个扇区结束。
  • MBR（主引导记录）：用来找到磁盘上的操作系统并引导启动（位于 0 磁道、1 扇区，共 512 字节）。
    • 446 字节：boot loader
    • 64 字节：存储分区表，每 16 字节表示一个分区，最多四个主分区（主分区 + 扩展分区）
    • 2 字节：结束位
  • GPT：新型分区表，支持分配 128 个主分区。

注意：MBR 与 GPT 之间不能互转，转换会导致数据丢失。

MBR 最多四个主分区，可通过扩展分区方案划分多个分区（如 3 个主分区 + 1 个扩展分区，扩展分区下再划分多个逻辑分区）。

# 3.2 fdisk 分区工具

  • fdisk 仅支持分配小于 2TB 的磁盘。
  • 查看当前设备：fdisk -l
  • 对设备分区：fdisk /dev/sdb

分区交互命令：

  • m：显示帮助
  • n：创建新分区
  • d：删除分区
  • p：查看分区
  • w：保存分区
  • q：退出

分区案例：

  • 案例 1：分配 4 个分区（4P）
  • 案例 2：分配 5 个分区（1P + 1E + 4L）
  • 案例 3：分配 6 个分区（3P + 1E + 3L）

# 3.3 gdisk 分区工具

  • gdisk 支持分配大于 2TB 的磁盘。
  • 查看当前设备：gdisk -l device
  • 对设备分区：gdisk /dev/sdb

分区交互命令：

  • ?：显示帮助
  • n：创建新分区
  • p：打印分区
  • w：保存分区
  • q：退出

分区案例：

  • 案例 1：分配 4 个主分区（4P）
  • 案例 2：分配 5 个主分区（5P）
  • 案例 3：分配 6 个主分区（6P）

# 3.4 mkfs 格式化系统

mkfs 命令用于格式化硬盘，类似于把房子装修成 3 室一厅还是 2 室一厅。

  • -b：设定数据区块占用空间大小，支持 1024、2048、4096 bytes 每个块
  • -t：指定文件系统类型，可以是 ext4、xfs

提示：

  1. 分区工具可以针对整块磁盘或单个分区进行格式化操作。
  2. 一般情况下建议不要直接格式化整块磁盘，要先分区再格式化，头部有预留空间。
# 1. 使用 mkfs 命令，格式化整个硬盘
[root@oldwang ~]# mkfs.ext4 /dev/sdb

# 2. 使用 mkfs 命令，格式化磁盘的某个分区
[root@oldwang ~]# mkfs.xfs /dev/sdb1

# 3. 使用 mkfs 命令指定一个数据块的大小
[root@dns-master ~]# mkfs.xfs -b size=1024 /dev/sdb2

# 4. 挂载管理

需要使用磁盘空间时，先准备一个目录作为挂载点，再用 mount 命令将该设备与目录关联。

# 4.1 临时挂载 mount

通过 mount 挂载后重启将会失效，称为临时生效。

  • -t：指定文件系统挂载分区
  • -a：检查并挂载 /etc/fstab 配置文件中未挂载的设备
  • -o：指定挂载参数，如 ro、rw
# 1. 挂载磁盘设备
[root@oldwang ~]# mkdir /db1
[root@oldwang ~]# mount -t xfs /dev/sdb1 /db1

# 2. 挂载磁盘设备，设置参数为仅可读
[root@oldwang ~]# mkdir /db2
[root@dns-master ~]# mount -t xfs -o ro /dev/sdb2 /db2
[root@dns-master ~]# touch /db2/new_file
touch: cannot touch '/db2/new_file': Read-only file system

# 4.2 umount 卸载

不想使用时，使用 umount [device|directory] 进行临时卸载。

  • -l：强制卸载
# 1. 卸载入口目录示例
[root@oldwang ~]# umount /db1

# 2. 卸载设备示例
[root@oldwang ~]# umount /dev/sdb1

# 3. 如碰到无法正常卸载的情况处理
[root@jaxxwang db1]# umount /db1
umount: /db1: device is busy.
(In some cases useful info about processes that use
the device is found by lsof(8) or fuser(1))
# 方法一：使用 lsof 或 fuser 查找占用进程；方法二：强制卸载
[root@student db1]# umount -l /db1

# 4.3 永久挂载 fstab

需要实现永久挂载时，将挂载相关信息写入 /etc/fstab 配置文件。

# 4.3.1 永久挂载配置编写

  • 配置文件规范：设备名称 | 挂载的入口目录 | 文件系统类型 | 挂载参数 | 是否备份 | 是否检查

操作步骤：

  1. 获取设备名称，或获取设备 UUID
  2. 手动临时挂载测试
  3. 写入 /etc/fstab 配置文件
  4. 使用 mount -a 检查是否存在错误
# 1. 获取设备名称，或设备的 UUID
[root@oldwang ~]# blkid | grep "sdb1"
/dev/sdb1: UUID="e271b5b2-b1ba-4b18-bde5-66e394fb02d9" TYPE="xfs"

# 2. 手动挂载测试
[root@oldwang ~]# mount UUID="e271b5b2-b1ba-4b18-bde5-66e394fb682d9" /db1

# 3. 写入 /etc/fstab 测试
# 手动编写
[root@oldwang ~]# tail -1 /etc/fstab
UUID=e271b5b2-b1ba-4b18-bde5-66e394fb02d9 /db1 xfs defaults 0 0
# 启动实现
[root@oldwang ~]# blkid | grep /dev/sda1 | awk -F '[: ]+' '{print $2}' | \
sed -r 's#(.*)#\1 /db1 xfs defaults 0 0#g' >> /etc/fstab

# 4. 加载 /etc/fstab 配置文件，同时检测是否存在语法错误
[root@oldwang ~]# mount -a

# 4.3.2 配置文件 /etc/fstab

/etc/fstab 配置文件格式说明：

  • 第一列：指定需要挂载的设备
    • 设备名称：/dev/sdb1
    • 设备 ID：UUID
  • 第二列：挂载的入口目录
  • 第三列：文件系统类型（xfs、ext4 等）
  • 第四列：挂载参数
    • async/sync：使用同步或异步方式存储数据，默认 async
    • user/nouser：是否允许普通用户使用 mount 命令挂载，默认 nouser
    • exec/noexec：是否允许可执行文件执行，默认 exec
    • suid/nosuid：是否允许存在 suid 属性的文件，默认 suid
    • auto/noauto：执行 mount -a 命令时，此文件系统是否被主动挂载，默认 auto
    • rw/ro：是否以只读或读写模式挂载，默认 rw
    • defaults：包含 rw、suid、dev、exec、auto、nouser、async 等参数
  • 第五列：是否要备份磁盘
    • 0：不备份
    • 1：每天进行备份操作
    • 2：每周进行备份操作
  • 第六列：开机是否检验扇区
    • 0：不要检验磁盘是否有坏扇区
    • 1：检验
    • 2：校验（当 1 级别检验完成之后进行 2 级别检验）

# 5. 虚拟磁盘 SWAP

# 5.1 什么是 SWAP

Swap 分区：当系统物理内存不够时，将硬盘中的一部分空间供当前运行的程序使用。

# 5.2 为什么需要 SWAP

当物理内存不够时，系统会随机 kill 占用内存的进程，从而产生 OOM（Out of Memory），临时使用 swap 可以解决。

案例：模拟服务器 OOM。

[root@oldwang ~]# dd if=/dev/zero of=/dev/null bs=800M
# 另开终端查看日志
[root@oldwang ~]# tail -f /var/log/messages
Out of memory: Kill process 2227 (dd) score 778 or sacrifice child
Killed process 2227 (dd) total-vm:906724kB, anon-rss:798820kB, file-rss:0kB

# 5.3 SWAP 基本应用

创建分区并格式化为 swap 分区：

# 1. 创建分区，并格式化为 swap 分区
[root@oldwang ~]# fdisk /dev/sdb
# fdisk 中创建分区后输入 t，修改分区类型为 swap
[root@oldwang ~]# mkswap /dev/sdb1

# 2. 查看当前 swap 分区大小
[root@oldwang ~]# free -m
total      used      free    shared buff/cache available
Mem:           1980        1475          80          10         424         242
Swap:          2047           4        2043

# 5.3.1 扩展 swap 分区

使用 swapon 命令扩展 swap 分区：

  • swapon device：将某个磁盘空间添加到 swap 分区中
  • swapon -a：激活所有 swap 分区
[root@oldwang ~]# swapon /dev/sdb1
[root@oldwang ~]# free -m
total      used      free    shared buff/cache available
Mem:           1980        1475          80          10         424         242
Swap:          3047           4        2043

# 5.3.2 缩小 swap 分区

使用 swapoff 命令缩小 swap 分区：

  • swapoff device：关闭某个磁盘的 swap 分区
  • swapoff -a：关闭所有 swap 分区
[root@oldwang ~]# swapoff /dev/sdb1
[root@oldwang ~]# free -m
total      used      free    shared buff/cache available
Mem:           1980        1475          80          10         424         242
Swap:          2047           4        2043

# 6. 文件系统

# 6.1 文件系统的作用

用户无法直接与硬件交互，如果需要申请 1GB 磁盘空间怎么办？为简化磁盘使用过程，操作系统提供了辅助系统 FS（文件系统）。

# 6.2 文件系统的类型

  • Windows：FAT32、NTFS
  • Linux：EXT2、EXT3、EXT4、XFS、VFAT、NTFS-3g

# 6.3 文件系统结构

磁盘被划分为两大存储区域：一类存储元数据 inode，一类存储真实数据 data block。

  • inode 划分了很多 inode block，每个 block 大小为 128B
  • data 划分了很多 data block，每个 block 大小为 4K
  • 磁盘存储文件时，至少占用一个 inode 与一个 block

针对 1T 磁盘格式化后被划分成几千万个 4K block，如何快速定位哪个可用？全盘扫描耗时过长，解决办法是使用位图：

  • inode bitmap：inode 位图
  • block bitmap：block 位图

文件删除原理：

  • 首先删除目录下的文件名称，然后将 inode、block 的 bitmap 状态修改为可用；但文件并没有真正被删除，还有恢复的可能性；一旦有新数据写入将其覆盖，数据才算真正删除。

文件移动原理：

  • 仅将文件名称从一个目录移动到另一个目录下面，并不会修改其 inode 和 block。

# 6.4 文件系统故障修复

Linux 为增加性能，通常先将数据写入内存，再刷新至磁盘。若服务器突然断电或其他未知原因，再次启动后会造成文件系统错误。

# 1. 添加磁盘，给磁盘分配空间
[root@oldwang ~]# fdisk /dev/sdc   # 分一个区
[root@oldwang ~]# mkfs.xfs /dev/sdc1
[root@oldwang ~]# mount /dev/sdc1 /mnt
[root@oldwang ~]# echo "Hello" > /mnt/new.txt

# 2. 使用 dd 模拟磁盘断电损坏，然后取消挂载，会发现无法正常重新挂载
[root@oldwang ~]# dd if=/dev/zero of=/dev/sdc bs=366M count=1
[root@oldwang ~]# umount /mnt
[root@oldwang ~]# mount /dev/sdc1 /mnt   # 报错，无法正常挂载

# 3. 使用 xfs_repair 修复文件系统
[root@oldwang ~]# xfs_repair /dev/sdc1

# 4. 如出现修复失败，可采用强制修复，但可能会造成部分数据丢失
[root@oldwang ~]# xfs_repair -L /dev/sdc1

# 7. 逻辑卷 LVM

# 7.1 为何要用 LVM

  • 刚安装 Linux 时往往不能确定每个分区使用的空间大小，只能凭经验分配，不科学。
  • 分区设置过大，浪费磁盘空间；分区设置过小，空间又不够。
  • 若希望分配的空间过大或过小都能动态调整，则需要使用 LVM。

# 7.2 什么是 LVM

LVM（Logical Volume Manager，逻辑卷管理） 是对磁盘分区进行管理的一种机制。

LVM 优点：

  • 可以创建和管理逻辑卷，而不是直接使用物理硬盘
  • 可以弹性地管理逻辑卷的扩大、缩小，操作简单，且不损坏已存储的数据
  • 可以随意将新的硬盘添加到 LVM，直接扩展已经存在的逻辑卷

LVM 缺点：

  • 如果有一个磁盘损坏，整个 LVM 都坏了，LVM 只有动态扩展作用
  • 解决办法：RAID + LVM = 既有冗余又有动态扩展

# 7.3 LVM 相关术语

  • 物理卷（PV）：将常规磁盘通过 pvcreate 命令初始化，形成物理卷。（比喻：面粉）
  • 卷组（VG）：把多个物理卷组成一个逻辑整体，卷组大小就是多个盘之和。（比喻：大面团）
  • 逻辑卷（LV）：从卷组中划分所需空间，用户仅需对其格式化然后即可挂载使用。（比喻：切成馒头）
  • 基本单元（PE）：分配逻辑大小的最小单元，默认 4MB。假设分配 100MB 空间，则需要创建 25 个 PE。

# 7.4 LVM 配置实践

# 7.4.1 环境与思路

  1. 准备三块物理磁盘，建议在虚拟机关闭状态添加，以便更好地实验
  2. 创建物理卷，将普通磁盘转换为物理卷
  3. 创建卷组，将物理卷加入到卷组中
  4. 在卷组中划分逻辑卷，然后挂载使用

# 7.4.2 创建物理卷

# 1. 将磁盘转换为物理卷，并加入 pv
[root@linux-node1 ~]# pvcreate /dev/sdb
Physical volume "/dev/sdb" successfully created.

# 2. 检查 pv 创建情况
[root@linux-node1 ~]# pvs
PV     VG   Fmt Attr PSize  PFree
/dev/sdb         lvm2 ---    1.00g 1.00g

# 7.4.3 创建卷组

# 1. 创建名为 datavg 的卷组，然后将物理卷加入进卷组
[root@linux-node1 ~]# vgcreate datavg /dev/sdb
Volume group "datavg" successfully created

# 2. 检查卷组（发现存在一个 PV 卷）
[root@linux-node1 ~]# vgs
VG      #PV #LV #SN Attr   VSize    VFree
datavg   1   0   0 WZ--n- 1626.96m 1626.96m

# 7.4.4 创建逻辑卷

# 1. 分配 datavg 逻辑卷，-n 指定逻辑卷名称，-L 指定逻辑卷大小
[root@linux-node1 ~]# lvcreate -L 100M -n lv1 datavg
Logical volume "lv1" created.

# 2. 查看逻辑卷
[root@linux-node1 ~]# lvscan
ACTIVE            "/dev/datavg/lv1" [100.00 MiB] inherit

# 7.4.5 挂载使用

# 1. 格式化逻辑卷
[root@linux-node1 ~]# mkfs.xfs /dev/datavg/lv1

# 2. 创建目录并挂载
[root@linux-node1 ~]# mkdir /lv1
[root@linux-node1 ~]# mount /dev/datavg/lv1 /lv1/
[root@linux-node1 ~]# df -h
Filesystem                  Size Used Avail Use% Mounted on
/dev/mapper/datavg-lv1 97M 5.2M 92M 6% /lv1

# 7.5 LVM 卷组管理

# 7.5.1 扩大卷组

# 1. 准备新的磁盘加入至 pv，然后检查卷组当前的大小
[root@jaxxwang ~]# pvcreate /dev/sdc
[root@oldwang ~]# vgs
VG      #PV #LV #SN Attr   VSize    VFree
datavg  1   1   0 WZ--n- 1020.00m 920.00m

# 2. 使用 vgextend 扩展卷组
[root@jaxxwang ~]# vgextend datavg /dev/sdc
Volume group "datavg" successfully extended

# 3. 再次检查，发现卷组已经扩大
[root@oldwang ~]# vgs
VG      #PV #LV #SN Attr   VSize    VFree
datavg  2   1   0 WZ--n-   1.99g 1.89g

# 7.5.2 缩减卷组

  • 假设想移除 /dev/sdb 磁盘，建议先将 sdb 磁盘数据迁移到 sdc 磁盘，然后再移除。
  • 注意：同一卷组的磁盘才可以进行在线迁移。
# 1. 检查当前逻辑卷中 PV 使用情况
[root@jaxxwang ~]# pvs
PV     VG   Fmt Attr PSize  PFree
/dev/sdb vg1 lvm2 a -- 2.00g 1.76g
/dev/sdc vg1 lvm2 a -- 2.00g 2.00g

# 2. pvmove 在线数据迁移，将 sdb 的数据迁移至 sdc
[root@jaxxwang ~]# pvmove /dev/sdb
/dev/sdb: Moved: 100.00%

# 3. 检查是否将 sdb 数据迁移至 sdc
[root@jaxxwang ~]# pvs
PV     VG   Fmt Attr PSize  PFree
/dev/sdb vg1 lvm2 a -- 2.00g 2.00g
/dev/sdc vg1 lvm2 a -- 2.00g 1.76g

# 4. 从卷组中移除 sdb 磁盘
[root@jaxxwang ~]# vgreduce datavg /dev/sdb
Removed "/dev/sdb" from volume group "datavg"

# 7.6 LVM 逻辑卷管理

# 7.6.1 扩展逻辑卷

  • 扩展逻辑卷取决于 VG 卷中是否还有剩余的容量。
  • 注意：扩展逻辑卷不能超过卷组 VG 的总大小。
# 先查看卷组剩余空间
[root@jaxxwang ~]# vgs
VG      #PV #LV #SN Attr   VSize    VFree
datavg  1   1   0 WZ--n- 1020.00m 920.00m

# 1. 扩展 lv 逻辑卷，增加 800M 分配给逻辑卷
[root@jaxxwang ~]# lvextend -L +800M /dev/datavg/lv1
# 也可以使用百分比，使用卷组中所有剩余空间
[root@jaxxwang ~]# lvextend -L +5%FREE /dev/datavg/lv1

# 2. 扩展逻辑卷后需要更新文件系统
[root@jaxxwang ~]# xfs_growfs /dev/datavg/lv1   # xfs 文件系统
[root@jaxxwang ~]# resize2fs /dev/datavg/lv1   # ext 文件系统

# 7.6.2 缩小逻辑卷

# 1. 卸载挂载点
[root@oldwang ~]# umount /lv1

# 2. 使用 lvreduce 调整 lv 大小为 1G
[root@oldwang ~]# lvreduce -L 1G /dev/datavg/lv1

# 3. 重新挂载分区
[root@oldwang ~]# mount -t xfs /dev/datavg/lv1 /lv1

# 7.6.3 删除逻辑卷

# 1. 先卸载挂载点，然后移除逻辑卷
[root@oldwang ~]# umount /dev/datavg/lv1
[root@oldwang ~]# lvremove /dev/datavg/lv1

# 2. 删除卷组
[root@oldwang ~]# vgremove datavg

# 3. 删除 pv
[root@oldwang ~]# pvremove /dev/sdb
[root@oldwang ~]# pvremove /dev/sdc

# 8. 磁盘阵列 RAID

# 8.1 什么是 RAID

RAID 简称磁盘阵列。阵列如同古代打仗排兵布阵，目的在于提高士兵整体作战能力，而不是某个士兵的战斗力。回到磁盘中，将多块盘组合排列，提高磁盘整体的读写能力和冗余能力，通常称为磁盘阵列。

# 8.2 为什么需要 RAID

  1. 提升读写能力：在 RAID 中可以让很多磁盘同时传输数据，多块磁盘在逻辑上感觉是一个磁盘，使用 RAID 可以达到单个磁盘的几倍、几十倍甚至上百倍的速率。
  2. 保证数据安全：硬盘非常脆弱，经常会坏掉，RAID 将多个硬盘组合在一起，就算坏掉一块盘，也不影响服务器对外提供服务，保证磁盘高可用。

RAID 可以预防数据丢失，但并不能百分百保证数据不丢，在使用 RAID 的同时还需要备份数据。

# 8.3 实现 RAID 的几种模式

# 8.3.1 RAID0

RAID0 条带卷，最少两块盘。读写性能好，但没有容错机制，坏一块磁盘数据全丢。

  • 磁盘空间使用率：100%，成本低
  • 读性能：N × 单块磁盘的读性能
  • 写性能：N × 单块磁盘的写性能
  • 冗余：无，任何一块磁盘损坏都将导致数据不可用
  • 应用场景：无状态服务（web）

# 8.3.2 RAID1

RAID1 镜像卷，写入性能一般、读取性能快、有容错机制，但磁盘有 50% 浪费。

  • 磁盘空间使用率：50%，成本较高
  • 读性能：N × 单块磁盘的读性能
  • 写性能：1 × 单块磁盘的写性能
  • 冗余：在这一对镜像盘中有一块磁盘可以使用，就无影响
  • 应用场景：系统盘

# 8.3.3 RAID5

RAID5 校验卷，至少 3 块相同大小的盘，且只允许坏一块盘，有效空间为 N-1，读写速度快。坏掉一块盘，读的性能会下降。

  • 磁盘空间利用率：(N-1)/N，即只浪费一块磁盘用于奇偶校验
  • 读性能：(N-1) × 单块磁盘的读性能，接近 RAID0 的读性能
  • 写性能：(N-1)/N × 单块磁盘的写性能，写入数据需要做校验值，性能会下降
  • 冗余：只允许一块磁盘损坏
  • 应用场景：常规选择（all）

# 8.3.4 RAID10

RAID10：先做 RAID1，再做 RAID0。

  • 磁盘空间利用率：50%
  • 读性能：快
  • 写性能：快
  • 冗余：只要一对镜像盘中有一块磁盘可以使用就没问题
  • 应用场景：数据库（db）

# 8.4 实现 RAID 的方式

  • 8.4.1 硬 RAID：使用硬件阵列卡，在安装操作系统之前进入 BIOS 配置（硬 RAID 模拟器）。
  • 8.4.2 软 RAID：通过操作系统软件实现，性能远不如硬 RAID，仅测试效果。

# 8.5 软 RAID 配置实战

# 8.5.1 RAID 环境准备

由于使用操作系统模拟的软 RAID，需要在虚拟机上添加多块硬盘来完成实验。创建软 RAID 的命令为 mdadm，如果没有使用 yum install mdadm 安装即可。

mdadm 磁盘阵列命令选项：

创建模式：

  • -C：创建阵列
  • -l：指定级别
  • -n：指定设备数量
  • -v：指定设备名称
  • -x：指定备用磁盘

管理模式：

  • --add：添加磁盘
  • --remove：移除磁盘
  • --fail：模拟磁盘故障

# 8.5.2 RAID0 实战

创建 RAID0 实验环境：RAID0 使用 sdb、sdc，无热备盘。

# 1. 创建 raid0
[root@oldwang ~]# mdadm -C -v /dev/md0 -l 0 -n 2 /dev/sdb /dev/sdc

# 2. 查看阵列信息
[root@oldwang ~]# mdadm -Ds
[root@oldwang ~]# mdadm -D /dev/md0

# 3. 格式化磁盘并分区挂载
[root@oldwang ~]# mkfs.xfs /dev/md0
[root@oldwang ~]# mkdir /raid0
[root@oldwang ~]# mount /dev/md0 /raid0/
[root@oldwang ~]# df -h

# 8.5.3 RAID1 实战

实验思路：创建 RAID1 并添加 1 个热备盘；模拟磁盘故障，看备用盘是否会自动顶替故障盘；从 RAID1 中移出故障盘。

创建 RAID1 实验环境：RAID1 使用 sdd、sde，热备盘为 sdf。

# 1. 准备 sdd、sde 两块盘，创建阵列为 RAID1，准备 sdf 为备用盘
[root@oldwang ~]# mdadm -C -v /dev/md1 -l 1 -n 2 /dev/sdd /dev/sde -x1 /dev/sdf

# 2. 格式化磁盘并分区挂载
[root@oldwang ~]# mkfs.xfs -f /dev/md1
[root@oldwang ~]# mkdir /mnt/raid1/
[root@oldwang ~]# mount /dev/md1 /mnt/raid1/

# 3. 使用 --fail 模拟 RAID1 中数据盘 /dev/sde 出现故障，观察 /dev/sdf 备用盘能否自动顶替故障盘
[root@oldwang ~]# mdadm /dev/md1 --fail /dev/sde

# 4. 检查当前 raid 状态
[root@oldwang ~]# mdadm -D /dev/md1
Number Major Minor  RaidDevice State
   0       8       16     0      active sync /dev/sdd
   1       8       32     1      spare rebuilding /dev/sdf   # 正在同步数据
   2       8       112    2      faulty /dev/sde            # 故障

# 5. 移除损坏的磁盘
[root@oldwang ~]# mdadm /dev/md1 -r /dev/sde

# 8.5.4 RAID5 实战

实验思路：使用三块盘创建 RAID5，用 -x 添加热备盘；模拟损坏一块磁盘，查看备用盘是否能顶上（此时是三块磁盘）；再模拟一块磁盘损坏，检查数据是否损坏（此时是两块磁盘）。

创建 RAID5 实验环境：RAID5 使用 sdg、sdh、sdi，热备盘为 sdj。

# 1. 创建 raid5，也可以在最后 -x 添加备用盘
[root@oldwang ~]# mdadm -C -v /dev/md5 -l 5 -n 3 /dev/sdg /dev/sdh /dev/sdi -x1 /dev/sdj

# 2. 格式化磁盘并分区挂载
[root@oldwang ~]# mkfs.xfs -f /dev/md5
[root@oldwang ~]# mkdir /mnt/raid5
[root@oldwang ~]# mount /dev/md5 /raid5/
[root@oldwang ~]# echo "Raid" > /raid5/file
[root@oldwang ~]# mdadm -D /dev/md5

# 3. 模拟一块磁盘损坏，查看 /dev/sdj 备用磁盘是否会顶上
[root@oldwang ~]# mdadm /dev/md5 --fail /dev/sdg
[root@oldwang ~]# mdadm -D /dev/md5

# 4. 将故障的 /dev/sdg 盘剔除
[root@oldwang ~]# mdadm /dev/md5 -r /dev/sdg

# 5. 再次模拟一块磁盘损坏，检查数据是否丢失
[root@oldwang ~]# mdadm /dev/md5 --fail /dev/sdg
[root@oldwang ~]# mdadm -D /dev/md5
