# Ansible 安装、配置与主机清单

本文介绍 Ansible 的安装方法、配置文件体系与主机清单（inventory）的编写。这三者是使用 Ansible 之前必须掌握的基础：装好 Ansible、读懂配置、写好主机清单，后续的命令与 Playbook 才能正确找到目标主机。

# 一、Ansible 安装

Ansible 的安装方式有多种，官方文档：https://docs.ansible.com/ansible/latest/installation_guide/intro_installation.html

下载源码：https://releases.ansible.com/ansible/
Pip 包：https://pypi.org/project/ansible/

# 1.1 Yum/Apt 源安装

CentOS（EPEL 源的 rpm 包）：

[root@centos7 ~] yum install ansible -y
[root@centos7 ~] ansible --version

Ubuntu：

[root@ubuntu ~] apt -y install ansible

Ubuntu 18.04 安装最新版 Ansible（通过官方 PPA）：

apt update
apt install software-properties-common
apt-add-repository --yes --update ppa:ansible/ansible
apt install ansible
ansible --version

说明：CentOS 需先配置好 EPEL 源。yum repolist 可查看源，yum info ansible / apt show ansible 可查看包信息。

# 1.2 编译安装

yum -y install python-jinja2 PyYAML python-paramiko python-babel python-crypto

wget https://releases.ansible.com/ansible/ansible-<版本>.tar.gz
tar xf ansible-<版本>.tar.gz && cd ansible-<版本>

python setup.py build
python setup.py install

mkdir /etc/ansible
cp -r examples/* /etc/ansible

# 1.3 Git 方式

git clone git://github.com/ansible/ansible.git --recursive
cd ./ansible
source ./hacking/env-setup

# 1.4 Pip 安装

yum install python-pip
pip install --upgrade pip
pip install ansible --upgrade
ansible --version

# 1.5 验证安装

[root@ansible ~] ansible --version

输出包含版本号、配置文件路径、模块搜索路径、Python 模块位置、可执行程序位置、Python 版本等。注意 config file 一项显示的正是当前生效的配置文件路径。

# 二、Ansible 相关文件

重要认知：Ansible 不是服务，没有对应的 service 文件，无需长期运行，只在需要时运行其二进制文件即可。安装完成即可直接使用。

核心文件有三个：

  1. /etc/ansible/ansible.cfg：主配置文件，配置 Ansible 工作特性；
  2. /etc/ansible/hosts：主机清单；
  3. /etc/ansible/roles：存放角色的目录。

# 三、Ansible 主配置文件

# 3.1 配置文件的加载优先级

Ansible 的配置文件可以放在多个位置，优先级从高到低如下：

  1. ANSIBLE_CONFIG 环境变量（注意：此项用 ansible --version 看不到，但可以生效）；
  2. ./ansible.cfg（当前目录下）；
  3. ~/.ansible.cfg（当前用户家目录）；
  4. /etc/ansible/ansible.cfg（系统默认配置文件）。

因此，当前目录下的 ansible.cfg 优先级高于系统默认。建议为每个项目在项目目录下创建独有的 ansible.cfg，避免不同项目互相干扰。

# 自定义默认配置文件路径
export ANSIBLE_CONFIG=/opt/ansible.cfg

# 将默认配置文件拷贝至当前目录，使其优先生效
cp /etc/ansible/ansible.cfg .

# 验证：ansible --version 中 config file 应显示为当前目录的 ansible.cfg
ansible --version

# 3.2 默认配置项说明

/etc/ansible/ansible.cfg 大部分内容无需修改，常用配置如下（带注释的为默认值，按需取消注释启用）：

[defaults]
# inventory     = /etc/ansible/hosts    # 主机列表配置文件
# library = /usr/share/my_modules      # 库文件存放目录
# remote_tmp = $HOME/.ansible/tmp      # 远程临时命令存放目录
# local_tmp     = $HOME/.ansible/tmp    # 本机临时命令执行目录
# forks         = 5                    # 默认并发数
# sudo_user     = root                 # 默认 sudo 用户
# ask_sudo_pass = True                 # 每次执行是否询问 ssh 密码
# ask_pass     = True
# remote_port   = 22
# host_key_checking = False            # 检查服务器 host_key，建议取消注释，实现首次连接自动信任目标主机
# log_path=/var/log/ansible.log        # 日志文件，建议启用
# module_name = command                # 默认模块，可改为 shell

[privilege_escalation]                  # 普通用户提权配置
# become=True
# become_method=sudo
# become_user=root
# become_ask_pass=False

提权配置：[privilege_escalation] 段控制普通用户如何提权（sudo 到 root 等），是生产中以非 root 用户执行 Ansible 时的关键配置。

# 四、Inventory 主机清单

官方文档：https://docs.ansible.com/ansible/latest/inventory_guide/intro_inventory.html

Ansible 的主要功能在于批量主机操作。为了便捷地使用部分主机，可在 Inventory 主机清单中将其分组组织。默认的 inventory 文件为 /etc/ansible/hosts，可以有多个，也可通过 Dynamic Inventory 动态生成。

生产建议：在每个项目目录下创建项目独立的 hosts 文件，避免混用。

# 4.1 主机清单文件格式

  1. inventory 文件遵循 INI 文件风格，中括号中的字符为组名；
  2. 同一个主机可同时归并到多个不同的组中；
  3. 若目标主机使用非默认 SSH 端口，可在主机名后用冒号加端口号标明；
  4. 若主机名遵循相似命名模式，可用列表方式标识各主机。

# 4.2 Inventory 常用参数

在主机清单中可为每台主机设置连接相关的变量：

变量说明
ansible_ssh_host将要连接的远程主机名/IP（与别名不同时使用）
ansible_ssh_portSSH 端口号（非默认端口时设置，可用 ip:端口 形式）
ansible_ssh_user默认 SSH 用户名
ansible_ssh_passSSH 密码（不安全，强烈建议用 --ask-pass 或 SSH 密钥）
ansible_sudo_passsudo 密码（不安全，建议用 --ask-sudo-pass）
ansible_sudo_exesudo 命令路径（1.8+）
ansible_connection连接类型：local、ssh、paramiko 等
ansible_ssh_private_key_fileSSH 私钥文件（多密钥且不用 SSH 代理时）
ansible_shell_type目标 shell 类型，默认 sh，可设 csh/fish
ansible_python_interpreter目标主机的 Python 解释器路径

# 4.3 主机清单示例

列表形式：

# vim /etc/ansible/hosts
ntp.example.com              # 1) 被管理主机的名称或 IP
[webservers]                 # 2) 将被管理主机分类
www1.example.com:2222        # 3) 非默认 SSH 端口
www2.example.com

[dbservers]
db1.example.com
db2.example.com
db3.example.com
# 或用列表方式
db[1:3].example.com

组嵌套（一个组包含其它组）：

[webservers]
www[1:100].example.com

[dbservers]
db-[a:f].example.com

[appservers]
10.0.0.[1:100]              # 列表形式：10.0.0.1 - 10.0.0.100

# 定义 testsrvs 组包含 webservers 和 dbservers 两个分组
[testsrvs:children]
webservers
dbservers

连接类型与变量示例：

[local]
10.0.0.8  ansible_connection=local        # 指定本地连接，无需 ssh

[websrvs]
# 注意：在被控主机行直接写密码会暴露安全信息，不推荐
10.0.0.7 ansible_connection=ssh ansible_ssh_port=2222 ansible_ssh_user=opsuser
10.0.0.6 ansible_connection=ssh ansible_ssh_user=root

# 用别名 + ansible_ssh_host
[websrvs]
web01 ansible_ssh_host=10.0.0.101
web02 ansible_ssh_host=10.0.0.102

# 仅填 IP 也可以
[websrvs]
10.0.0.7
10.0.0.17

---
[websrvs:vars]
# 组级公共变量
ansible_ssh_password=<密码>

some_host   ansible_ssh_port=2222   ansible_ssh_user=manager
aws_host     ansible_ssh_private_key_file=/home/example/.ssh/aws.pem
freebsd_host ansible_python_interpreter=/usr/local/bin/python
ruby_module_host ansible_ruby_interpreter=/usr/bin/ruby.1.9.3

安全提醒：把明文密码写进主机清单会暴露安全风险，生产环境应使用 SSH 密钥认证或 --ask-pass，详见下一节。

# 五、使用前的准备工作（SSH 免密）

Ansible 相关工具大多通过 SSH 协议实现对远程主机的配置管理、应用部署和任务执行。建议使用前先配置主控端能基于密钥认证联系各被控节点。

# 5.1 解决首次连接的交互确认

第一次远程连接某台主机时，对方会默认询问是否信任该主机的 host key，需输入 yes 后才会将公钥写入本机 known_hosts。两种方式可自动处理：

方式一：修改 SSH 客户端配置

vim /etc/ssh/ssh_config
StrictHostKeyChecking no        # 自动回复 yes

# 验证 known_hosts
cat ~/.ssh/known_hosts

方式二：修改 Ansible 配置

vim /etc/ansible/ansible.cfg
host_key_checking = False        # 取消该行注释

# 5.2 基于密码认证（不常用）

# 注意：websrvs 组所有主机密码必须一致，否则无法连接
# 推荐使用 Key 认证
ansible websrvs -m ping -k
SSH password: <密码>

# 5.3 批量配置 SSH 密钥（sshpass + ssh-copy-id）

实际运维中常需要批量为多台主机配置免密登录。可借助 sshpass 配合 ssh-copy-id 并发推送公钥：

#!/bin/bash
HOSTS="
192.168.80.8
192.168.80.18
192.168.80.28
"
PASS=<主机密码>

# 生成密钥（若不存在）
[ -f /root/.ssh/id_rsa ] || ssh-keygen -P "" -f /root/.ssh/id_rsa &> /dev/null

# 安装 sshpass
rpm -q sshpass &> /dev/null || yum -y install sshpass &> /dev/null

# 并发推送公钥，忽略主机密钥严格检查
for i in $HOSTS; do
    {
        sshpass -p $PASS ssh-copy-id -o StrictHostKeyChecking=no -i /root/.ssh/id_rsa.pub $i &> /dev/null
    } &
done
wait

进阶脚本可先扫描局域网活动主机，再向扫描到的主机分发密钥，实现主机间相互免密。核心思路一致：用 ssh-keygen 生成密钥 → 用 ssh-copy-id 分发公钥 → 配置 StrictHostKeyChecking no。
