# Ansible 命令行工具与 Ad-Hoc 命令

本文介绍 Ansible 自带的六大命令行工具，重点讲解 ansible 命令（Ad-Hoc 临时命令）的用法：命令格式、常用选项、主机匹配模式（host-pattern）、并发控制、提权以及执行过程与状态含义。Ad-Hoc 命令适合临时、一次性任务，是日常运维中最高频的操作。

# 一、Ansible 相关工具

安装后，Ansible 提供以下命令行工具（均在 /usr/bin/ 下）：

工具作用
ansible主程序，临时命令执行工具（Ad-Hoc）
ansible-doc查看模块文档，相当于 man
ansible-playbook执行定制的自动化剧本（Playbook）
ansible-pull远程执行命令的工具（拉取模式）
ansible-vault文件加密/解密工具
ansible-console基于交互式 Console 执行命令的工具
ansible-galaxy下载/上传 Roles 模块的官方平台工具

Ansible 实现管理主要有两种方式：

  • Ansible Ad-Hoc：利用 ansible 命令，主要用于临时命令场景；
  • Ansible Playbook：用于长期规划好的、大型项目场景，需要前期规划。

# 二、ansible-doc：查看模块文档

ansible-doc 用于显示模块帮助，相当于 man。

格式：

ansible-doc [options] [module...]

常用选项：

  • -l, --list：列出可用模块；
  • -s, --snippet：显示指定模块的 playbook 片段。

示例：

# 列出所有模块
ansible-doc -l

# 查看指定模块的详细说明
ansible-doc ping

# 查看指定模块的简单说明
ansible-doc -s ping

# 过滤查看
ansible-doc -l | grep ^ping

# 查看模块的"使用案例"（EXA 部分，非常实用）
ansible-doc ping | grep -A 100 EXA
ansible-doc file | grep -A 100 EXA

# 查看指定类型的插件
ansible-doc -t connection -l
ansible-doc -t lookup -l

为什么用 file 模块而不是直接用 chown？ Shell 命令不具备幂等性，而 Ansible 的大部分模块（如 file）支持幂等性，使用模块更安全可靠。这是 Ansible 模块的核心价值。

# 三、ansible：Ad-Hoc 临时命令

# 3.1 命令格式与选项

ansible <host-pattern> [-m module_name] [-a args]

常用选项：

选项说明
--version显示版本
-m module指定模块，默认为 command
-v / -vv / -vvv详细过程，逐级更详细
--list-hosts显示主机列表（可简写 --list）
-C, --check检查，并不执行
-T, --timeout=TIMEOUT执行命令超时时间，默认 10s
-k, --ask-pass提示输入 SSH 连接密码，默认 Key 验证
-u, --user=REMOTE_USER执行远程命令的用户，默认 root
-b, --become提权（替代旧版 sudo）
--become-user=USERNAME指定 sudo 切换的用户，默认 root
-K, --ask-become-pass提示输入 sudo 口令
-f FORKS, --forks FORKS指定并发执行任务的主机数

示例：

# 本机
ansible localhost -m ping

# 主机组
ansible websrvs -m ping

# 显示详细过程
ansible websrvs -m ping -v
ansible websrvs -m ping -vv
ansible websrvs -m ping -vvv

# 3.2 以普通用户身份提权操作

实际生产中常以普通用户连接、再通过 sudo 提权执行。需先在被控端授权：

# 被控端：创建普通用户并授权 sudo
[root@centos8 ~] useradd testuser
[root@centos8 ~] echo <密码> | passwd --stdin testuser
[root@centos8 ~] vim /etc/sudoers
testuser  ALL=(ALL) NOPASSWD: ALL
# 主控端：以 testuser 连接，sudo 提权到 root 执行 whoami
[root@ansible ~] ansible 192.168.80.8 -m shell -a 'whoami' -u testuser -k -b --become-user=root
SSH password:        # 输入远程主机 testuser 用户的 SSH 连接密码
10.0.0.8 | CHANGED | rc=0 >>
root

提权用法小结：

# 以 testuser 执行 ping
ansible all -m ping -u testuser -k

# 以 testuser sudo 到 root 执行 ping
ansible all -m ping -u testuser -k -b

# 以 testuser sudo 到 mage 用户执行 ping
ansible all -m ping -u testuser -k -b --become-user=mage

# 以 testuser sudo 到 root 执行 ls
ansible all -m command -u testuser -a 'ls /root' -b --become-user=root -k -K

# 3.3 Host-pattern 主机匹配

host-pattern 用于匹配被控制的主机列表，支持多种模式：

全部与通配：

# 所有 Inventory 中的主机
ansible all -m ping

# 通配符
ansible "*" -m ping
ansible 192.168.80.* -m ping
ansible "srvs" -m ping
ansible "192.168.80.8 192.168.80.18" -m ping

或关系（冒号 :）：

ansible "websrvs:appsrvs" -m ping
ansible "192.168.1.10:192.168.1.20" -m ping

逻辑与（:&）：

# 在 websrvs 组且在 dbsrvs 组中的主机（交集）
ansible "websrvs:&dbsrvs" -m ping

逻辑非（:!）：

# 在 websrvs 组但不在 dbsrvs 组中的主机
# 注意：使用 ! 时必须用单引号，双引号会被 bash 当作历史展开
ansible 'websrvs:!dbsrvs' -m ping

综合逻辑：

ansible 'websrvs:dbsrvs:&appsrvs:!ftpsrvs' -m ping

正则表达式（~）：

ansible "~(web|db).*\.example\.com" -m ping

实战示例：

# 重启所有以 kube 或 etcd 开头、且不是本机(10.0.0.101)的主机
[root@kube-master1 ~] ansible 'kube*:etcd:!10.0.0.101' -a reboot && reboot

验证匹配结果（--list-hosts）：

[root@centos8 ~] ansible all --list-hosts
 hosts (3):
    10.0.0.6
    10.0.0.7
    10.0.0.8

[root@centos8 ~] ansible websrvs --list-hosts
 hosts (3):
    10.0.0.6
    10.0.0.7
    10.0.0.8

注意：引用 ! 时不要用双引号，否则会触发 bash 的 event not found 错误，必须用单引号。

# 3.4 并发控制

# 单台单台执行
ansible all -a 'sleep 1' -f1

# 一次性并发执行
ansible all -a 'sleep 1' -f10

# 3.5 命令执行过程

Ansible 执行一条 Ad-Hoc 命令的过程：

  1. 加载默认配置文件 /etc/ansible/ansible.cfg；
  2. 加载相应的模块（如 command 模块）；
  3. Ansible 生成临时 Python 文件，传输到远程服务器的 $HOME/.ansible/tmp/ansible-tmp-数字/XXX.PY；
  4. 为文件添加执行权限；
  5. 执行文件并返回结果；
  6. 删除临时文件并退出。

验证方式：执行一个耗时命令，再在被控端查看临时目录：

[root@ansible ~] ansible all -m shell -a 'sleep 100'
[root@centos8 ~] ll ~/.ansible/tmp/*

# 3.6 执行状态颜色

Ansible 执行结果通过颜色区分状态（可在 [colors] 段配置）：

颜色含义
绿色成功执行，没有发生状态改变
黄色成功执行，发生了状态改变（changed）
红色执行失败

ping 模块说明：ansible all -m ping 中的 ping 模块并没有走 ICMP 协议，而是通过 SSH 连接执行一个返回 pong 的 Python 脚本，用于测试与目标主机的连通性。

# 四、ansible-console：交互式执行

ansible-console 提供交互式命令行，支持 Tab 补全，Ansible 2.0+ 新增。

提示符格式： 执行用户@当前主机组 (主机数量)[f:并发数]$

常用子命令：

  • forks n：设置并发数，如 forks 10；
  • cd 主机组：切换组，如 cd websrvs；
  • list：列出当前组主机列表；
  • ? 或 help：列出所有内置命令。

示例：

[root@ansible ~]# ansible-console
Welcome to the ansible console.
Type help or ? to list commands.

root@all (3)[f:5]$ ping
root@all (3)[f:5]$ list
root@websrvs (2)[f:5]$ cd websrvs
root@websrvs (2)[f:5]$ forks 1
root@websrvs (2)[f:1]$ ping
root@appsrvs (2)[f:5]$ yum name=httpd state=present
root@appsrvs (2)[f:5]$ service name=httpd state=started

在 console 中可直接使用模块语法（模块名 参数=值），适合交互式探索。

# 五、ansible-playbook：执行剧本

用于执行编写好的 Playbook 任务：

ansible-playbook hello.yml

示例 hello.yml：

---
# hello world yml file
- hosts: websrvs
  remote_user: root
  gather_facts: no

  tasks:
    - name: hello world
      command: /usr/bin/wall hello world

Playbook 的详细用法将在后续文章展开。

# 六、ansible-vault：文件加密

用于加密/解密 YAML 文件（RHCE 考试涉及）。

ansible-vault [create|decrypt|edit|encrypt|rekey|view]

ansible-vault encrypt hello.yml     # 加密
ansible-vault decrypt hello.yml     # 解密
ansible-vault view hello.yml        # 查看
ansible-vault edit hello.yml        # 编辑加密文件
ansible-vault rekey hello.yml       # 修改口令
ansible-vault create new.yml        # 创建新文件

安全实践：涉及密码、密钥等敏感信息的 Playbook 或变量文件，应使用 ansible-vault 加密后再存放，避免明文泄露。

# 七、ansible-galaxy：Role 管理平台

Galaxy 是一个免费网站（类似 GitHub），发布了大量共享的 Roles 角色。ansible-galaxy 命令行工具连接 https://galaxy.ansible.com ，进行 init、search、install、remove 等操作。

示例：

# 搜索项目
ansible-galaxy search lamp

# 列出所有已安装的 galaxy
ansible-galaxy list

# 安装（默认下载到 ~/.ansible/roles 下）
ansible-galaxy install geerlingguy.mysql
ansible-galaxy install geerlingguy.redis

# 删除
ansible-galaxy remove geerlingguy.redis

# 也可安装指定角色
ansible-galaxy role install noobient.wordpress

# 小结

本文梳理了 Ansible 的六大命令行工具，并深入讲解了 ansible Ad-Hoc 命令：格式与选项、普通用户提权、host-pattern 主机匹配（通配/或/与/非/正则）、并发控制、执行过程与状态颜色。Ad-Hoc 适合临时任务，而当任务需要重复、可复用时，就应转为 Playbook——下一篇开始介绍 Playbook 与 YAML。
