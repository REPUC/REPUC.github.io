# 1. 文件管理概述

谈到 Linux 文件管理，首先要明确：我们要对文件做些什么？无非就是对文件进行创建、复制、移动、查看、编辑、压缩、查找、删除等操作。

例如：当我们想修改系统的主机名称，是否应该知道文件在哪，才能去做对应的修改？

# 1.1 系统目录结构

几乎所有的计算机操作系统都使用目录结构组织文件：在一个目录中存放子目录和文件，子目录中又进一步存放子目录和文件，以此类推形成树状的文件结构。由于结构很像一棵树的分支，因此又被称为"目录树"。

  • Windows：以多根的方式组织文件，如 C:\、D:\
  • Linux：以单根的方式组织文件，即 /

Linux 根目录下的顶层目录包含：bin、boot、dev、etc、home、root、run、sbin、tmp、usr、var 等。

# 1.1.1 命令相关目录 /bin

存放命令相关的目录：

  • /bin：普通用户使用的命令，如 /bin/ls、/bin/date
  • /sbin：管理员使用的命令，如 /sbin/service
[root@bgx ~]# which ls
alias ls="ls --color=auto"
/usr/bin/ls
[root@bgx ~]# which useradd
/usr/sbin/useradd

# 1.1.2 用户家相关目录 /home

存放用户相关数据的家目录（类似 Windows 中不同用户登陆显示不同桌面背景）：

  • /home：普通用户的家目录，默认 /home/username
  • /root：超级管理员 root 的家目录，普通用户无权操作
[root@bgx ~]# pwd
/root
[root@bgx ~]# useradd tt
[root@bgx ~]# ls /home/
tt

# 1.1.3 系统文件目录 /usr

存放系统相关文件的目录：

  • /usr：相当于 Windows 的 C:\Windows
  • /usr/local：软件安装的目录，相当于 C:\Program Files
  • /usr/bin/：普通用户使用的应用程序（重要）
  • /usr/sbin：管理员使用的应用程序（重要）
  • /usr/lib：库文件 Glibc 32bit
  • /usr/lib64：库文件 Glibc 64bit
[root@bgx ~]# ls /usr/
bin      games    lib      libexec  sbin    src
etc      include  lib64    local    share   tmp

# 1.1.4 系统启动目录 /boot

存放系统启动时内核与 grub 引导菜单：

  • /boot：存放系统启动相关文件，如 kernel、grub（引导装载程序）

# 1.1.5 配置文件目录 /etc

/etc 存放系统配置文件，后续所有服务的配置都在这个目录中：

  • /etc/sysconfig/network-scripts/ifcfg-*：网络配置文件
  • /etc/hostname：系统主机名配置文件

# 1.1.6 设备相关目录 /dev

/dev 存放设备文件，如硬盘、硬盘分区、光驱等：

  • /dev/null：黑洞设备，只进不出，类似垃圾回收站
  • /dev/random：生成随机数的设备
  • /dev/zero：能源源不断产生数据，类似取款机，随时随地取钱
[root@bgx ~]# ls /dev/sda*
[root@bgx ~]# ls /dev/zero /dev/random /dev/null
# /dev/zero 能产生源源不断的数据（摇钱树）
# /dev/null 黑洞（只进不出）

# 1.1.7 可变的目录 /var

存放一些变化的文件：

  • /var：存放变化文件，如 /var/log/ 下的日志文件
  • /var/tmp：进程产生的临时文件
  • /tmp：系统临时目录（类似公共厕所）

# 1.1.8 虚拟系统目录 /proc

虚拟的文件系统（对应的进程停止后，/proc 下对应目录会被删除）：

  • /proc：反映当前系统正在运行进程的实时状态，类似汽车运行中的仪表板，能看到油耗、时速、转向灯、故障等

# 1.2 文件路径定位

# 1.2.1 为什么要进行定位

  • 你要在哪个目录下创建文件？
  • 你要将文件复制到什么地方？
  • 你要删除的文件在什么地方？

# 1.2.2 如何对文件进行定位

例如 /etc/hostname，整个路径中包含文件名称以及文件所在的位置，这就是路径，即通过路径对文件进行定位。

# 1.2.3 访问路径方式 - 绝对路径

绝对路径：从 / 开始的路径，如 /var/log/messages。

# 1.2.4 访问路径方式 - 相对路径

相对路径：相对于当前目录来说，如 a.txt、./a.txt、../var/。

# 2.5.1 sort 命令

功能：基于全局对文本进行排序，可以使用 sort 命令对文件进行排序。

sort [OPTION]... [FILE]...

常用选项：

  • -r：逆序
  • -n：按数值排序
  • -t：指定分隔符
  • -k：指定排序的列，如 -k1,1 或 -k3,3
# 1. 创建测试文件
[root@oldwang ~]# cat >> file.txt <<EOF
b:3
c:2
a:4
e:5
d:1
f:11
EOF

# 2. 按默认排序（按字符排序）
[root@oldwang ~]# sort file.txt
a:4
b:3
c:2
d:1
e:5
f:11

# 按指定分隔符和列排序（-t 指定分隔符，-k 指定排序列）
[root@oldwang ~]# sort -t ":" -k2 sort.txt
d:1
f:11   # 按字符排序，11在2前面
c:2
b:3
a:4
e:5

# 按数值排序（-n 数值排序）
[root@oldwang ~]# sort -t ":" -n -k2 p.txt
d:1
c:2
b:3
a:4
e:5
f:11

# 复杂排序：对多个列排序（-k3.1,3.1nr 按第3列第1个字符逆序数值排）
[root@oldwang ~]# sort -t. -k3.1,3.1nr -k4.1,4.3nr ip.txt

# 2.5.2 uniq 命令

如果文件中有多行完全相同的内容，希望删除重复的行，同时统计完全相同的行出现的总次数，可以使用 uniq 命令（必须配合 sort 使用）。

uniq [OPTION]... [INPUT [OUTPUT]]

常用选项：

  • -c：统计重复次数
# 1. 准备测试文件
[root@oldwang ~]# cat file.txt
abc
123
abc
123

# 2. uniq 需配合 sort 使用，先排序
[root@oldwang ~]# sort file.txt
123
123
abc
abc

# 3. sort + uniq 去重
[root@oldwang ~]# sort file.txt | uniq
123
abc

# -c 参数能统计出文件中每行内容重复的次数
[root@oldwang ~]# sort file.txt | uniq -c
2 123
2 abc

# 注意: 重定向输出，避免直接修改原文件

# 3. 文件扩展知识

# 3.1 文件属性

使用 ls -l 列出目录下所有文件时，会以长格式显示，长格式显示就是 Windows 下看到的文件详细信息，称为文件属性，整个文件属性分为多列。

[root@oldwang ~]# ls -l ks.cfg
-rw-------. 1 root root 4434 May 30 13:58 ks.cfg

各列含义：

  • -rw-------.：第一个字符是文件类型，其余为权限
  • 1：硬链接次数
  • root：文件属于哪个用户
  • root：文件属于哪个组
  • 4434：文件大小
  • May 30 13:58：最新修改的时间与日期
  • ks.cfg：文件或目录名称

# 3.2 文件类型

通常使用颜色或后缀名称区分文件类型，但很多时候不够准确。可以通过 ls -l 以长格式显示文件属性，通过第一列的第一个字符判断文件具体类型。

[root@oldwang ~]# ls -ld /etc/hosts /tmp /bin/ls /dev/sda /dev/tty1 /etc/grub2.cfg /dev/log /run/dmeventd-client

-rwxr-xr-x. 1 root root 117656 Jun 30 2016 /bin/ls

srw-rw-rw-. 1 root root      0 Jan 20 10:35 /dev/log

brw-rw----. 1 root disk   8, 0 Jan 20 10:36 /dev/sda

crw--w----. 1 root tty   4, 1 Jan 20 10:36 /dev/tty1

lrwxrwxrwx. 1 root root    22 Jan 13 11:31 /etc/grub2.cfg -> ../boot/grub2/grub.cfg

-rw-r--r--. 1 root root   199 Jan 20 11:03 /etc/hosts

drwxrwxrwt. 61 root root 8192 Jan 21 13:01 /tmp

文件类型说明：

文件类型字母类型含义
-普通文件（文本、二进制、压缩、图片、日志等）
d目录文件
b设备文件（块设备）存储设备硬盘 /dev/sda、/dev/sr0
c设备文件（字符设备）终端 /dev/tty1
s套接字文件，进程与进程间的一种通信方式（socket 插座）
l链接文件

有些情况下无法通过 ls -l 判断文件类型（如文件可能是普通文件、压缩文件或命令文件），此时需要使用 file 命令更精准地判断文件类型。

[root@oldwang ~]# file /etc/hosts
/etc/hosts: ASCII text
[root@oldwang ~]# file /bin/ls
/bin/ls: ELF 64-bit LSB executable, x86-64, version 1 (SYSV), dynamically linked (uses shared libs), for GNU/Linux 2.6.32, BuildID[sha1]=aa7ff68f13de25936a098016243ce57c3c982e06, stripped
[root@oldwang ~]# file /dev/sda
/dev/sda: block special
[root@oldwang ~]# file /dev/tty1
/dev/tty1: character special
[root@oldwang ~]# file /etc/grub2.cfg
/etc/grub2.cfg: broken symbolic link to ../boot/grub2/grub.cfg
[root@oldwang ~]# file /home
/home: directory

Linux 文件扩展名不代表任何含义，仅为了让人能更好地识别文件类型。

# 3.3 链接文件

# 3.3.1 Inode 与 Block

文件有文件名与数据，在 Linux 上被分成两个部分：数据 data 与文件元数据 metadata。

  1. 数据 data block：数据块是记录文件真实内容的地方，称为 Block
  2. 元数据 metadata：用来记录文件大小、创建时间、所有者等信息，称为 Inode
  3. 需要注意：Inode 不包含文件名称，仅包含文件的元数据信息，具体包括：
    • 文件的字节数
    • 文件的 User ID、Group ID
    • 文件的读、写、执行权限
    • 文件的时间戳
    • 链接数，即有多少个文件名指向这个 inode
    • 文件数据 block 的位置

每个 inode 都是一个编号，操作系统通过 Inode 来识别不同的文件。对系统来说，文件名只是 inode 便于识别的别名（绰号）。

表面上用户通过文件名打开文件，系统内部实际过程分为三步：

  1. 首先，系统找到这个文件名对应的 inode 编号
  2. 其次，通过 inode 编号，获取 inode 信息
  3. 最后，根据 inode 信息，找到文件数据所在的 block，读出数据

# 3.3.2 软连接

什么是软连接：软链接相当于 Windows 的快捷方式。

软链接实现原理：

  1. 软链接文件会将 inode 指向源文件的 block
  2. 当访问软链接文件时，其实访问的是源文件本身

软链接使用场景：

  • 软件升级
  • 代码发布

软链接场景实践（代码发布）：

# 1. 准备环境
[root@oldwang ~]# mkdir -p /data/rainbow-v1.1
[root@oldwang ~]# echo "123" > /data/rainbow-v1.1/index.html

# 2. 创建软链接
[root@oldwang ~]# ln -s /data/rainbow-v1.1/ /data/rainbow
[root@oldwang ~]# ls -l /data/
drwxr-xr-x. 2 root root  6 Apr 5 12:23 dir
lrwxrwxrwx. 1 root root 19 Apr 5 10:12 rainbow -> /data/rainbow-v1.1/
drwxr-xr-x. 2 root root 24 Apr 5 10:12 rainbow-v1.1

# 3. 测试读取
[root@oldwang ~]# cat /data/rainbow/index.html
123

# 更新一个网站的程序代码
[root@oldwang ~]# mkdir /data/rainbow-v1.2
[root@oldwang ~]# echo "456" > /data/rainbow-v1.2/index.html

# 5. 升级软链接
[root@oldwang ~]# rm -f /data/rainbow && ln -s /data/rainbow-v1.2/ /data/rainbow
[root@oldwang ~]# cat /data/rainbow/index.html
456

# 6. 回退
[root@oldwang ~]# rm -f /data/rainbow && ln -s /data/rainbow-v1.1/ /data/rainbow
[root@oldwang ~]# cat /data/rainbow/index.html
123

# 3.3.3 硬连接

硬链接类似于超市有多个门，无论从哪个门进入，看到的内容都是一样的，不会影响进入超市。

回到系统中，硬链接的解释：不同的文件名指向同一个 inode，简单说就是指向同一个真实的数据源。

硬链接与软链接区别：

  1. ln 命令创建硬链接，ln -s 命令创建软链接
  2. 目录不能创建硬链接，且硬链接不可以跨越分区系统
  3. 软链接支持对目录创建，同时支持跨越分区系统
  4. 硬链接文件与源文件的 inode 相同，软链接文件与源文件 inode 不同
  5. 删除软链接文件，对源文件及硬链接文件无任何影响
  6. 删除文件的硬链接文件，对源文件及链接文件无任何影响
  7. 删除链接文件的源文件，对硬链接无影响，会导致软链接失效
  8. 删除源文件及其硬链接文件，整个文件会被真正删除

# 3.4 文件时间

Linux 下文件有 3 个时间，分别是 atime、mtime、ctime。

简名全名中文名含义
atimeaccess time访问时间文件中的数据最后被访问的时间
mtimemodify time修改时间文件内容被修改的最后时间
ctimechange time变化时间文件的元数据发生变化（如权限、所有者等）

# 3.4.1 环境准备

[root@oldwang ~]# mount -o remount,strictatime /
[root@oldwang ~]# echo "hello boy" >> new_file
[root@oldwang ~]# stat new_file

# 3.4.3 mtime（修改时间）

修改文件内容：

[root@oldwang ~]# echo "Hello" >> new_file
[root@oldwang ~]# stat new_file
File: 'new_file'
Size: 16          Blocks: 8          IO Block: 4096 regular file
Device: fd00h/64768d    Inode: 34724341    Links: 1
Access: (0644/-rw-r--r--) Uid: (    0/    root) Gid: (    0/    root)
Access: 2021-07-07 16:28:35.520036828 +0800
Modify: 2021-07-07 16:32:36.806358744 +0800 # 修改内容后，mtime发生变化

ctime 发生变化的缘由是：内容变化了，inode 所记录的元数据也需要变化，所以时间发生了变化。
