# Nginx 反向代理与负载均衡

本文讲解 Nginx 最核心的生产能力：正向代理与反向代理的区别、四层与七层代理、HTTP 反向代理配置（proxy_pass 系列指令）、缓存、IP 透传、跨域解决，以及基于 upstream 的负载均衡与调度算法。这是 Nginx 在生产中承担流量入口的关键。

# 一、代理模式基础

# 1.1 正向代理与反向代理

正向代理：位于客户端和目标服务器之间的代理服务器。为从目标服务器取得内容，客户端向代理服务器发送请求并指定目标，代理服务器向目标服务器转交请求并将获得的内容返回给客户端。典型场景：用户无法直接访问某网站，通过代理服务器转发请求（如翻墙访问国外网站）。类比租房：租客（用户）无法直接联系房东（国外网站），只能通过中介（代理服务器）联系。

反向代理：以代理服务器接受 Internet 上的连接请求，将请求转发给内部网络上的服务器，并将从服务器得到的结果返回给 Internet 上的客户端。此时代理服务器对外表现为一个反向代理服务器。典型场景：负载均衡——客户端请求发送到负载均衡服务器（二房东），再转发给真正的服务器（房东）执行，再返回结果。通过反向代理访问目标服务器时，客户端不知道真正的目标服务器是谁，甚至不知道自己访问的是代理服务器。

# 1.2 代理相关模块

Nginx 通过不同协议与后端服务器通信，主要模块：

模块作用
ngx_http_proxy_module将客户端请求以 HTTP 协议转发至指定服务器
ngx_http_upstream_module定义为 proxy_pass/fastcgi_pass/uwsgi_pass 等引用的后端服务器分组
ngx_stream_proxy_module将客户端请求以 TCP 协议转发至指定服务器
ngx_http_fastcgi_module将客户端对 PHP 的请求以 FastCGI 协议转发至指定服务器
ngx_http_uwsgi_module将客户端对 Python 的请求以 uWSGI 协议转发至指定服务器

# 1.3 同构代理与异构代理

  • 同构代理：前端用户访问 Nginx 是 HTTP/HTTPS，代理访问后端也是 HTTP 协议，前后端同协议；
  • 异构代理：前端 HTTP/HTTPS，代理与后端使用 FastCGI 等不同协议。

# 1.4 四层代理与七层代理

四层代理：TCP 层，使用 IP + 端口，类似路由器，只修改 IP 地址转发给后端，TCP 三次握手直接和后端连接。

七层代理：必须先和代理机三次握手，得到 7 层（HTTP 层）具体内容后再转发，代理机须与 client 和后端都建立连接。性能稍差，但胜在七层能写更多转发规则。

生产链路：四层代理 → 多个七层代理（水平扩容）→ 业务服务，实现高并发。

四层（LVS）与七层（Nginx）对比：

维度四层（LVS）七层（Nginx）
工作层传输层（四层）应用层（七层）
监听端口不监听监听端口
后端是否看到客户端地址可以不可以
建立连接（三次握手）不参与，只转发代替后端与客户建立连接
TCP 请求次数1 次2 次

代理原理：

  • 四层代理：用 NAT（网络地址转换）技术，请求进来修改数据包的目标 IP、源 IP、源端口，发向目标服务器，处理完再修改返回客户端；
  • 七层代理：读取并解析 HTTP 请求内容，根据 URL、参数、cookie、请求头转发到相应服务器，转发过程为建立与目标机器连接→转发请求→收到响应转发回客户端。

优缺点：

  • 性能：理论上四层比七层快（七层需解析数据包内容，消耗额外 CPU）；
  • 灵活性：四层用 NAT，代理服务器一般不知请求具体内容，只做转发；七层可据请求内容（url、参数、cookie、请求头）做很多事。

# 二、实现 HTTP 反向代理

Nginx 基于 ngx_http_proxy_module 模块提供 HTTP 协议反向代理服务。

# 2.1 反向代理配置参数

# proxy_pass

语法：proxy_pass URL;，Context: location, if in location, limit_except。

设置将客户端请求转发给的后端服务器主机，可为主机名（转发时作 Host 首部）或 IP:port。

关键区别（重点）：

location /web {
    # proxy_pass 后无 uri（无 /），类似 root，需将 location 的 url 附加到 proxy_pass 后
    proxy_pass http://192.168.80.18:8080;
    # http://nginx/web/index.html ==> http://192.168.80.18:8080/web/index.html
    # 后端服务器站点根目录下要有 web 目录

    # proxy_pass 后有 uri（有 /），类似 alias，置换
    proxy_pass http://192.168.80.18:8080/;
    # http://nginx/web/index.html ==> http://192.168.80.18:8080/index.html
}

正则 location 注意：若 location 用正则（、*，不含 ^~），则 proxy_pass 后不能使用 uri（不能有 /），用户请求的 uri 直接附加至后端。

location ~|~* /uri/ {
    proxy_pass http://host:port;   # 不能加 /
}
# http://HOSTNAME/uri/ --> http://host/uri/

# 头部处理指令

proxy_hide_header field;      # 隐藏后端服务器响应首部（可设 http/server/location）
proxy_pass_header field;      # 透传默认不传递的首部（Date、Server、X-Pad、X-Accel 等）
proxy_pass_request_body on|off;    # 是否向后端发送 HTTP 实体，默认 on
proxy_pass_request_headers on|off; # 是否转发客户端请求首部给后端，默认 on
# 隐藏后端 ETag
location /web {
    proxy_pass http://192.168.80.18:8080/;
    proxy_hide_header ETag;
}
# 透传 Server 和 Date
proxy_pass_header Server;
proxy_pass_header Date;

# proxy_set_header

更改或添加客户端请求首部并转发至后端，如后端需获取客户端真实 IP。

# $proxy_add_x_forwarded_for：将客户端 IP 追加到 X-Forwarded-For 首部，多 IP 逗号分隔；无该字段时等于 $remote_addr
proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
proxy_set_header X-Real-IP $remote_addr;   # 添加客户端真实 IP（NAT 上网时为公网 IP），常用于日志记录

后端 Apache 日志格式加 X-Real-IP：

LogFormat "%h %l %u %t \"%r\" %>s %b \"%{Referer}i\" \"%{User-Agent}i\" \"%{X-Real-IP}i\"" combined

# 超时指令

proxy_connect_timeout time;   # 与后端建立连接超时，默认 60s，超时返回 504
proxy_read_timeout time;      # 向后端发起 read 后等待超时，默认 60s
proxy_send_timeout time;      # 向后端发起 write 后等待超时，默认 60s

# 长连接

proxy_http_version 1.1;         # 设为 1.1 支持长连接（默认 1.0）
proxy_set_header Connection ""; # 配合 keepalive 实现代理与后端长连接，避免高并发时后端大量 TIME_WAIT

# 其他

proxy_ignore_client_abort off;  # 客户端中断时是否中断对后端请求，默认 off（记录 499）
proxy_headers_hash_bucket_size 128;   # 保存 HTTP 报文头 hash 表上限
proxy_headers_hash_max_size 512;
server_names_hash_bucket_size 512;
proxy_next_upstream error|timeout|invalid_header|http_500|http_502|http_503|http_504;
# 后端出错/超时/无效首部/500 等时，切换至下一个后端服务器

# 2.2 实战：反向代理单台 Web 服务器

需求：将用户访问 www.example.org 的请求转发给后端服务器（192.168.80.18）处理。

# 反向代理服务器
server {
    listen 80;
    server_name www.example.org;
    location / {
        proxy_pass http://192.168.80.18/;       # 转发至后端
        proxy_set_header Host $http_host;       # 转发主机头至后端
        proxy_connect_timeout 10s;
    }
}
nginx -t && nginx -s reload

# 后端服务器 192.168.80.18
yum install nginx -y && nginx
echo 192.168.80.18 > /usr/share/nginx/html/index.html

错误提示：

  • 后端无法连接（iptables REJECT / 停止 / 宕机，无 arp 缓存）→ 502 Bad Gateway；
  • 后端 1 分钟内无响应（iptables DROP，有 arp 缓存）→ 504 Gateway Time-out。

# 2.3 实战：指定 location 实现反向代理

针对指定 location：

server {
    listen 80;
    server_name www.example.org;
    location / {
        index index.html index.php;
        root /data/nginx/html/pc;          # 访问 / 返回代理服务器站点目录
    }
    location /static {
        proxy_pass http://192.168.80.18:80/;    # 有 / 表示置换，返回后端 /index.html
        # proxy_pass http://192.168.80.18:80;   # 无 / 表示附加，返回后端 static/index.html
    }
}
curl -L http://www.example.org/          # 返回主站页面
curl -L http://www.example.org/static    # 返回后端页面

针对特定资源实现代理（正则 location）：

location ~ \.(jpe?g|png|bmp|gif)$ {
    proxy_pass http://192.168.80.18;    # 正则 location，proxy_pass 不能加 /，否则语法出错
}
# nginx -t 报错：proxy_pass cannot have URI part in location given by regular expression

转发至后端指定站点（多 Server）：

# 后端服务器配置
server {
    listen 80;
    server_name blog.example.org;
    location / { root /data/html/blog; }
}

# 反向代理服务器
location /blog {
    proxy_pass http://blog.example.org;
    proxy_set_header Host blog.example.org;   # 指定转发主机头，指向后端指定站点
}

# 反向代理服务器 DNS 解析

# 2.4 反向代理缓存功能

启用缓存后，Nginx 转发请求前先在缓存查找，命中则直接返回不转发后端；未命中才转发后端，接收结果后缓存。

缓存配置指令：

# 在 http 块定义缓存（默认关闭）
proxy_cache_path /var/cache/nginx/proxy_cache
   levels=1:2:2             # 缓存目录层次，1:2:2 生成 2^20=1048576 个目录
   keys_zone=proxycache:20m # 内存中缓存大小，存 key 和 metadata，1M 存约 8000 个 key
   inactive=120s            # 缓存有效时间
   max_size=10g;            # 最大磁盘占用

proxy_cache zone_name | off;       # 调用缓存或关闭，默认 off
proxy_cache_key string;            # 缓存键，默认 $scheme$proxy_host$request_uri
proxy_cache_valid [code ...] time; # 特定响应码缓存时长
proxy_cache_valid 200 302 10m;
proxy_cache_valid 404 1m;

调用缓存：

proxy_cache proxycache;                    # 调用缓存
proxy_cache_key $request_uri;              # 缓存键
proxy_cache_valid 200 302 301 10m;        # 指定状态码缓存时长
proxy_cache_valid any 1m;                  # 必须指定，否则不缓存
proxy_cache_use_stale error|timeout|...;  # 后端异常时使用过期缓存
proxy_cache_methods GET|HEAD|POST ...;    # 对哪些请求方法缓存（GET/HEAD 总被缓存）

清理缓存：方法 1 rm -rf 缓存目录；方法 2 第三方模块 ngx_cache_purge。

实战：

# 1) http 块开启缓存定义
proxy_cache_path /data/nginx/proxycache
    levels=1:1:1
    keys_zone=proxycache:20m
    inactive=120s
    max_size=1g;

# 2) server 块调用缓存
location /static {
    proxy_pass http://192.168.80.18:80/;
    proxy_cache proxycache;
    proxy_cache_key $request_uri;
    proxy_cache_valid 200 302 301 10m;
    proxy_cache_valid any 5m;
    proxy_set_header Host $http_host;
}

压测对比：开启缓存后，ab -n 2000 -c 200 的每秒请求数从约 744 提升到约 8040，性能提升数倍。

# 2.5 添加响应报文头部信息

基于 ngx_http_headers_module，对后端响应报文添加指定首部。

add_header name value [always];   # Context: http, server, location, if in location
add_header X-Via $server_addr;            # 当前 nginx 主机 IP
add_header X-Cache $upstream_cache_status; # 缓存命中 HIT，未命中 MISS
add_header X-Accel $server_name;          # 客户访问的 FQDN
add_header TEST hello;                   # 自定义
# 1.13.2 版后支持 add_trailer 添加响应尾部

验证：curl http://www.example.org/static/log.html -I 可见 X-Cache: HIT；清除缓存后变为 MISS。

# 2.6 反向代理客户端 IP 透传

正常情况下，真实服务器只能看到代理服务器 IP，看不到客户端 IP。IP 透传让客户端 IP 也能在真实服务端可见。

一级代理：

server {
    listen 80;
    server_name www.example.org;
    location / {
        proxy_pass http://192.168.80.18:80/;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # 添加客户端 IP 和代理 IP
    }
}

$proxy_add_x_forwarded_for：将客户端 IP 追加到 X-Forwarded-For，多 IP 逗号分隔，无该字段时用 $remote_addr。

后端 Nginx 默认日志格式含 $http_x_forwarded_for，后端 Apache 需在 LogFormat 中加 %{X-Forwarded-For}i。

多级代理：

每级代理都配置 proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;，最终后端日志中 X-Forwarded-For 为完整 IP 链（如 192.168.80.1, 192.168.80.8）。

# 2.7 利用 Nginx 解决跨域问题

跨域：浏览器同源限制——访问 URL 的协议（Schema）/端口（Port）/域名（Host）任一与当前 URL 片段不匹配即存在跨域。浏览器会禁止跨域请求，但返回状态码仍为 200。

常见解决方案：CORS、JSONP、Nginx 反向代理。

Nginx 反向代理解决跨域：

server {
    listen 80;
    server_name www.example.org;
    location /api/ {
        proxy_pass http://192.168.80.8:8080;    # 反向代理至后端 API 站点
    }
}

前端将请求改为同域的 /api/，由 Nginx 代理到后端，浏览器视为同源，跨域问题解决。

# 三、HTTP 反向代理负载均衡

Nginx 可将客户端请求转发至一组后端服务器，并提供状态监测，实现负载均衡。基于 ngx_http_upstream_module 模块提供服务器分组转发、权重分配、状态监测、调度算法等高级功能。

# 3.1 upstream 配置参数

# 自定义一组服务器，配置在 http 块内
upstream name {
    server .....
}

# 示例
upstream backend {
    server backend1.example.com       weight=5;
    server backend2.example.com:8080;
    server unix:/tmp/backend3;
    server backup1.example.com:8080   backup;
    server backup2.example.com:8080   backup;
}
server {
    location / {
        proxy_pass http://backend;
    }
}

server 支持的参数：

参数说明
weight=number设置权重，默认 1，实现类似 LVS 的 WRR/WLC
max_conns=number后端 server 最大活动连接数，默认 0 无限制
max_fails=number下线条件，连续检测失败次数（默认 1），访问时才用 TCP 触发健康检查（非周期）
fail_timeout=time上线条件，不可用服务器每隔此时间再次检测恢复，默认 10s
backup备份服务器，所有后端不可用时启用（与 ip_hash 冲突，不能同时用；注意指向自身 server 可能死循环 500，应指向另一虚拟主机）
down标记为 down，平滑下线，新用户不再调度，旧用户不受影响

# 3.2 调度算法

rr（轮询，默认）：按请求顺序逐一分配到不同后端，相当于 LVS 的 rr。后端宕机会自动从池中剔除。

wrr（加权轮询）：在 rr 基础上加权重，权重越高访问概率越大，按配置和性能合理利用资源。

upstream websrvs {
    server 10.0.0.17 weight=2;
    server 10.0.0.27 weight=6;
}

ip_hash（源地址 hash）：基于客户端 remote_addr（IPv4 前 24 位或整个 IPv6）做 hash，实现会话保持，同一客户端请求始终传至同一服务器（除非该服务器不可用）。

注意：同一局域网多客户端可能调度到同一主机；与 backup 冲突。

upstream websrvs {
    ip_hash;
    server 10.0.0.17 weight=1;
    server 10.0.0.27 weight=2;
    server 10.0.0.37 weight=3;
}
# 接受请求：客户端 IP 前三位做 hash，如 md5(1.1.1)=digest1，基于权重总量取模，按结果分配

least_conn（最少连接）：优先调度到当前连接最少的后端，相当于 LVS 的 WLC。连接数相同时用 WRR。

least_conn;

hash KEY [consistent]（一致性 hash）：基于指定请求首部字段或 URI 做 hash，consistent 用 ketama 一致性 hash（基于 2^32 取模，适合后端为 Cache 服务器，扩容缩容时数据迁移少）。

hash $request_uri consistent;   # 基于 URI 一致性 hash，调度到后端缓存服务器
hash $remote_addr consistent;    # 对全部 32bit IPv4 一致性 hash
hash $cookie_sessionid;          # 基于 cookie sessionid 做 hash，实现会话绑定

一致性哈希原理：传统哈希用 hash(key) % 节点数 取模，节点数变化（扩容/缩容）时基数变化，导致大部分映射关系改变，需迁移大量数据（最坏 O(M)）。一致性哈希对 2^32 取模（固定值），组织成哈希环，节点增删只影响环上相邻节点，大幅减少数据迁移。

# 3.3 示例：负载均衡多台后端 Web 服务器

环境：192.168.80.100 代理服务器，192.168.80.101/102 后端 Apache。

# 部署后端 Apache
yum install httpd -y
echo "web1 192.168.80.101" > /var/www/html/index.html
systemctl enable --now httpd
systemctl disable --now firewalld
# 同理部署 192.168.80.102
# 代理服务器配置
http {
    upstream webserver {
        server 192.168.80.101:80 weight=1 fail_timeout=5s max_fails=3;   # 状态监测
        server 192.168.80.102:80 weight=1 fail_timeout=5s max_fails=3;
        # server 127.0.0.1:80 backup;    # 热备，所有服务器异常后自动上线
        keepalive 100;             # 每 worker 缓存的上游最大空闲保活连接
        keepalive_timeout 60s;     # 空闲连接超时
    }

    server {
        listen 80;
        server_name www.example.org;
        location / {
            index index.html index.php;
            root /apps/nginx/html;
        }
        location /web {
            index index.html;
            proxy_pass http://webserver/;        # 引用 upstream
            proxy_set_header Host $http_host;
            proxy_next_upstream error|timeout|invalid_header|http_500|http_502|http_503|http_504;
            proxy_http_version 1.1;              # 支持长连接
            proxy_set_header Connection "";      # 配合 keepalive 实现长连接
        }
    }
}
cat /etc/hosts    # 192.168.80.100 www.example.org
curl http://www.example.org/       # Nginx 192.168.80.100
curl http://www.example.org/web    # 轮询到后端 web1/web2
# 依次关闭后端服务，验证 max_fails/fail_timeout 状态监测与 backup 可用性

# 3.4 基于 Cookie 实现会话绑定

upstream websrvs {
    hash $cookie_hello consistent;    # hello 为 cookie 的 key
    server 192.168.80.101:80 weight=1 fail_timeout=5s max_fails=3;
    server 192.168.80.102:80 weight=1 fail_timeout=5s max_fails=3;
}
server {
    location /web {
        proxy_pass http://websrvs;
        proxy_set_header Host $http_host;
    }
}
curl -b'hello=example' http://www.example.org/web   # 同一 cookie 值始终调度到同一后端

# 3.5 实现 HTTPS 的负载均衡

方式一：两个 Server 块（HTTP 跳转 HTTPS + HTTPS 负载均衡）

upstream websrvs {
    server 192.168.80.101:80;
    server 192.168.80.102:80;
}
server {
    listen 80;
    server_name www.example.org;
    return 302 https://$server_name$request_uri;    # HTTP 跳转 HTTPS
}
server {
    listen 443 ssl http2;
    server_name www.example.org;
    ssl_certificate /apps/nginx/ssl/www.example.org.pem;
    ssl_certificate_key /apps/nginx/ssl/www.example.org.key;
    ssl_session_cache shared:sslcache:20m;
    ssl_session_timeout 10m;
    location / {
        proxy_pass http://websrvs;                 # 负载均衡转发
        proxy_set_header Host $http_host;
    }
}

方式二：一个 Server 块

upstream webservers {
    server 192.168.80.101;
    server 192.168.80.102;
}
server {
    listen 80;
    listen 443 ssl;
    server_name www.example.org;
    ssl_certificate /apps/nginx/ssl/www.example.org.pem;
    ssl_certificate_key /apps/nginx/ssl/www.example.org.key;
    location / {
        proxy_pass http://webservers;
        proxy_set_header host $http_host;
        index index.html;
        if ($scheme = http) {
            rewrite ^/(.*) https://$server_name/$1 redirect;   # HTTP 跳转 HTTPS
        }
    }
}

# 小结

本文覆盖 Nginx 反向代理与负载均衡的全部核心：正反向代理、四层/七层对比、proxy_pass 系列指令（重点掌握 proxy_pass 后带不带 / 的区别）、缓存、IP 透传、跨域解决、upstream 负载均衡（权重、max_fails/fail_timeout 健康检查、backup 热备、down 平滑下线）与调度算法（rr/wrr/ip_hash/least_conn/hash consistent）。下一篇将讲解四层代理（stream）与 FastCGI/PHP-FPM 集成。
