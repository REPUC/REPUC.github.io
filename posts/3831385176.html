# Nginx 基础与 Web 服务原理

本文是 Nginx 系列的开篇，先建立底层认知：了解 Web 服务的发展历程、Apache 与 Nginx 的差异、影响用户体验的因素，再深入 Linux 的 I/O 模型与零拷贝技术——这些是理解 Nginx 为何高性能的根基。

# 一、Web 服务基础

Nginx 可作为更强大的 Web 服务器，轻松超越 Apache，解决其 C10K（万级并发）问题，并能应对超过 100 万级别的并发请求。同时，Nginx 也可替代 LVS 作为调度服务器，克服 LVS 无法对后端服务器进行健康检查的劣势——Nginx 不仅实现了健康检查，还提供了访问调度与负载均衡功能。

# 1.1 互联网发展历程回顾

  • 1993 年 3 月，中国通过 64K 专线正式连入 Internet，成为我国接入互联网的第一根专线。
  • 1995 年马云创业并推出中国黄页；1999 年创建阿里巴巴；2003 年创立淘宝网；2004 年创立支付宝（蚂蚁金服旗下，含支付宝、余额宝、蚂蚁花呗、芝麻信用等子业务）。
  • 2009 年开始举办双十一购物狂欢节，历年成交额从 2009 年的 5000 万元，增长到 2020 年的 4982 亿元。
  • 2012 年淘宝商城更名为天猫；2014 年阿里巴巴集团于纽约证券交易所挂牌上市。

互联网的爆发式增长，对 Web 服务的并发能力提出了极高要求，这正是 Nginx 崛起的时代背景。

# 1.2 Web 服务介绍

Apache 是经典的 Web 服务端，由美国伊利诺伊大学香槟分校的国家超级计算机应用中心开发，经历了 1.X 和 2.X 两大版本，可通过编译安装实现特定功能。

Apache 的三种工作模型：

模型说明优点缺点
prefork预派生模式，一个主控制进程生成多个子进程，使用 select 模型，最大并发 1024，每个子进程一个独立线程响应请求稳定每个请求对应一个进程，占内存多、并发差，不适合高并发
worker多进程与多线程混合，控制进程启动多个子进程，每个子进程含固定线程处理请求比 prefork 占内存少，能处理更多请求keepalive 长连接下线程被长期占据，高并发时可能无可用线程
eventApache 2.4.X 起支持，事件驱动模型（epoll），每个进程响应多个请求单线程响应多请求，占内存少，高并发表现优，有专门线程管理 keepalive没有线程安全控制

Nginx 是高性能的 Web 服务端，由俄罗斯工程师为 rambler.ru 公司开发，2002 年开始，2004 年 10 月首次公开发布（0.1.0）。2019 年 3 月 F5 以约 6.7 亿美元收购 Nginx。Nginx 核心模块代码约 19.8 万行（含空格注释），是天猫、淘宝、京东、小米、网易、新浪等一线互联网公司都在使用或二次开发的 Web 服务器。

Nginx 的能力：作为 HTTP 服务器、反向代理服务器、邮件服务器，能快速响应静态网页请求，支持 FastCGI / SSL / Virtual Host / URL Rewrite / Gzip / HTTP Basic Auth，以及 HTTP 或 TCP 的负载均衡（1.9 版本以上且开启 stream 模块），并支持第三方功能扩展。

# 1.3 用户访问体验与性能

互联网存在用户速度体验的 1-3-10 原则：1 秒最优，1-3 秒较优，3-10 秒较慢，10 秒以上用户无法接受。用户放弃一个产品的代价很低——只是换一个 URL。

性能对用户行为的影响（行业研究数据）：

  • 全球最大搜索引擎：慢 500ms = 20% 用户放弃访问；
  • 全球最大电商亚马逊：慢 100ms = 1% 放弃交易；
  • 79% 的用户表示不太可能再次打开一个缓慢的网站；
  • 47% 的用户期望网页在 2 秒内加载；
  • 40% 的用户表示加载超过 3 秒就会放弃；
  • 页面加载延迟 1 秒可能导致转化损失 7%、浏览量减少 11%；
  • 8 秒定律：等待超过 8 秒，超过 30% 的用户放弃等待。

请珍惜每一毫秒的时间。

影响用户体验的因素：

  • 客户端：硬件配置（内存）、网络速率（带宽）、与服务端距离（CDN）；
  • 服务器：网络速率、硬件配置、架构设计、应用程序工作模式、并发数量、响应文件大小及数量（buffer cache）、I/O 压力。

# 二、服务端 I/O 流程

I/O 指 Input/Output，IOPS（Input/Output Per Second）即每秒的输入输出量（或读写次数），是衡量磁盘性能的主要指标之一。

一次完整的 I/O 是用户空间进程数据与内核空间内核数据报文的完整交换。由于内核空间与用户空间严格隔离，数据交换不能由用户进程直接调用内核内存，而需经历一次从内核内存 copy 到用户进程内存的过程。简言之，I/O 就是把数据从内核空间的内存复制到用户空间进程的内存。

Linux 的 I/O 读写（Linux 一切皆文件）：

  • 文件 I/O：对普通文件的读写；
  • 磁盘 I/O：对 Block 文件的读写；
  • 网络 I/O：对 socket 文件的读写。

磁盘 I/O：进程向内核发起系统调用请求磁盘资源（如 html 文件、图片），内核通过驱动程序将目标文件加载到内核内存，加载完成后将数据从内核内存复制给进程内存；大数据量时需要等待时间。

网络 I/O：网络通信就是网络协议栈到用户空间进程的 IO。处理过程：

1-3. 获取请求数据：客户端与服务器建立连接发出请求，服务器接受请求；
4. 构建响应：服务器接收完请求，在用户空间处理，直到构建响应完成；
5-7. 返回数据：服务器将响应通过内核空间的网络 I/O 发还客户端。

不论磁盘和网络 I/O，每次 I/O 都经历两个阶段：

  • 第一步：将数据从文件加载至内核内存空间（缓冲区），等待数据准备完成，时间较长；
  • 第二步：将数据从内核缓冲区复制到用户空间进程内存，时间较短。

# 三、I/O 模型

# 3.1 相关概念

同步/异步：关注消息通信机制，即调用者在等待处理结果时，被调用者是否提供完成状态的通知。

  • 同步（synchronous）：被调用者不提供事件处理结果的通知，需调用者主动询问是否完成。
  • 异步（asynchronous）：被调用者通过状态、通知或回调机制主动通知调用者其运行状态。

阻塞/非阻塞：关注调用者在等待结果返回之前所处的状态。

  • 阻塞（blocking）：IO 操作需彻底完成后才返回用户空间，结果返回前调用者被挂起，干不了别的事情。
  • 非阻塞（nonblocking）：IO 操作被调用后立即返回一个状态值，无需等 IO 彻底完成，结果返回前调用者不被挂起，可以去做别的事。

# 3.2 五种网络 I/O 模型

五种 IO 模型：阻塞型、非阻塞型、IO 多路复用型、信号驱动 IO 型、异步 IO 型。

# （1）阻塞型 I/O（blocking IO）

类比钓鱼：程序必须时刻盯着鱼竿（阻塞型），等待鱼上钩，数据准备好才能"收杆"继续处理，期间无法做其他事。

用户线程通过系统调用 read 发起 I/O 读操作，由用户空间转到内核空间。内核等到数据包到达后，将数据拷贝到用户空间，完成 read。用户需等待 read 将数据读到 buffer 后才处理。整个 I/O 请求过程中用户线程被阻塞，不能做任何事，CPU 利用率不够。

  • 优点：程序简单，阻塞等待期间进程/线程挂起，基本不占 CPU。
  • 缺点：每个连接需独立进程/线程处理，并发量大时内存、线程切换开销大。Apache 的 prefork 即此模式，用的较少。

# （2）非阻塞型 I/O（nonblocking IO）

类比钓鱼：程序无需始终盯着鱼竿，可暂时离开做其他事（非阻塞），但需时不时回来检查是否有鱼上钩。

用户线程发起 IO 请求时立即返回，但未读到数据，需不断发起 IO 请求直到数据到达。即"轮询"机制存在两个问题：大量文件描述符都要等就得一个一个 read，带来大量 Context Switch（read 是系统调用，每次调用都在用户态和核心态间切换）；轮询时间不好把握（设太长响应延迟大，设太短过于频繁重试，干耗 CPU）。一般很少直接使用，而是在其他 IO 模型中使用非阻塞特性。

设置连接为非阻塞时，系统调用 recvfrom 没有数据返回时内核立即返回 EWOULDBLOCK 错误，而不一直阻塞。这种循环调用 recvfrom 称为轮询 polling，往往耗费大量 CPU，实际使用很少。

# （3）信号驱动式 I/O（signal-driven IO）

类比智能鱼竿：无需时刻守着，鱼上钩时自动发送信号（信号驱动式），可专注其他事，发现后再主动"收杆"。

用户首先注册一个处理 IO 信号的信号处理函数，数据未准备好时进程不阻塞，数据准备好时收到 SIGIO 信号，调用信号处理函数，在其中调用 IO 函数操作数据，完成后通知用户。通过系统调用 sigaction 注册信号处理回调函数，调用立即返回，主程序继续执行；当内核数据就绪时产生 SIGIO 信号，回调函数中调用 recvfrom 获取数据。

  • 优点：等待数据期间进程不被阻塞，主程序可继续执行，提高资源利用率。
  • 缺点：大量 IO 操作时可能因信号队列溢出导致无法通知。

# （4）多路复用 I/O（I/O multiplexing）

类比：只需监督一个 select 函数，由它同时操作多根鱼竿。

多路复用指一个线程可同时（实际是交替并发完成）监控和处理多个文件描述符对应的 IO，即复用同一个线程。线程调用内核的 select、poll、epoll 等系统调用实现多路复用。其基本原理是这些函数不断轮询负责的所有 socket，当某个 socket 有数据到达就通知用户进程。用户进程调用 select 后整个进程被 block，内核"监视"所有 select 负责的 socket，任一 socket 数据准备好 select 就返回，用户进程再调用 read 将数据从内核拷贝到用户进程。

Apache prefork 是 select 模式，worker 是 poll 模式。

  • 优点：基于一个阻塞对象同时在多个描述符上等待就绪，而非多个线程（每个描述符一个线程），大大节省系统资源。
  • 缺点：连接数较少时效率比多线程+阻塞 IO 低，延迟更大（单个连接需 2 次系统调用）。

适用场合：客户端处理多个描述符；服务器既要处理监听套接字又要处理已连接套接字；服务器同时处理 TCP 和 UDP；服务器处理多个服务或协议。

# （5）异步 I/O（asynchronous IO）

类比全自动化鱼竿：可完全离开做其他事，鱼竿自动钓鱼，无需守着（异步）。但限制是一个人只能用一根鱼竿，效率相对低；多路复用能同时处理多个"鱼竿"，大幅提高效率。

数据等待和搬迁都不由当前进程/线程处理，调用系统函数后直接返回继续执行，用户进程不被阻塞，数据在用户空间准备就绪后以状态、通知或回调告知用户处理。用户进程进行 aio_read 调用后，无论内核数据是否准备好都直接返回，用户进程可做别的事，socket 数据准备好后内核直接复制数据给进程并发通知。IO 两个阶段进程都是非阻塞的。

与信号驱动 IO 最大区别：信号驱动是内核通知用户进程何时开始一个 I/O 操作，异步 IO 是内核通知用户进程 I/O 操作何时完成。

  • 优点：能充分利用 DMA 特性，让 I/O 操作与计算重叠。
  • 缺点：实现真正的异步 IO 操作系统需大量工作。Windows 通过 IOCP 实现，Linux 2.6 才引入 AIO 但不完善，因此 Linux 下高并发网络编程以 IO 复用模型 + 多线程 架构基本可满足需求。开源异步 IO 库有 libevent、libev、libuv。

# 3.3 五种 IO 模型对比

五种模型中，越往后阻塞越少，理论效率最优。前四种属于同步 IO（真正的 IO 操作 recvfrom 会阻塞进程/线程），只有异步 IO 才与 POSIX 定义的异步 IO 相匹配。

# 3.4 I/O 的具体实现方式

Nginx 在不同操作系统实现不同的事件驱动模型，主要实现方式：

  1. select：Linux 和 Windows 都基本支持，接口定义基本相同，最大并发限制 1024，是最早期的事件驱动模型。
  2. poll：Linux 基本驱动模型，Windows 不支持，是 select 的升级版，取消了最大并发限制。
  3. epoll：Nginx 支持的最高性能事件驱动库之一，是 poll 的升级版。处理方式是创建待处理事件列表发给内核，返回时轮询检查该表判断事件是否发生。epoll 支持一个进程打开的最大事件描述符上限是系统可打开文件的最大数，I/O 效率不随描述符数目增加而线性下降（只对内核上报的"活跃"描述符操作）。
  4. kqueue：BSD 系列平台的高效事件驱动模型（FreeBSD 4.1+、OpenBSD 2.0+、NetBSD+、Mac OS X），是 poll 的变种。
  5. Iocp：Windows 上的实现方式，对应第 5 种（异步 IO）模型。
  6. rtsig：不常用事件驱动，最大队列 1024。
  7. /dev/poll：Unix 衍生平台（Solaris、HP/UX），使用虚拟的 /dev/poll 设备，通过 ioctl() 获取事件通知。
  8. eventport：Sun 公司开发 Solaris 时提出，Solaris 10+ 版本，防止内核崩溃。

核心结论：select、poll、epoll 都是 IO 多路复用机制，本质上都是同步 IO（读写事件就绪后需自己负责读写，过程阻塞）；而异步 IO 无需自己负责读写，由实现负责把数据从内核拷贝到用户空间。

# select / poll / epoll 对比

select（POSIX 规定，几乎所有平台支持，跨平台性好）：

  • 缺点：单个进程监视 fd 数量有最大限制（Linux 上默认 1024，修改需重新编译内核，且会降低效率）；对 socket 线性扫描（轮询），效率低；采用内存拷贝方法传递 FD 消息，大量 fd 时复制开销大。

poll（本质与 select 无区别，将用户传入数组拷贝到内核空间查询每个 fd 状态）：

  • 无最大连接数限制（基于链表存储）；大量 fd 数组整体复制于用户态和内核地址空间之间，不管复制是否有意义。
  • 特点：水平触发（报告 fd 后未处理，下次 poll 仍会报告）；select 是边缘触发（只通知一次）。

epoll（Linux 2.6 引入，select/poll 的增强版本，支持水平触发 LT 和边缘触发 ET，最大特点是边缘触发，只告诉进程哪些 fd 刚变为就绪态，且只通知一次）：

  • 使用"事件"就绪通知方式，通过 epoll_ctl 注册 fd，fd 就绪时内核采用类似 callback 的回调机制激活，epoll_wait 收到通知。
  • 优点：无最大并发连接限制（能打开的 FD 上限远大于 1024，1G 内存能监听约 10 万个端口，见 /proc/sys/fs/file-max）；效率提升（非轮询，不随 FD 数增加而效率下降，只管理"活跃"连接，与连接总数无关）；利用 mmap 加速与内核空间的消息传递，减少复制开销。

Nginx 利用 epoll 实现 IO 多路复用：将连接信息和事件放到队列中，一次放到文件事件分派器，事件分派器将事件分发给事件处理器。Nginx 跑在单线程中，所有操作按顺序线性执行，读写等待用户输入输出都是阻塞的，I/O 操作一般不能直接返回，某一文件 I/O 阻塞会导致整个进程无法对其他客户提供服务——I/O 多路复用正是为解决此问题而生。多个连接共用一个阻塞对象，应用程序只需在一个阻塞对象上等待，无需阻塞等待所有连接，当某条连接有新数据可处理时操作系统通知应用程序，线程从阻塞状态返回开始业务处理。

总结：Nginx 性能强大的原因在于灵活运用多路复用 I/O 模型中的 epoll 机制，使其能高效处理大量并发连接，最大化资源利用率。epoll 相比 select 的优势：只读取就绪的 fd 而非扫描全部、基于事件就绪通知、减少进程切换与遍历循环及内存拷贝（活跃连接只占总并发的很小一部分）。

# I/O 选择

  • 完全跨平台：可用 select、poll，但性能较差；
  • 针对不同操作系统自行选择最优技术：Linux 选 epoll，Mac 选 kqueue，Windows 选 IOCP，提高 IO 处理性能。

文件最大并发连接数与内存的关系：内存为 1G 时 /proc/sys/fs/file-max 约 92953；内存为 2G 时约 195920。单个进程监视的 fd 最大数量由 FD_SETSIZE 宏决定（默认 1024，见 linux/include/uapi/linux/posix_types.h）。

# 四、零拷贝

# 4.1 零拷贝介绍

传统 Linux I/O 的问题：传统标准 I/O 接口（read、write）基于数据拷贝，数据经 copy_to_user / copy_from_user。好处是通过中间缓存减少磁盘 I/O，坏处是大量数据拷贝、用户态与内核态频繁切换消耗大量 CPU，严重影响传输性能。统计表明，Linux 协议栈中数据包在内核态与用户态间拷贝所用时间，甚至占到数据包整个处理流程时间的 57.1%。

什么是零拷贝：传统 IO 性能较差，故提出零拷贝机制提升效率。零拷贝通过尽量避免拷贝操作缓解 CPU 压力。零拷贝并非真正做到"0"拷贝，更多是一种思想，基于此思想的众多优化技术统称为零拷贝——减少复制操作。

# 4.2 零拷贝相关技术

# （1）MMAP 零拷贝技术（Memory Mapping）

MMAP 减少了两次复制，同时减少内核空间与用户空间的上下文切换。传统 IO 中从内核缓冲区到用户缓冲区有一次 CPU 拷贝，从用户缓冲区到 Socket 缓冲区又有一次 CPU 拷贝；mmap 则一步到位，直接基于 CPU 将内核缓冲区数据拷贝到 Socket 缓冲区。

mmap 直接将磁盘文件数据映射到内核缓冲区（基于 DMA 拷贝），用户缓冲区与内核缓冲区共享一块映射数据，建立共享映射后无需从内核缓冲区拷贝到用户缓冲区。mmap() 系统调用使进程通过映射同一普通文件实现共享内存，文件映射到进程地址空间后，进程可像访问普通内存一样访问文件，系统自动回写脏页面到文件磁盘，无需再调用 read/write。内存映射减少数据在用户空间和内核空间间的拷贝，适合大量数据传输。

相比普通 read 系统调用，mmap 少一次 copy（read 时进程无法直接访问 kernel space，read 返回前内核需将数据复制到进程 buffer；mmap 后进程可直接访问 mmap 的数据 page cache）。

# （2）SendFile 零拷贝技术

Linux 提供 sendFile 函数实现零拷贝。在 Linux 中，sendfile 是将读到内核空间的数据转到 socket buffer 进行网络发送，适合大文件传输。
