# Nginx 常见功能模块

本文讲解 Nginx 生产中常用的功能模块：状态页、变量、自定义访问日志、压缩、HTTPS 加密、Rewrite 重写（重点）、防盗链。这些模块让 Nginx 从单纯的 Web 服务器，进化为功能完整的生产级反向代理与安全网关。

# 一、Nginx 状态页

通过 ngx_http_stub_status_module 模块提供 nginx 的运行状态信息，用于监控。

状态页配置：

server {
    listen 80;
    server_name status.example.org;
    location /nginx_status {
        stub_status;
        allow 192.168.1.0/24;   # 允许访问的网段
        deny all;               # 其他拒绝
    }
}

状态页输出内容：

Active connections: 291
server accepts handled requests
16630948 16630948 31070465
Reading: 6  Writing: 1796  Waiting: 142
  • Active connections：当前活跃连接数；
  • server accepts handled requests：accepts 总数、handled 总数、requests 总数；
  • Reading：正在读取请求头；Writing：正在写响应；Waiting：空闲等待。

# 二、Nginx 变量使用

Nginx 提供大量内建变量，可在配置中引用，用于日志、判断、转发等。常见变量：

变量说明
$remote_addr客户端 IP
$remote_user客户端用户（基本认证）
$time_local本地时间
$request请求行（方法+URI+协议）
$status响应状态码
$body_bytes_sent发送的响应体字节数
$http_refererReferer 请求头
$http_user_agentUser-Agent 请求头
$http_x_forwarded_forX-Forwarded-For 请求头
$scheme请求协议（http/https）
$server_nameserver_name
$server_addrserver 地址
$server_portserver 端口
$request_uri原始请求 URI（含参数）
$document_root当前 location 的 root 值
$fastcgi_script_name请求的脚本文件名
$upstream_cache_status上游缓存状态（HIT/MISS）

可通过 set 指令定义自定义变量：set $variable value;。

# 三、Nginx 自定义访问日志

通过 log_format 定义日志格式，access_log 指定日志文件与格式。

http {
    log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent" "$http_x_forwarded_for"';
    access_log  /apps/nginx/logs/access.log  main;
}

按站点自定义日志：

server {
    server_name www.example.org;
    error_log /apps/nginx/logs/example.org_error.log notice;
    access_log /apps/nginx/logs/example.org_access.log main;
    ...
}

# 四、Nginx 压缩功能

通过 gzip 模块压缩响应，减少传输数据量。

http {
    gzip on;                       # 开启压缩
    gzip_min_length 1k;            # 最小压缩长度
    gzip_comp_level 4;             # 压缩级别（1-9）
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript;
    # 指定压缩的 MIME 类型
}

gzip_static 模块可对预先压缩的 .gz 文件直接发送，无需实时压缩。

# 五、HTTPS 加密

# 5.1 HTTPS 原理

Web 网站登录页通常使用 HTTPS 加密传输，保障数据安全。HTTPS = HTTP + SSL/TLS，在 HTTP 上加一层加密模块，服务端与客户端信息传输都通过 TLS 加密。

HTTPS 实现过程：

  1. 客户端发起 HTTPS 请求：访问 https 地址（一般 443 端口）；
  2. 服务端配置证书：必须有一套证书（向组织申请或自签）。证书即公钥+私钥，如同锁和钥匙——把公钥（锁）送给别人锁箱子，别人不知内容也打不开，只有私钥（钥匙）能开；
  3. 传送证书：服务端给客户端传递证书（公钥），含颁发机构、过期时间等；
  4. 客户端解析证书：客户端验证公钥有效性（颁发机构、过期时间，需客户端预存 CA 证书验证），异常则弹出警告；无异常则生成随机值，用证书公钥加密该随机值；
  5. 传送加密数据：将加密后的随机值传给服务器，让服务器得到随机值，后续通信用该值加密解密；
  6. 服务端解密：服务端用私钥解密得到随机值，再通过该值进行对称加密（信息与私钥算法混合，只有知道私钥才能获取内容）；
  7. 传输加密信息：服务端将加密数据传给客户端；
  8. 客户端解密：客户端用私钥解密还原原数据。即使第三方截获数据也无法得知内容。

# 5.2 证书获取

方式一：申请免费 SSL 证书（如云厂商）

在云平台申请免费 SSL 证书（二级域名需为账号所拥有的域名），签发成功后域名控制台自动添加 DNS 解析记录，下载证书压缩包，将服务器证书与上级 CA 证书分别粘贴至 xxx.crt/xxx.cer 文件。

方式二：Shell 脚本生成私有证书（自签名）

#!/bin/bash
SITE_NAME=www.example.org
CA_SUBJECT="/O=example/CN=ca.example.org"
SUBJECT="/C=CN/ST=hubei/L=wuhan/O=example/CN=$SITE_NAME"
SERIAL=34
EXPIRE=202002
FILE=$SITE_NAME

# 生成自签名 CA 证书
openssl req -x509 -newkey rsa:2048 -subj $CA_SUBJECT -keyout ca.key -nodes -days 202002 -out ca.crt
# 生成 key 和 csr
openssl req -newkey rsa:2048 -nodes -keyout ${FILE}.key -subj $SUBJECT -out ${FILE}.csr
# 签发证书
openssl x509 -req -in ${FILE}.csr -CA ca.crt -CAkey ca.key -set_serial $SERIAL -days $EXPIRE -out ${FILE}.crt
chmod 600 ${FILE}.key ca.key
bash certificate.sh

自签名私有证书不被系统信任，Windows 中无法找到颁发机构。

# 5.3 HTTPS 配置参数

Nginx 的 HTTPS 功能基于 ngx_http_ssl_module 模块。yum 安装默认开启；编译安装需 --with-http_ssl_module。

ssl on | off;              # 是否启用 ssl（1.15.0 废弃，用 listen [ssl] 替代）
listen 443 ssl http2;       # 监听 443，启用 ssl 和 http2

ssl_certificate /path/to/file;        # 证书文件（含服务器证书和 CA，一般 crt）
ssl_certificate_key /path/to/file;    # 私钥文件（一般 key）

ssl_protocols [SSLv2] [SSLv3] [TLSv1] [TLSv1.1] [TLSv1.2];   # 支持的协议版本，默认后三个，现代浏览器已不支持 TLS1.0/1.1

ssl_session_cache off|none|[builtin[:size]] [shared:name:size];  # ssl 缓存
# off 关闭；none 通知客户端支持但不实际支持；builtin 内建缓存（每 worker 私有，可能内存碎片）；shared 共享缓存（需定义名称和大小，1M 存约 4000 会话，多虚拟主机可用同名）

ssl_session_timeout time;   # 客户端复用 ssl 会话缓存的有效时长，默认 5 分钟

官方性能优化建议（减少处理器负载）：worker 进程数等于处理器数、启用 keep-alive、启用共享会话缓存、禁用内建缓存、适当增加会话生命周期。

worker_processes auto;
http {
   server {
       listen              443 ssl http2;
       keepalive_timeout   70;
       ssl_protocols       TLSv1 TLSv1.1 TLSv1.2;
       ssl_ciphers         AES128-SHA:AES256-SHA:RC4-SHA:DES-CBC3-SHA:RC4-MD5;
       ssl_certificate     /apps/nginx/conf/cert.pem;
       ssl_certificate_key /apps/nginx/conf/cert.key;
       ssl_session_cache   shared:SSL:10m;
       ssl_session_timeout 10m;
   }
}

# 5.4 自签名证书生成

cd /apps/nginx/
mkdir certs && cd certs/

# 自签名 CA 证书
openssl req -newkey rsa:4096 -nodes -sha256 -keyout ca.key -x509 -days 3650 -out ca.crt
# Country Name: CN；State: BeiJing；Organization: example.Ltd；Common Name: ca.example.org

# 生成 key 和 csr
openssl req -newkey rsa:4096 -nodes -sha256 -keyout www.example.org.key -out www.example.org.csr

# 签发证书
openssl x509 -req -days 3650 -in www.example.org.csr -CA ca.crt -CAkey ca.key -CAcreateserial -out www.example.org.crt

# 验证证书
openssl x509 -in www.example.org.crt -noout -text

# 合并 CA 和服务器证书（注意：服务器证书在前，CA 在后，否则出错）
cat www.example.org.crt ca.crt > www.example.org.pem

# 5.5 HTTPS 配置【常用】

利用公网证书：

server {
    listen 80;
    listen 443 ssl http2;              # 监听 443
    server_name www.example.cn;        # 站点域名
    ssl_certificate /apps/nginx/certs/www.example.cn.pem;      # 证书路径
    ssl_certificate_key /apps/nginx/certs/www.example.cn.key;  # 私钥路径
    ssl_session_cache shared:sslcache:20m;                      # 会话缓存，提高性能
    ssl_session_timeout 10m;                                     # 会话超时
    root /data/nginx/html/example;                               # 站点根目录
}

利用私有证书：

server {
    listen 80;
    listen 443 ssl http2;
    server_name www.example.org;
    ssl_certificate /apps/nginx/certs/www.example.org.pem;
    ssl_certificate_key /apps/nginx/certs/www.example.org.key;
    ssl_session_cache shared:sslcache:20m;
    ssl_session_timeout 10m;
    root /data/nginx/html/example_org;
}
# 合并生成 pem 证书（服务器证书在前，CA 在后）
cat www.example.org.crt > /apps/nginx/certs/www.example.org.pem
cat ca.crt >> /apps/nginx/certs/www.example.org.pem
mv www.example.org.key /apps/nginx/certs/

私有证书默认不被系统信任，浏览器会警告，点击"高级 >> 继续访问"即可。curl 访问私有证书站点会报 SSL 错误：

  • 方法一：忽略验证 curl -k https://www.example.org；
  • 方法二：将私有 CA 证书导入 Linux 系统 CA 信任列表 cat www.example.org.pem >> /etc/pki/tls/certs/ca-bundle.crt。

Windows 主机想信任私有证书：浏览器设置 > 管理证书 > 受信任的根证书颁发机构 > 导入（需导入私有 CA 服务器证书）。

# 5.6 实现多域名 HTTPS（SNI）

Nginx 基于 SNI（Server Name Indication）实现单 IP 多域名多证书：客户端在建立 SSL 连接前先发送要访问的域名（Hostname），服务器据此返回合适的证书。

# 制作 key 和 csr，签名，合并证书（同上，针对 m.example.org）
server {
    listen 80 default_server;
    server_name m.example.org;
    rewrite ^(.*)$ https://$server_name$1 permanent;   # HTTP 跳转 HTTPS
}
server {
    listen 443 ssl http2;
    server_name m.example.org;
    ssl_certificate /apps/nginx/certs/m.example.org.pem;
    ssl_certificate_key /apps/nginx/certs/m.example.org.key;
    ssl_session_cache shared:sslcache:20m;
    ssl_session_timeout 10m;
    location / { root "/data/nginx/html/mobile"; }
    location /mobile_status { stub_status; }
}

# 5.7 实现 HSTS

HSTS（HTTP Strict Transport Security）强制浏览器使用 HTTPS，防止降级攻击。

server {
    listen 443 ssl http2;
    server_name www.example.org;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    location / {
        if ( $scheme = http ) {
            rewrite ^/(.*)$ https://www.example.org/$1 redirect;
        }
    }
}

# 六、升级 OpenSSL 版本

OpenSSL 广泛用于实现 TLS 协议。心脏出血（Heartbleed）漏洞于 2014 年 4 月披露，源于 TLS 心跳扩展未做边界检查，属缓冲区过读，可读取超出允许范围的数据，服务器和客户端均可能受攻击。

升级 OpenSSL 解决漏洞：

# 准备 OpenSSL 源码包
cd /usr/local/src
wget https://www.openssl.org/source/openssl-1.1.1h.tar.gz
tar xvf openssl-1.1.1h.tar.gz

# 编译安装 Nginx 并指定新版本 OpenSSL 路径
cd /usr/local/src/nginx-1.22.1
nginx -V                       # 查看旧配置选项
# 完整输入原 configure 内容，末尾加 --with-openssl=/usr/local/src/openssl-1.1.1h
./configure --prefix=/apps/nginx --user=nginx --group=nginx --with-http_ssl_module ... --with-openssl=/usr/local/src/openssl-1.1.1h
make && make install
nginx -t && systemctl restart nginx
nginx -V                       # 验证 OpenSSL 版本已更新

Ubuntu22.04 可编译 OpenSSL 3.0.7，但较低版本 nginx 不支持 OpenSSL 3.X，只支持 1.X。

# 七、Rewrite 模块【常用：至关重要】

Nginx 利用 ngx_http_rewrite_module 模块解析和处理 rewrite 请求，依靠 PCRE（perl compatible regular expression），编译前需安装 PCRE 库。

rewrite 作用：实现 URL 重写，如网站结构改变后无需客户端修改书签或其他网站链接，仍可访问原有内容，还能提高网站安全性。

示例场景：

  • 访问 http://www.58.com/bj → 跳转 http://beijing.58.com
  • 访问 http://www.360buy.com → 跳转 http://www.jd.com/

# 7.1 ngx_http_rewrite_module 模块指令

# （1）if 指令

用于条件匹配判断，根据结果选择不同配置，可配置在 server 或 location 块。Nginx 的 if 语法仅能做单次判断，不支持 if/else、if/elif 多重判断。

语法：if (condition) { ... }，Context: server, location。

匹配符号：

符号说明
=比较变量和字符串是否相等
!=比较是否不相等
~区分大小写正则匹配
!~区分大小写，不匹配为真
~*不区分大小写正则匹配
!~*不区分大小写，不匹配为真
-f / !-f请求文件是否存在/不存在
-d / !-d请求目录是否存在/不存在
-x / !-x文件是否可执行/不可执行
-e / !-e文件或目录是否存在（含文件、目录、软链接）

注意：$ 变量值为空字符串或 0 时 if 认为条件为 false，其他为 true。

官方示例：

if ($http_user_agent ~ MSIE) {           # User-Agent 含 MSIE
    rewrite ^(.*)$ /msie/$1 break;
}
if ($http_cookie ~* "id=([^;]+)(?:;|$)") {
    set $id $1;
}
if ($request_method = POST) {
    return 405;
}
if ($slow) {
    limit_rate 10k;                      # 限速 10k
}
if ($invalid_referer) {
    return 403;
}

范例：拒绝 curl 访问

location / {
    if ($http_user_agent ~ curl) {
        return 403;
    }
    root /data/nginx/html/pc;
}

# （2）set 指令

指定 key 并定义变量，value 可为 text、变量或组合。

语法：set $variable value;，Context: server, location, if。

location /set {
    set $name example;
    echo $name;
    set $my_port $server_port;
    echo $my_port;
}

# 根据网络判断是否限速
location /set {
    set $slow 1;            # 0 不限速，非 0 限速
    if ($slow) {
        limit_rate 10k;
    }
}

# （3）break 指令

中断当前相同作用域（location）中的其他配置。位于它前面的配置生效，后面的 ngx_http_rewrite_module 指令不再执行，回到上一层作用域继续读取。注意：break 在 location 块中，后续指令仍会执行，只是不执行 rewrite 模块的指令，其他指令仍执行。

语法：break;，Context: server, location, if。

location /break {
    default_type text/html;
    set $name example;
    echo "break_before:name=$name";
    break;                    # location 中 break 后面指令还会执行（非 rewrite 指令）
    set $my_port $server_port;    # 中断：该行不执行（rewrite 模块指令）
    echo "break_after:my_port=$my_port";
    echo "break_after:name=$name";
}
# 测试：break_before:name=example；break_after:my_port=；break_after:name=example

# （4）return 指令【常用】

完成对请求的处理，直接向客户端返回响应状态码。可指定重定向 URL（301/302）、指定提示文本（403/500）、重定向跳转 HTTPS 等。return 后所有配置不再执行。

语法：

return code;              # 返回指定 HTTP 状态码
return code [text];       # 返回状态码及响应体内容（可调变量，text 有空格需引号）
return code URL;          # 返回状态码 URL
return URL;               # 302 跳转（URL 必须完整，含 scheme）

Context: server, location, if。

范例：返回状态码与文本

location / {
    if ( $scheme = http ){
        return 500 "service error";    # 返回状态码和文本
        echo "if-----> $scheme";       # return 后不再执行
    }
    if ( $scheme = https ){
        echo "if ----> $scheme";
    }
}
# curl http:// 返回 500；curl https:// 正常返回

范例：防压测工具

if ( $http_user_agent ~* "Wget|apachebench" ) {
    set $user_agent_deny 1;
}
if ( $user_agent_deny =1 ) {
    return 403;
}

范例：判断请求并重定向

location / {
    if ($http_user_agent ~ curl) {
        return http://www.baidu.com;    # 302 临时重定向（默认）
    }
}
# return URL 不添加响应码默认 302 临时重定向；301 永久重定向

# 7.2 rewrite 指令【重点】

通过正则表达式匹配改变 URI，可存在多个指令按顺序匹配。rewrite 针对用户请求的 URL/URI 做处理。

语法：rewrite regex replacement [flag];，Context: server, location, if。

rewrite 将 URI 基于 regex 检查，匹配时替换为新 URI。注意：同一级配置块中多个 rewrite 规则自下而上逐个检查，替换后会重新一轮替换检查（隐含循环，不超过 10 次，超过返回 500）。[flag] 控制循环机制。替换后的 URL 以 http:// 或 https:// 开头时，直接以重定向返回（永久重定向 301）。

正则表达式格式：

符号说明
.匹配除换行符外任意字符
\w匹配字母/数字/下划线/汉字
\s匹配任意空白符
\d匹配数字，等同 [0-9]
\b匹配单词开始或结束
^ / $匹配字符串开始/结束
* / + / ?重复 0+/1+/0或1 次
(n) / {n,} / {n,m}重复 n/n 以上/n 到 m 次
*? +? ??贪婪匹配的非贪婪形式
\W \S \D \B匹配非字母数字等的字符
[^x]匹配除 x 外任意字符

官方示例：

server {
    rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 last;
    rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra last;
    return 403;
}
# 若放在 location /download/ 内，last 应换为 break，否则会循环 10 次返回 500
location /download/ {
    rewrite ^(/download/.*)/media/(.*)\..*$ $1/mp3/$2.mp3 break;
    rewrite ^(/download/.*)/audio/(.*)\..*$ $1/mp3/$2.ra break;
    return 403;
}
# 替换串末尾加 ? 可避免附加原请求参数
rewrite ^/users/(.*)$ /show?user=$1? last;

# rewrite flag 使用介绍

rewrite 有四种 flag：redirect（临时重定向 302）、permanent（永久重定向 301）、break、last。前两种是跳转型（客户端浏览器重新对新地址请求，地址信息变化），后两种是代理型（服务器内部跳转，客户端地址不变）。

flag说明
redirect临时重定向，重写后以 302 返回新 URL，客户端重新请求（用相对路径或 http/https 开头）
permanent永久重定向，重写后以 301 返回新 URL，客户端重新请求
break重写后停止当前 location 后续重写操作，跳转至重写规则之后的其他配置，结束循环（建议在 location 中使用，适用于一次重写）
last重写后停止当前 location 后续重写，对新 URL 启动新一轮重写检查（不建议在 location 中使用，适用于多次重写，注意避免超过 10 次及死循环）

测试代码：

server {
    listen 80;
    server_name www.example.org;
    root /data/site;
    location / {
        rewrite /1.html /2.html;    # 无 flag，会继续执行后面的 rewrite
        rewrite /2.html /3.html;
    }
    location /2.html {
        rewrite /2.html /a.html;
    }
    location /3.html {
        rewrite /3.html /b.html;
    }
}
# 请求 /1.html 最终访问 /b.html；请求 /2.html 最终访问 /a.html

# break 与 last 区别（重点）

  • break：遇到后，本 location 后续指令与其他 location 的所有指令都不执行。
location / {
    rewrite /1.html /2.html break;    # 后面有 rewrite 的其他指令通通不执行
    rewrite /2.html /3.html;
}
# 请求 /1.html 最终访问 /2.html
  • last：遇到后，本 location 里后续规则不执行，但重写后的 URL 会再次从头匹配所有 location（含本 location），哪个先匹配执行哪个，可能造成死循环 500。
location / {
    rewrite /1.html /2.html last;
    rewrite /2.html /3.html;
}
# 请求 /1.html 最终访问 /a.html
# 死循环示例：rewrite /1.html /2.html last; rewrite /2.html /1.html last; → 500

break 和 last 都属服务器内部跳转，客户端无感知（地址不变）。

# 基于 rewrite 实现永久与临时重定向

return 与 rewrite 的区别：

  • return：访问 www.example.org/1.html、/2.html 都返回主站点（不管 URL 内容），可用 return 301 https://$server_name$request_uri; 保留 URI；
  • rewrite：访问 www.example.org/1.html 返回 目标站点/1.html，访问 /2.html 返回 目标站点/2.html（更合理，保留具体路径）。
# 将源域名 www.example.org 永久重定向到目标站点
server {
    listen 80;
    server_name www.example.org;
    location / {
        root /data/nginx/html/pc;
        index index.html;
        rewrite / https://target.example.com permanent;   # permanent 永久重定向
        # rewrite / https://target.example.com redirect;  # redirect 临时重定向
    }
}

301 永久重定向：域名永远跳转至新域名，跳转记录缓存到客户端浏览器，会缓存 DNS 解析记录，即使 nginx 无法访问浏览器也用缓存重定向（如京东 www.360buy.com → www.jd.com）。

302 临时重定向：告诉浏览器域名非固定重定向，后期可能更改，浏览器不缓存 DNS 解析记录，nginx 无法访问时浏览器不能利用缓存，导致重定向失败。

# 7.3 案例

# （1）自动跳转 HTTPS【常用】

范例 1：两个 Server 块实现自动跳转 HTTPS

server {
    listen 80;
    server_name www.example.org;
    return 302 https://$server_name$request_uri;    # 自动跳转 HTTPS
}
server {
    listen 443 ssl http2;
    server_name www.example.org;
    ssl_certificate /apps/nginx/certs/www.example.org.pem;
    ssl_certificate_key /apps/nginx/certs/www.example.org.key;
    ssl_session_cache shared:sslcache:20m;
    ssl_session_timeout 10m;
    location / { root /data/nginx/html/example_org; }
}
# 访问 http://www.example.org/1.html → https://www.example.org/1.html

范例 2：一个 Server 块 + 特定 URL 实现自动跳转 HTTPS

server {
    listen 80;
    listen 443 ssl;
    server_name www.example.org;
    ssl_certificate /apps/nginx/certs/www.example.org.pem;
    ssl_certificate_key /apps/nginx/certs/www.example.org.key;
    ssl_session_cache shared:sslcache:20m;
    ssl_session_timeout 10m;

    location / {    # 全站跳转
        root /data/nginx/html/example_org;
        index index.html;
        if ($scheme = http ){                                  # 不加 if 条件会导致死循环
            return https://www.example.org$request_uri;        # 302 临时重定向
            # return 302 https://$server_name$request_uri;
            # rewrite ^/(.*) https://$host/$1 permanent;      # 301 永久
        }
    }
    location /login {                                       # 特定 URL 跳转 HTTPS
        if ($scheme = http ){
            rewrite ^/(.*) https://$host/$1 redirect;        # 302
        }
    }
}

死循环排查：规则匹配问题导致陷入死循环时，curl 会报 Maximum (50) redirects followed。

# （2）判断文件是否存在【常用】

访问错误 URL 时重定向至官网首页。

server {
    listen 80;
    server_name www.example.org;
    location / {
        root /data/nginx/html/pc;
        index index.html;
        if (!-e $request_filename) {
            rewrite .* http://$server_name/index.html;   # 客户端 302 跳转
            # rewrite .* /index.html;                     # 服务器内部跳转
        }
    }
}
# 访问不存在的页面 http://www.example.org/xxx.html → 重定向至首页

# （3）指定客户端类型跳转新域名【常用】

移动端设备访问站点时自动重定向至 m 站点。

# 前置：m.example.org 站点配置
server {
    listen 80;
    server_name m.example.org;
    root /data/nginx/html/mobile;
}

# 需求：移动端访问 www.example.org 时重定向至 m.example.org
server {
    listen 80;
    server_name www.example.org;
    root /data/nginx/html/example_org;
    if ($http_user_agent ~* "android|iphone|ipad") {
        rewrite ^/(.*)$ http://m.example.org/$1 redirect;
        # return 302 http://m.example.org$request_uri;
    }
}

# （4）网站维护跳转

停机维护时，指定 IP 正常访问，其他 IP 跳转维护页。

server {
    listen 80;
    server_name www.example.org;
    root /data/site;
    index index.html;
    set $ip 0;
    if ($remote_addr = 10.0.0.101) { set $ip 1; }
    if ($remote_addr = 10.0.0.102) { set $ip 1; }
    if ($ip = 0) {
        rewrite ^(.*)$ /maintain.html break;   # 其他 IP 跳转维护页
    }
}

# （5）其它案例

# 案例 1：User-Agent 含 MSIE 则重写到 /msie 目录
if ( $http_user_agent ~ MSIE){
    rewrite ^(.*)$ /msie/$1 break;
}

# 案例 2：目录转换为对象存储形式
# /20200106/static -> /static?id=20200106
rewrite ^/(\d+)/(.+)/ /$2?id=$1 redirect;

# 案例 3：多目录转换访问方式
# www.example.com/images/20200106/1.jpg => www.example.com/index.do?name=images&dir=20200106&file=1.jpg
if ($host ~* (.*)\.example\.com) {
    rewrite ^/(.*)/(\d+)/(.*)$ /index.do?name=$1&dir=$2&file=$3 redirect;
}

# 八、Nginx 防盗链

防盗链：防止自己服务器中的资源被他人盗用，尤其对按流量收费的场景，避免花自己的钱给别人当图床。

防盗链基于客户端携带的 Referer（记录打开页面前从哪个页面跳转来的标记信息）。若别人只链接了自己网站的图片/资源，而非打开整个页面，就是盗链，referer 就是之前那个网站域名。

实现盗链演示：在站点 www.example.net 盗链 www.example.org 的图片资源。

# 盗链服务器 www.example.net
server {
    listen 80;
    server_name www.example.net;
    location / {
        index index.html;
        root "/data/nginx/html/net";
        access_log /apps/nginx/logs/www.example.net_access.log main;
    }
}
# 被盗链站点 www.example.org 配置
server {
    listen 80;
    listen 443 ssl;
    server_name www.example.org;
    ssl_certificate /apps/nginx/certs/www.example.org.pem;
    ssl_certificate_key /apps/nginx/certs/www.example.org.key;
    ssl_session_cache shared:sslcache:20m;
    ssl_session_timeout 10m;
    location / {
        root /data/nginx/html/example_org;
        index index.html;
        access_log /apps/nginx/logs/www.example.org_access.log main;
    }
}

在盗链站点页面中 <img src="http://www.example.org/images/logo.jpg">，访问后查看被盗链站点日志，可见 referer 为 http://www.example.net/ 的盗链记录。

实现防盗链：基于 ngx_http_referer_module 模块，检查请求 referer 是否有效。

语法：valid_referers none | blocked | server_names | string ...;，Context: server, location。

值说明
none请求无 referer 首部（用户直接输入域名访问）
blocked有 referer 首部但无有效值（如为空）
server_namesreferer 含本主机名及 nginx 监听的 server_name
arbitrary_string自定义字符串，可用 * 通配，如 *.example.org example.*
regular expression正则匹配，用 ~ 开头，如 ~.*\.example\.com

示例：

location /images {
    root /data/nginx/html/pc;
    index index.html;
    valid_referers none blocked server_names
        *.example.com example.* www.example.org/galleries/
        ~\.google\.;
    if ($invalid_referer) {
        return 403;
    }
}

范例：定义防盗链

server {
    index index.html;
    valid_referers none blocked server_names *.example.org ~\.google\. ~\.baidu\. ~\.bing\. ~\.so\. ~\.sogou\. ;
    if ($invalid_referer) {               # 无效 referer 访问
        return 403 "Forbidden Access";    # 返回 403
        # return 302 http://www.example.org/images/daotu.jpg;    # 会死循环
        # rewrite ^(.*)$ /images/daotu.jpg break;                # 返回错误图片
    }
}
nginx -t && nginx -s reload
# 指定 referer 访问
curl -e 'http://www.baidu.com' www.example.org        # 有效
curl -e 'http://www.xxx.com' www.example.org        # 被拒绝
curl -e 'www.xxx.com' www.example.org                # 不加 http 的 referer 不拒绝
