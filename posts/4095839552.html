# Ansible 常用模块详解（下）：系统与配置类

本文讲解 Ansible 中与系统管理、软件包、服务、用户、文件内容修改、系统信息收集相关的常用模块：hostname、cron、yum/apt、yum_repository、service、user、group、lineinfile、replace、selinux、reboot、mount、setup、debug。这些模块覆盖了服务器日常配置管理的绝大部分场景。

# 一、hostname 模块

功能：管理主机名。

# 修改指定主机主机名
ansible 192.168.80.18 -m hostname -a 'name=node18.example.com'

# 验证
ansible 192.168.80.18 -m shell -a 'hostname'

重要注意：千万别以分组来修改主机名，否则整个组的主机名都会被改成同一个。除非你确实有此需求，否则应针对单台主机操作。

# 错误示范：整个组主机名变成同一个
ansible websrvs -m hostname -a 'name=node.example.com'

# 二、cron 模块

功能：批量管理远程主机中的计划任务。

支持的时间字段：minute、hour、day、month、weekday（分、时、日、月、周）。

示例：

# 创建任务：工作日 02:30 执行备份
ansible 10.0.0.8 -m cron -a 'hour=2 minute=30 weekday=1-5 name="backup mysql" job=/root/mysql_backup.sh'

# 创建任务：每 5 分钟同步时间
ansible websrvs -m cron -a "minute=*/5 job='/usr/sbin/ntpdate ntp.example.com &>/dev/null' name=Synctime"

# 禁用计划任务
ansible websrvs -m cron -a "minute=*/5 job='/usr/sbin/ntpdate ntp.example.com &>/dev/null' name=Synctime disabled=yes"

# 启用计划任务
ansible websrvs -m cron -a "minute=*/5 job='/usr/sbin/ntpdate ntp.example.com &>/dev/null' name=Synctime disabled=no"

# 删除任务
ansible websrvs -m cron -a "name='backup mysql' state=absent"
ansible websrvs -m cron -a 'state=absent name=Synctime'

cron 模块通过 name 标识任务，可精确地增、删、禁、启计划任务，比直接写 crontab 更可维护。

# 三、yum 和 apt 模块

功能：

  • yum 模块：管理软件包，只支持 RHEL、CentOS、Fedora，不支持 Ubuntu；
  • apt 模块：管理 Debian 相关版本的软件包。
  • 后续可通过判断系统版本来决定使用哪个模块（结合 when 条件）。

示例（yum）：

# 安装 state=present
ansible websrvs -m yum -a 'name=httpd state=present'

# 卸载 state=absent
ansible websrvs -m yum -a 'name=httpd state=absent'

# 启用 epel 源安装
ansible websrvs -m yum -a 'name=nginx state=present enablerepo=epel'

# 升级除 kernel 和 foo 开头以外的所有包
ansible websrvs -m yum -a 'name=* state=latest exclude=kernel*,foo*'

# 一次安装多个软件包
ansible websrvs -m yum -a 'name=sl,cowsay'

# 直接基于远程主机上的软件包安装（URL 形式）
ansible websrvs -m yum -a "name=https://mirror.example.com/zabbix/zabbix-agent-5.2.5-1.el7.x86_64.rpm state=present"

# 查看包
ansible localhost -m yum -a "list=tree"

示例（apt，Ubuntu）：

# 安装软件包（注意：RedHat 用 yum，Ubuntu 用 apt）
ansible 192.168.80.18 -m apt -a 'name=bb,sl,cowsay,cmatrix,oneko,hollywood,boxes,libaa-bin,x11-apps state=present'

# 卸载软件包
ansible websrvs -m apt -a 'name=sl,cowsay state=absent'

# 四、yum_repository 模块

功能：批量管理远程主机上的 Yum 仓库。

示例（添加多个仓库到同一文件）：

- name: Add multiple repositories into the same file (1/2)
  yum_repository:
    name: epel
    description: EPEL YUM repo
    file: external_repos
    baseurl: https://download.fedoraproject.org/pub/epel/$releasever/$basearch/
    gpgcheck: no

- name: Add multiple repositories into the same file (2/2)
  yum_repository:
    name: rpmforge
    description: RPMforge YUM repo
    file: external_repos
    baseurl: http://apt.sw.be/redhat/el7/en/$basearch/rpmforge
    mirrorlist: http://mirrorlist.repoforge.org/el7/mirrors-rpmforge
    enabled: no

- name: Remove repository from a specific repo file
  yum_repository:
    name: epel
    file: external_repos
    state: absent

创建与删除仓库的 Playbook：

# yum_repo.yml
- hosts: websrvs
  tasks:
    - name: Add repositories
      yum_repository:
        name: test
        description: EPEL YUM repo
        file: external_repos
        baseurl: https://download.fedoraproject.org/pub/epel/$releasever/$basearch/
        gpgcheck: no
ansible-playbook yum_repo.yml
# 验证：cat /etc/yum.repos.d/external_repos.repo
# remove_yum_repo.yml
- hosts: websrvs
  tasks:
    - name: remove repo
      yum_repository:
        name: test
        file: external_repos
        state: absent
ansible-playbook remove_yum_repo.yml

# 五、service 模块

功能：批量管理远程主机上的服务。

# 启动服务并开机自启
ansible 192.168.80.18 -m service -a 'name=httpd state=started enabled=yes'

# 停止服务
ansible websrvs -m service -a 'name=httpd state=stopped'

# 重载服务
ansible websrvs -m service -a 'name=httpd state=reloaded'

# 修改配置后重启服务
ansible websrvs -m shell -a "sed -i 's/^Listen 80/Listen 8080/' /etc/httpd/conf/httpd.conf"
ansible websrvs -m service -a 'name=httpd state=restarted'

state 常用取值：started、stopped、restarted、reloaded。

# 六、user 模块

功能：管理用户，可批量创建、修改、删除用户，为用户创建密钥对等。

示例：

# 创建用户
ansible all -m user -a 'name=user1 comment="test user" uid=2048 home=/app/user1 group=root'
ansible all -m user -a 'name=nginx comment=nginx uid=88 group=nginx groups="root,daemon" shell=/sbin/nologin system=yes create_home=no home=/data/nginx non_unique=yes'

# 删除用户及家目录等数据（remove=yes，默认 remove=no）
ansible all -m user -a 'name=nginx state=absent remove=yes'

生成加密密码并创建用户：

# 用 password_hash 过滤器生成 sha512 加密密码
ansible localhost -m debug -a "msg=<!--swig￼0-->"
# 输出形如：$6$salt$MktMKPZJ6t59GfxcJU20DwcwQzfMvOlHFVZiOVD71w.

# 用生成的密码创建用户
ansible websrvs -m user -a 'name=test password="$6$salt$MktMKPZJ6t59GfxcJU20DwcwQzfMvOlHFVZiOVD71w."'

# 创建用户并生成 4096bit 私钥
ansible websrvs -m user -a 'name=test generate_ssh_key=yes ssh_key_bits=4096 ssh_key_file=.ssh/id_rsa'

不要在命令中直接写明文密码，应先用 password_hash 生成加密串再写入，保证安全。

# 七、group 模块

功能：管理组。

# 创建组
ansible websrvs -m group -a 'name=nginx gid=88 system=yes'

# 删除组
ansible websrvs -m group -a 'name=nginx state=absent'

# 八、lineinfile 模块

功能：相当于 sed，可修改文件内容。Ansible 在用 sed 替换时常遇转义和特殊符号问题，lineinfile 和 replace 模块能方便地进行替换。修改文件单行时优先使用 lineinfile。

regexp 参数规则：使用正则匹配对应行。替换时若多行都能匹配，只有最后被匹配的行会被替换；删除时若多行都能匹配，这些行都会被删除。若要多行匹配替换，需使用 replace 模块。

示例：

# 将 Listen 开头的行改为 Listen 8080（regexp 参数）
ansible 192.168.80.18 -m lineinfile -a "path=/etc/httpd/conf/httpd.conf regexp='^Listen' line='Listen 8080'"

# 批量禁用 SELinux
ansible all -m lineinfile -a "path=/etc/selinux/config regexp='^SELINUX=' line='SELINUX=disabled'"

# 删除以 # 开头的所有行
ansible 192.168.80.18 -m lineinfile -a 'dest=/etc/fstab state=absent regexp="^#"'

# 九、replace 模块

功能：根据正则表达式替换文件中的字符串，文件中所有被匹配到的字符串都会被替换。

与 lineinfile 的区别（重点）：

  1. lineinfile 的 regexp：匹配行，替换时只替换最后匹配的行，删除时删除所有匹配行；
  2. replace：匹配字符串，替换时所有匹配的字符串都会被替换。

示例：

# 查找所有以 UUID 开头的行，并注释掉（所有匹配行都处理）
ansible all -m replace -a "path=/etc/fstab regexp='^(UUID.*)' replace='#\1'"

# 查找以 # 开头且后接 UUID 的行（被注释的），移除行首 # 取消注释
ansible all -m replace -a "path=/etc/fstab regexp='^#(UUID.*)' replace='\1'"

选择原则：改单行用 lineinfile，批量替换字符串用 replace。

# 十、selinux 模块

功能：批量管理远端主机的 SELinux 策略。

# 启用
ansible 192.168.80.18 -m selinux -a 'state=enforcing policy=targeted'

# 禁用
ansible 192.168.80.18 -m selinux -a 'state=disabled'

# 验证
[root@centos8 ~] grep -v '#' /etc/selinux/config
SELINUX=disabled
SELINUXTYPE=targeted
[root@centos8 ~] getenforce
Permissive

# 十一、reboot 模块

注意：Windows 目标请使用 win_reboot 模块。

[root@ansible ~] ansible websrvs -m reboot

# 十二、mount 模块

功能：批量管理被控端设备挂载。

主要参数：src（本地或远程设备路径）、path（挂载到本地的路径）、fstype（文件系统类型 xfs/nfs 等）、opts（挂载参数）、state（absent/mounted/unmounted）。

示例：

# 临时挂载
ansible websrvs -m mount -a 'src="UUID=b3e48f45-f933-4c8e-a700-22a159ec9077" path=/home fstype=xfs opts=noatime state=present'

# 临时取消挂载
ansible websrvs -m mount -a 'path=/home fstype=xfs opts=noatime state=unmounted'

# 永久挂载（NFS）
ansible websrvs -m mount -a 'src=10.0.0.8:/data/wordpress path=/var/www/html/wp-content/uploads opts="_netdev" state=mounted'

# 永久卸载
ansible websrvs -m mount -a 'src=10.0.0.8:/data/wordpress path=/var/www/html/wp-content/uploads state=absent'

# 十三、setup 模块（重要）

功能：收集主机的系统信息（facts），这些信息可直接作为变量使用。主机较多时会影响执行速度，可用 gather_facts: no 禁止收集。

filter 参数：用于条件过滤，仅返回匹配的信息。

常用 filter 示例：

# 收集 websrvs 组所有主机的所有 facts
ansible websrvs -m setup

# 主机节点名
ansible websrvs -m setup -a "filter=ansible_nodename"
# 主机名
ansible websrvs -m setup -a "filter=ansible_hostname"
# 主机所属域名
ansible websrvs -m setup -a "filter=ansible_domain"
# 总内存
ansible websrvs -m setup -a "filter=ansible_memtotal_mb"
# 空闲内存
ansible websrvs -m setup -a "filter=ansible_memfree_mb"
# 操作系统家族（RedHat、Debian 等）
ansible websrvs -m setup -a "filter=ansible_os_family"
# 主版本号 / 完整版本号
ansible websrvs -m setup -a "filter=ansible_distribution_major_version"
ansible websrvs -m setup -a "filter=ansible_distribution_version"
# 虚拟 CPU 数量
ansible websrvs -m setup -a "filter=ansible_processor_vcpus"
# 所有 IPv4 地址列表 / 默认 IPv4
ansible websrvs -m setup -a "filter=ansible_all_ipv4_addresses"
ansible all -m setup -a 'filter="ansible_default_ipv4"'
# 架构类型
ansible websrvs -m setup -a "filter=ansible_architecture"
# 已运行时间
ansible websrvs -m setup -a "filter=ansible_uptime_seconds"
# 以 ansible_processor 开头的所有 facts
ansible websrvs -m setup -a "filter=ansible_processor*"
# 环境变量
ansible websrvs -m setup -a 'filter=ansible_env'
# Python 版本
ansible all -m setup -a 'filter=ansible_python_version'

setup 模块是 Ansible 动态感知主机信息的基础，配合 when 条件可实现"按系统版本/CPU/内存做差异化配置"。

# 十四、debug 模块

功能：输出信息，通过 msg 定制输出内容。注意：msg 后的变量有时需要加引号。

示例：

# 默认输出 Hello world（未指定 msg 时默认输出 "Hello world!"）
[root@ansible ~] ansible 192.168.80.18 -m debug

# 利用 debug 输出变量
[root@centos8 ~] vim debug.yaml
---
- hosts: websrvs
  tasks:
  - name: output variables
    debug:
      msg: Host "<!--swig￼1-->" Ip "<!--swig￼2-->"

[root@centos8 ~] ansible-playbook debug.yaml

# 显示字符串特定字符（索引从 0 开始）
- hosts: all
  gather_facts: no
  vars:
    a: "12345"
  tasks:
  - debug:
      msg: "<!--swig￼3-->"   # 输出 "3"

debug 模块是调试与信息输出的必备工具，常配合 register、var 使用。

# 小结

本文覆盖了系统与配置类模块。核心要点：

  • hostname 勿对整组操作，避免主机名冲突；
  • cron 用 name 标识任务，便于增删禁启；
  • yum/apt 按系统选择，可结合 when 实现跨发行版兼容；
  • lineinfile 改单行、replace 批量替换字符串，二者分工明确；
  • user 用 password_hash 生成加密密码，勿写明文；
  • setup 收集 facts，是动态感知与条件化配置的基础；
  • debug 是调试输出的利器。

至此，Ansible 常用模块已全部覆盖。下一篇开始进入核心内容——Playbook 与 YAML。
