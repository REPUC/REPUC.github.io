# Linux IO 重定向

本篇讲解 Linux 输入输出重定向与进程管道技术：从重定向的概念、标准输入/输出/错误输出的文件描述符，到 >、>>、2>、&>、< 等重定向操作符的用法与实战，再到管道 |、tee、xargs 的配合使用，并附丰富的命令示例。

# 一、重定向基础概述

# 1.1 什么是重定向

将原本要输出到屏幕中的数据信息，重新定向到某个指定的文件中，或者定向到黑洞中。

# 1.2 为什么需要重定向

  1. 当程序执行输出的信息比较多时，需要保存下来再进行分页查看；
  2. 后台执行的程序一般都会有输出，不希望它的输出干扰到屏幕；
  3. 定时执行的备份任务，希望将备份的结果保留下来时；
  4. 当重复创建用户，会提示一些错误信息，可以直接将信息丢弃；
  5. 希望将错误日志与正确日志，分别输出保存到不同文件时。

# 1.3 标准输入与标准输出

当进程操作一个文件时：

  1. 首先程序无法直接访问硬件，需要借助内核来访问文件；
  2. 内核（kernel）需要利用**文件描述符（file descriptor）**来访问文件。

总结：进程 → 通过 → 文件描述符（非负整数）→ 访问 → 文件名称；进程使用文件描述符来管理打开的文件对应关系。

通常程序访问一个文件至少会打开三个标准文件，分别是标准输入、标准输出、错误输出。进程将从标准输入中得到数据，将正常输出打印至屏幕终端，将错误的输出信息也打印至屏幕终端。

标准文件与文件描述符对应表：

名称文件描述符作用
标准输入（STDIN）0默认是键盘，也可以是文件或其他命令的输出
标准输出（STDOUT）1默认输出到屏幕
错误输出（STDERR）2默认输出到屏幕
文件名称（filename）3+程序打开的其他文件

# 二、输出重定向案例

输出重定向即改变输出内容的位置。常见重定向类型如下：

类型操作符用途
标准覆盖输出重定向>将程序输出的正确结果输出到指定的文件中，会覆盖文件原有内容
标准追加输出重定向>>将程序输出的正确结果以追加的方式输出到指定文件，不会覆盖
错误覆盖输出重定向2>将程序的错误结果输出到指定的文件中，会覆盖文件原有内容
错误追加输出重定向2>>将程序输出的错误结果以追加的方式输出到指定文件，不会覆盖

# 2.1 案例 1：标准输出重定向

行为：如果文件不存在则创建；如果文件存在则清空内容。

[root@oldwang ~]# > edu.txt
[root@oldwang ~]# ifconfig eth0 > edu.txt

# 2.2 案例 2：标准追加输出重定向

行为：如果文件不存在则创建；如果文件存在则在文件尾部添加内容。

[root@oldwang ~]# echo "Hello Students" >> edu.txt

# 2.3 案例 3：错误输出重定向

# 1. 正确输出及错误输出至相同文件
[jaxxwang@oldwang ~]$ find /etc -name "*.conf" >ok 2>ok

# 2. 正确输出及错误输出至不同的文件
[jaxxwang@oldwang ~]$ find /etc -name "*.conf" 1>ok 2>err

# 2.4 案例 4：混合输出重定向

# 1. 将正确输出和错误输出混合至同一文件
[jaxxwang@oldwang ~]$ find /etc -name "*.conf" &>ab

# 2. 将两个文件内容组合为一个文件
[jaxxwang@oldwang ~]$ cat ok err > ab

# 正确和错误都输入到相同位置（2>&1：把标准错误输出重定向到标准输出所在的位置）
[root@oldwang ~]# ls /root /error >ab 2>&1

# 2.5 案例 5：将内容输出至黑洞

将内容输出至黑洞设备 /dev/null（丢弃不想要的输出）：

[root@oldwang ~]# ls /root /error >ab 2>/dev/null
[root@oldwang ~]# ls /root /error >ab &>/dev/null

# 三、输入重定向案例

输入重定向指的是重新指定设备来"代替键盘"作为新的输入设备。

# 3.1 输入重定向示例

1. 通过输入重定向读取文件内容

[root@oldwang ~]# cat < /etc/hosts

2. 通过输入重定向读入多行内容（heredoc，只要不出现 EOF 就可以一直录入）

[root@dns-master ~]# cat <<EOF
小明 99
小红 166
小王 86
EOF

3. 通过输入重定向将数据导入至数据库中

[root@oldwang ~]# mysql -uroot -poldwang.com < /opt/wordpress.sql

# 3.2 脚本输入重定向

使用输入重定向打印安装服务的菜单导航栏：

[root@dns-master ~]# cat install.sh
#!/usr/bin/bash
cat <<-EOF
  | 1) 安装nginx         |
  | 2) 安装php           |
  | 3) 退出               |
EOF
read -p "请选择你要安装的软件编号 [ 1 | 2 | 3 ]: "

# 四、进程管道技术

# 4.1 什么是管道

管道操作符号 |，主要用来连接左右两个命令，将左侧命令的标准输出，交给右侧命令的标准输入。

  • 注意事项：管道无法传递标准错误输出至后者命令；
  • 管道命令符能让大家进一步掌握命令之间的搭配使用方法，进一步提高命令输出值的处理效率。

# 4.2 管道流程

格式：

cmd1 | cmd2 [... | cmdn]

流程：左侧命令的 stdout → 管道 → 右侧命令的 stdin。

# 4.3 管道使用案例

# 案例 1：将 /etc/passwd 中的用户按 UID 大小排序

[root@oldwang ~]# sort -t":" -k3 -n /etc/passwd
[root@oldwang ~]# sort -t":" -k3 -n /etc/passwd -r      # 反向排序
[root@oldwang ~]# sort -t":" -k3 -n /etc/passwd | head  # 取排序后前 10 行

# 案例 2：统计当前 /etc/passwd 中用户使用的 shell 类型

思路：输出第 7 列（shell），然后排序、去重、统计。

[root@oldwang ~]# awk -F: '{print $7}' /etc/passwd
[root@oldwang ~]# awk -F: '{print $7}' /etc/passwd | sort
[root@oldwang ~]# awk -F: '{print $7}' /etc/passwd | sort | uniq
[root@oldwang ~]# awk -F: '{print $7}' /etc/passwd | sort | uniq -c    # 统计每种 shell 数量

# 案例 3：打印并输出当前所有主机所有网卡的 IP 地址

[root@oldwang ~]# ip addr | grep 'inet ' | awk '{print $2}' | awk -F"/" '{print $1}'
127.0.0.1
10.0.0.100

# 4.4 tee 与 xargs

# 4.4.1 管道中使用 tee

tee 的作用：将管道中的数据同时输出到文件和后续命令，即既能保存一份，又能继续向下传递处理。

[root@web ~]# ip addr | grep 'inet ' | tee ip.txt | awk -F"/" '{print $1}' | awk '{print $2}'
127.0.0.1
10.0.0.100

# 查看 tee 保存下来的完整数据
[root@web ~]# cat ip.txt
inet 127.0.0.1/8 scope host lo
inet 10.0.0.100/24 brd 192.168.69.255 scope global ens32

# 4.4.2 管道中使用 xargs

xargs 参数传递：主要让一些不支持管道的命令可以使用管道技术，将前一个命令的输出作为后一个命令的参数。

# 将前一个命令的输出作为后一个命令的参数
[root@web ~]# which cat | xargs ls -l

# 批量删除：将 ls 的输出逐项传给 rm 执行
[root@web ~]# ls | xargs rm -fv
