# Linux 权限管理

本篇围绕 Linux 文件权限展开：先讲权限的含义、rwx 的二进制与八进制表示、文件与目录权限的区别验证，再介绍 chmod/chown/chgrp 修改权限与所属关系，然后深入 SUID/SGID/SBIT 特殊权限、chattr 特殊属性，最后讲解 umask 默认权限的计算原理，并附多个实战场景与练习。

# 一、文件权限介绍

# 1.1 什么是权限

  • 权限是用来约束用户能对系统所做的操作；
  • 或者说，权限是指某个特定的用户具有的特定系统资源使用权力。

# 1.2 为什么需要权限

Linux 是一个多用户系统，对每一个用户来说，个人隐私的保护十分重要，所以需要进行权限划分：

  • 安全性：降低误删除风险、减少人为造成故障以及数据泄露等风险；
  • 数据隔离：不同的权限能看到、以及操作不同的数据（比如员工薪资表）；
  • 职责明确：电商场景中客服只能查看投诉、无法查阅店铺收益，运营则能看到投诉以及店铺收益。

# 1.3 权限与用户的关系

在 Linux 系统中，权限用来定义用户能做什么、不能做什么：

  • 针对文件定义了三种身份：属主（owner）、属组（group）、其他人（others）；
  • 每种身份又对应三种权限：读（read）、写（write）、执行（execute）。

用户访问文件的流程：

  1. 判断用户是否为文件属主，如果是则按属主权限进行访问；
  2. 判断用户是否为文件属组，如果是则按属组权限进行访问；
  3. 如果既不是文件属主、也不是该文件属组，则按其他人权限进行访问。

# 1.4 权限中 rwx 的含义

Linux 中权限由 rwxr-xr-x 这 9 位字符来表示，主要控制文件的属主（user）、属组（group）、其他用户（other）：

字母含义二进制八进制权限表示法
r读取权限1004
w写入权限0102
x执行权限0011
-没有权限0000

文件权限示例 1： rwxrw-r-- alice hr file1.txt

  • Q1：alice 对 file1.txt 拥有什么权限？→ rwx（属主）
  • Q2：jack 对 file1.txt 有什么权限？（前提：jack 附加组为 hr 组）→ rw-（属组）
  • Q3：tom 对 file1.txt 有什么权限？→ r--（其他人）

文件权限示例 2： rw-r----- root dev file2.txt

  • Q1：root 对 file2.txt 拥有什么权限？→ rw-（属主）
  • Q2：jack 对 file2.txt 有什么权限？（前提：jack 附加组为 dev 组）→ r--（属组）
  • Q3：alice 对 file2.txt 有什么权限？→ ---（其他人）

文件权限示例 3： rwxr--rwx jack ops file3.txt

  • Q1：jack 对 file3.txt 拥有什么权限？→ rwx（属主）
  • Q2：tom 对 file3.txt 有什么权限？（前提：tom 附加组为 ops 组）→ r--（属组）
  • Q3：alice 对 file2.txt 有什么权限？→ rwx（其他人）

# 二、修改文件权限

# 2.1 修改权限的意义

简单来说：赋予某个用户或组 → 能够以何种方式（读/写/执行）→ 访问文件。

# 2.2 如何修改权限

修改权限使用 chmod（change mode） 命令实现：

  • 对于 root 用户而言，可以修改任何人的文件权限；
  • 对于普通用户，仅仅只能变更属于自己的文件权限。

# 2.2.1 UGO 方式

# 给文件所有人（u/g/o/a）添加读写执行权限
[root@web ~]# chmod a=rwx file

# 取消文件的所有权限
[root@web ~]# chmod a=-rwx file

# 属主读写执行，属组读写，其他人无权限
[root@web ~]# chmod u=rwx,g=rw,o=- file

# 属主属组读写执行，其他人读权限
[root@web ~]# chmod ug=rwx,o=r file

# 2.2.2 数字权限方式

# 设定文件权限 644，即 rw-r--r--
[root@web ~]# chmod 644 file

# 设定文件权限 600，即 rw-------
[root@web ~]# chmod 600 file

# 设定目录权限为 755，递归授权，即 rwxr-xr-x
[root@web ~]# chmod -R 755 dir

# 2.2.3 权限设定案例

场景 1： 针对 hr 部门的访问目录 /home/hr 设置权限，要求：

  1. 超级管理员 root 用户和 hr 组的员工可以读、写、执行；
  2. 其他用户或者组没有任何权限。
[root@web ~]# groupadd hr
[root@web ~]# useradd hr1 -G hr
[root@web ~]# useradd hr2 -G hr
[root@web ~]# mkdir /home/hr
[root@web ~]# chgrp hr /home/hr
[root@web ~]# chmod 770 /home/hr

场景 2： 在 Linux 中，权限设定对文件和对目录的影响是有区别的：

权限对文件的影响对目录的影响
读权限（r）具有读取、阅读文件内容的权限具有浏览目录及子目录的权限
写权限（w）具有新增、修改文件内容的权限具有增加、删除目录内文件的权限
执行权限（x）具有执行文件的权限具有访问目录的内容（取决于目录中文件的权限）

# 2.3 权限对文件的影响

# 2.3.1 验证 r 权限

步骤：使用 root 身份新建文件 → 切换普通用户 → 测试可读权限 → 测试执行和删除权限。

[root@web ~]# echo "date" > /opt/filename
[root@web ~]# ls -l /opt/filename
-rw-r--r-- 1 root root 5 Jan 24 08:24 /opt/filename

[root@web ~]# su - oldwang
[oldwang@web ~]$ cat /opt/filename
date

# 删除文件需要对上级目录有 w 权限，此处无权限所以删除失败
[oldwang@ansible-hostname ~]$ rm -f /opt/filename
rm: cannot remove '/opt/filename': Permission denied

结论：r 权限让普通用户可以使用 cat 等命令查看文件内容，但删除文件看的是上级目录的 w 权限。

# 2.3.2 验证 w 权限

修改权限只有 w，测试能否查看文件、写入数据、删除文件：

[root@web ~]# chmod 642 /opt/filename

[oldwang@ansible-hostname ~]$ cat /opt/filename
cat: /opt/filename: Permission denied

[oldwang@ansible-hostname ~]$ vim /opt/filename      # 提示权限拒绝
[oldwang@ansible-hostname ~]$ echo "date" >> /opt/filename   # 无法写入

[oldwang@ansible-hostname ~]$ rm -f /opt/filename
rm: cannot remove '/opt/filename': Permission denied

结论：仅有 w 权限时，因为无 r 权限无法查看文件，且对文件本身的 w 权限不能删除文件（删除看的是目录）。

# 2.3.3 验证 x 权限

修改权限只有 x，测试查看、写入、删除、执行文件：

[root@web ~]# chmod 641 /opt/filename

[oldwang@ansible-hostname ~]$ cat /opt/filename
cat: /opt/filename: Permission denied

[oldwang@ansible-hostname ~]$ vim /opt/filename
[oldwang@ansible-hostname ~]$ echo "date" >> /opt/filename

[oldwang@ansible-hostname ~]$ rm -f /opt/filename
rm: cannot remove '/opt/filename': Permission denied

# 文件没有执行权限，直接执行失败
[oldwang@ansible-hostname ~]$ /opt/filename
-bash: /opt/filename: 权限不够

# 2.3.4 文件权限总结

  1. 读取权限 r：具有读取、阅读文件内容的权限
    • 只能使用查看类命令 cat、head、tail、less、more。
  2. 写入权限 w：具有新增、修改文件内容的权限
    • 使用 vim 会提示权限拒绝，但可强制保存，会覆盖文件的所有内容；
    • 使用 echo 命令重定向的方式可以往文件内写入数据，>> 可以追加内容；
    • 使用 rm 无法删除文件，因为删除文件需要看上级目录是否有 w 权限。
  3. 执行权限 x：具有执行文件的权限
    • 对于普通文件，单独的 x 权限基本没有用；
    • 如果普通用户需要执行文件，需要配合 r 权限。
  4. 文件权限常见组合：
    • 文件 r 权限：只给用户查看，无其他操作；
    • 文件 rw 权限：可以查看和编辑文件内容；
    • 文件 rx 权限：允许查看和执行文件，但不能修改文件；
    • 文件 rwx 权限：能读、能写、能执行、不能删除。

# 2.4 权限对目录的影响

# 2.4.1 验证 r 权限

使用 root 身份新建目录，权限设为 774，目录中创建普通文件，测试能否查看目录内容、能否进入目录：

[root@web ~]# mkdir /data
[root@web ~]# echo "123" > /data/file
[root@web ~]# chmod 774 /data/

[oldwang@ansible-hostname ~]$ ls /data/
ls: cannot access /data/file: Permission denied
file

[oldwang@ansible-hostname ~]$ cd /data/
-bash: cd: /data/: 权限不够

结论：r 权限只允许浏览目录内文件名，但进入目录需要 x 权限。

# 2.4.2 验证 w 权限

权限设为 772，测试能否查看目录内容、删除目录中文件：

[root@web ~]# chmod 772 /data/

[oldwang@ansible-hostname ~]$ ls /data/
ls: cannot open directory /data/: Permission denied

[oldwang@ansible-hostname ~]$ cd /data/
-bash: cd: /data/: 权限不够

[oldwang@ansible-hostname ~]$ rm -f /data/file
rm: cannot remove '/data/file': Permission denied

结论：w 权限可以创建、删除、修改目录内文件名，但需要 x 权限配合（不能进入目录时，删除操作也会被拒绝）。

# 2.4.3 验证 x 权限

权限设为 771，测试能否查看目录内容、能否进入目录：

[root@web ~]# chmod 771 /data/

[oldwang@ansible-hostname ~]$ ls /data/
ls: cannot open directory /data/: Permission denied

[oldwang@ansible-hostname ~]$ cd /data/
[oldwang@ansible-hostname data]$

结论：x 权限允许进入目录，但不能浏览、复制、移动、删除目录。

# 2.4.4 目录权限小结

  1. 读取权限 r：具有浏览目录及子目录的权限
    • 使用 ls 命令浏览目录及子目录，但同时也会提示权限拒绝；
    • 使用 ls -l 命令浏览目录及子目录，文件属性会带问号，并且只能看到文件名。
  2. 写入权限 w：具有增加、删除或修改目录内文件名的权限，需要 x 权限配合
    • 可以在目录内创建文件、删除文件（与文件本身权限无关）；
    • 不能进入目录、不能复制目录、不能删除目录、不能移动目录。
  3. 执行权限 x：具有进入目录的权限
    • 只能进入目录；
    • 不能浏览、复制、移动、删除。
  4. 目录权限常见组合：
    • 目录 rx 权限：允许浏览目录内文件以及子目录，不允许在该目录下创建文件、删除文件；
    • 目录 rw 权限：能查看目录，能往目录写入文件，但无法进入目录（使用情况太少）；
    • 目录 rwx 权限：可以浏览、进入、创建、删除目录中的文件。

# 三、修改文件所属关系

# 3.1 修改文件所属关系的意义

场景类比：alice 用户现在有很多房产，希望将其中某一套出售给 jack 用户变现：

  1. 通过 root 用户变更属主关系，将房产默认属主身份 alice 修改为 jack；
  2. 修改完成后，该房产拥有人则为 jack 用户，而不再是 alice 用户。

# 3.2 如何修改文件的所属关系

使用 chown（change owner）、chgrp（change group） 命令实现：

  • chown 能变更文件的属主和属组；
  • chgrp 仅能变更文件的属组。

# 3.2.1 chown（change owner）

# 1. 准备环境，创建文件和目录
[root@web ~]# mkdir /data

# 2. 修改所属主为 bin
[root@web ~]# chown bin /data

# 3. 修改所属组为 adm
[root@web ~]# chown .adm /data

# 4. 修改目录所属主为 root，所属组为 root，并递归授权
[root@web ~]# chown -R root.root dir

# 3.2.2 chgrp（change group）

# 1. 准备环境，创建文件和目录
[root@web ~]# mkdir /data2

# 2. 修改所属组为 adm
[root@web ~]# chgrp adm /data2

# 3.3 修改文件所属关系场景

# 3.3.1 基于 Httpd 场景说明

Web 服务（httpd 进程）以 apache 用户身份运行，进程能以何种方式访问一个文件，取决于文件的属主/属组以及权限设置。站点文件属主是 root 时，apache 用户无权读取，就会提示权限不足。

# 3.3.2 基于 Httpd 场景实践

步骤 1：安装 httpd

[root@web ~]# setenforce 0
[root@web ~]# systemctl stop firewalld
[root@web ~]# yum install httpd -y
[root@web ~]# systemctl start httpd

步骤 2：在默认站点目录创建文件，修改其权限，验证是否能访问成功

[root@web ~]# echo "New Web Site" > /var/www/html/index.html
[root@web ~]# chmod 600 /var/www/html/index.html
[root@web ~]# ls -l /var/www/html/index.html
-rw------- 1 root root 22 Apr 21 17:27 /var/www/html/index.html

步骤 3：无法访问，解决提示权限不足，有如下两种方式

方式一：直接放开文件权限

[root@web ~]# chmod 777 /var/www/html/index.html

方式二：查看 httpd 进程运行用户，将文件属主属组改为 apache，再恢复 600 权限

[root@web ~]# ps -ef | grep httpd
root     2418     1  0 14:07 ?      00:00:08 /usr/sbin/httpd -DFOREGROUND
apache    2419  2418  0 14:07 ?      00:00:08 /usr/sbin/httpd -DFOREGROUND
apache    2420  2418  0 14:07 ?      00:00:08 /usr/sbin/httpd -DFOREGROUND
apache    2421  2418  0 14:07 ?      00:00:08 /usr/sbin/httpd -DFOREGROUND
apache    2422  2418  0 14:07 ?      00:00:08 /usr/sbin/httpd -DFOREGROUND

[root@web ~]# chown apache.apache /var/www/html/index.html
[root@web ~]# chmod 600 /var/www/html/index.html

# 3.4 权限相关练习

场景 1 需求：

  1. 创建 project_a、project_b 两个组；
  2. 创建用户 a1、a2、b1、b2 四个用户；
  3. 将用户 a1、a2 添加到 project_a 组，用户 b1、b2 添加到 project_b 组；
  4. 所有目录以及文件都保存在 /all 目录下；
  5. 在 /all 目录下创建两个项目目录，分别为 project_a、project_b；
  6. 在每个项目下创建一个与用户同名的目录；
  7. 各个项目之间不可以互相访问（project_a 项目不可访问 project_b）；
  8. 相同部门用户之间可以互相查看文件内容，但不可以修改；用户自己创建的文件自己可以修改。
# 需求 1-3：创建组与用户
[root@web ~]# groupadd project_a
[root@web ~]# groupadd project_b
[root@web ~]# useradd a1 -G project_a
[root@web ~]# useradd a2 -G project_a
[root@web ~]# useradd b1 -G project_b
[root@web ~]# useradd b2 -G project_b

# 需求 4-6：创建目录结构
[root@web ~]# mkdir -p /all
[root@web ~]# mkdir -p /all/{project_a,project_b}
[root@web ~]# mkdir -p /all/project_a/{a1,a2}
[root@web ~]# mkdir -p /all/project_b/{b1,b2}

# 设置权限：项目目录组内可读写执行，其他人无权限（实现项目间隔离）
[root@web ~]# chmod -R 770 /all/project_a
[root@web ~]# chmod -R 770 /all/project_b

# 设置属主属组：各用户目录归各自用户管理
[root@web ~]# chown -R a1.project_a /all/project_a/a1/
[root@web ~]# chown -R a2.project_a /all/project_a/a2/
[root@web ~]# chown -R b1.project_b /all/project_b/b1/
[root@web ~]# chown -R b2.project_b /all/project_b/b2/

# 四、文件特殊权限

前面学习了 r、w、x 三种基本权限，但在查询系统文件时会发现一些其他权限字母：

  • /usr/bin/passwd 文件，属主本应是 x 的权限位出现了 s；
  • /usr/bin/locate 文件，属组本应是 x 的权限位出现了 s；
  • /tmp 目录，其他人本应是 x 的权限位出现了 t。

这就是特殊权限。

# 4.1 特殊权限 SUID

# 4.1.1 SUID 产生背景

Linux 系统中，每个普通用户都可以更改自己的密码，这是合理的设置；但用户密码信息存储在 /etc/shadow 文件中，而 /etc/shadow 文件不允许任何人修改：

[root@web ~]# ls -l /etc/shadow
---------- 1 root root 11409 Apr 13 03:26 /etc/shadow

普通用户能修改自己的密码，原因在于 passwd 命令本身拥有特殊权限 setUID——在属主的权限位的执行权限上是 s。理解特殊权限 setUID：当一个执行文件设置 SetUID 后，用户在执行这个文件时，将以文件所有者的身份来执行。

当普通用户 oldwang 执行 passwd 命令时会发生的变化：

  1. 由于 passwd 命令拥有 suid 特殊权限（命令属主权限位有一个 S）；
  2. 所以 passwd 命令在执行过程中，会以命令的属主身份运行（即 root 身份）；
  3. 总结：oldwang → passwd → 转换为命令属主身份 root 执行 → 操作 /etc/shadow 完成信息变更。

# 4.1.2 SUID 配置语法

[root@web ~]# chmod u+s /usr/bin/cat
[root@web ~]# chmod 4755 /usr/bin/cat

# 4.1.3 SUID 作用总结

  1. 让普通用户对可执行的二进制文件，临时拥有二进制文件的所属主权限；
  2. 如果设置的二进制文件没有执行权限，那么 suid 的权限显示就是大写 S；
  3. 特殊权限 suid 仅对二进制可执行程序有效，其他文件或目录则无效。

注意：suid 相对危险，不建议对 vim 或 rm 进行 suid 设定操作。

# 4.2 特殊权限 SGID

# 4.2.1 什么是 SGID

  • SGID 设置在二进制可执行文件上：命令在执行的过程中，会以命令的属组身份运行该命令；
  • SGID 设置在目录上：在该目录下新建的文件/目录自动继承父目录的属组。

# 4.2.2 SGID 配置语法

[root@web ~]# chmod g+s /dir
[root@web ~]# chmod 2755 /dir

# 4.2.3 SGID 场景说明

需求：系统有两个用户 ex1 与 ex2，这两个用户都拥有 example 附加组：

  1. 这两个用户需要共同拥有 /data/code 目录的开发权；
  2. 互相之间能修改彼此的文件，且该目录不允许其他人进入查阅。
[root@web ~]# groupadd example
[root@web ~]# useradd ex1 -G example
[root@web ~]# useradd ex2 -G example
[root@web ~]# mkdir /data/code
[root@web ~]# chgrp example /data/code/
[root@web ~]# chmod 770 /data/code/
[root@web ~]# chmod 2770 /data/code/    # 设置 SGID，新建文件自动继承 example 属组

# 4.3 特殊权限 SBIT

# 4.3.1 什么是 SBIT

一旦目录被赋予了粘滞位（Sticky Bit），除了 root 可以删除目录中的所有文件，普通用户对该目录就算拥有 w 权限，也只能删除自己建立的文件，而不能删除其他用户建立的文件。

# 4.3.2 SBIT 配置示例

需求：默认情况下 /tmp 不是粘滞位，如何将此目录设置为粘滞位？

[root@web ~]# chmod 1755 /tmp
[root@web ~]# chmod o+t /tmp

# 4.3.3 SBIT 使用场景

后期初始化 MySQL 服务时，服务会创建一些临时文件存储至 /tmp 目录下，初始化完毕后自己会清理掉里面的数据，别人无法清理（如果这个目录不是粘滞位，那么初始化 MySQL 就会报错）。编写 shell 脚本模拟此场景：

  1. 模拟 MySQL 初始化创建文件至 /tmp；
  2. 模拟普通用户登录系统删除 MySQL 的初始化文件；
  3. 如果普通用户删除成功，则初始化失败（因为 MySQL 服务创建的文件，需要自行销毁）；
  4. 设置粘滞位后，MySQL 服务尝试删除，删除成功，则初始化成功。

Shell 脚本如下：

#!/usr/bin/bash
mysql_tmp_file=/tmp/mysql.init
User=oldwang

# 1. 模拟 MySQL 创建初始化文件
touch ${mysql_tmp_file}

# 2. 模拟普通用户删除
useradd oldwang
su - ${User} -c "rm -f ${mysql_tmp_file} &>/dev/null"

# 3. 判断删除是否成功
if [ $? -eq 0 ];then
    echo "${mysql_tmp_file} 文件被 ${User} 用户删除成功，该目录不是sbit，mysql初始化失败"
else
    echo "${mysql_tmp_file} 文件被 ${User} 用户删除失败，该目录是sbit，mysql初始化成功"
fi

结果测试与验证：

# 默认 /tmp 为粘滞位
[root@web ~]# sh mysql_init.sh
/tmp/mysql.init 文件被 oldwang 用户删除失败，该目录是sbit，mysql初始化成功

# 取消粘滞位后
[root@web ~]# chmod 777 /tmp/
[root@web ~]# sh mysql_init.sh
/tmp/mysql.init 文件被 oldwang 用户删除成功，该目录不是sbit，mysql初始化失败

# 4.3.4 SBIT 作用总结

  1. 让所有普通用户对该目录具有写入权限，并且能实现每个用户只能删自己的文件；
  2. 粘滞位目录表现在 others 的 x 位，用 t 表示，如果没有执行权限则显示为 T；
  3. 粘滞位目录的属主以及 root 用户有权限删除目录中的内容，其他用户无权限删除。

# 4.4 特殊权限相关练习

场景 1 需求： 假如你是一个员工组的团队领导，为 zzz 公司工作：

  1. 公司要求创建一个 dir_zzz 目录；
  2. 让 ops 组成员都能在该目录下创建或访问文件；
  3. 但是除了文件创建者之外的其他人不能删除文件，你会怎么做？
[root@web ~]# chgrp ops /dir_zzz       # 目录属组设为 ops
[root@web ~]# chmod g+s /dir_zzz       # 设置 SGID，新建文件继承 ops 属组
[root@web ~]# chmod o+t /dir_zzz       # 设置粘滞位，只能删自己的文件

# 五、文件特殊属性

# 5.1 什么是特殊属性

这类文件属性凌驾于 rwx 基础权限之上，是一种高级属性。

# 5.2 特殊属性的作用

  1. 创建一个文件，不允许被修改、移动、删除，包括 root 也不行——适合 /etc/passwd；
  2. 创建一个文件，仅允许往文件里面追加数据，不允许修改、移动、删除——适合 sudo 审计日志。

# 5.3 特殊属性如何配置

Linux 系统通过 chattr 来实现特殊属性的配置。

命令格式：

chattr [+-=] [选项] 文件或目录名

常用选项：

  • a：可对文件进行追加内容；
  • i：锁定文件，不允许其他操作（修改、删除等）。

配置 /etc/passwd 文件：不能改、不能追加、不能删除

# 1. 锁定文件
[root@web ~]# chattr +i /etc/passwd

# 2. 尝试删除，提示不允许
[root@web ~]# rm -f /etc/passwd
rm: cannot remove '/etc/passwd': Operation not permitted

配置 /var/log/secure 文件：只能追加写入日志，不允许手动修改，也不允许删除

# 1. 设置追加属性，查看结果
[root@web ~]# chattr +a /var/log/secure
[root@web ~]# lsattr /var/log/secure
-----a---------- /var/log/secure

# 2. 验证追加写入正常
[root@web ~]# echo "test" >> /var/log/secure
[root@web ~]# echo "test" >> /var/log/secure

# 3. 验证删除、修改被拒绝
[root@oldboy tmp]# rm -f /var/log/secure
rm: cannot remove '/var/log/secure': Operation not permitted

取消特殊属性（需要 root 身份）：

[root@web ~]# chattr -i /etc/passwd
[root@web ~]# chattr -a /var/log/secure

# 5.4 特殊属性场景示例

场景：模拟病毒篡改站点，然后使用 chattr 锁住文件，让病毒程序无法篡改，再追踪并杀死病毒程序。

步骤 1：安装 http 服务并启动对外

[root@web ~]# setenforce 0
[root@web ~]# systemctl stop firewalld
[root@web ~]# systemctl disable firewalld
[root@web ~]# yum install httpd -y
[root@web ~]# systemctl start httpd

步骤 2：编写病毒脚本，定时篡改网页内容

[root@web ~]# cat /usr/bin/virus
#!/usr/bin/bash
web_site=/var/www/html/index.html
while true
do
    # 1. 篡改网页内容
    echo "我是病毒的Code" > ${web_site}
    sleep 16
    # 2. 写入定时任务，定时执行病毒脚本
    echo "*/1 * * * * /bin/bash -x /usr/bin/virus &>/tmp/virus.log" > /var/spool/cron/root
    # 3. 锁定病毒脚本，防止被删除
    chattr +i /usr/bin/virus
done

步骤 3：锁定篡改文件，然后杀死病毒

# 清空并锁定 cron 任务文件，防止病毒再次启动
[root@web ~]# > /var/spool/cron/root
[root@web ~]# chattr +i /var/spool/cron/root

# 恢复正常网页内容并锁定，防止被再次篡改
[root@web ~]# echo "Hello Web Server" > /var/www/html/index.html
[root@web ~]# chattr +i /var/www/html/index.html

# 找出病毒进程并杀死
[root@web ~]# kill $(ps -ef | grep virus | grep -v grep | awk '{print $2}')

# 六、文件默认权限

# 6.1 什么是默认权限

默认权限指用户在创建文件或目录时，默认分配给文件或目录的访问权限。

# 6.2 默认权限的由来

背景：

  1. 用户创建一个文件的默认访问权限为：rw-rw-rw-（八进制值 666）；
  2. 用户创建一个目录的默认访问权限为：rwxrwxrwx（八进制值 777）；
  3. 但最终创建出来的文件权限是 644、目录是 755，为什么目录不是 777、文件不是 666 呢？

分析：系统创建文件或目录受 umask 控制，比如 umask 设置为 022：

  • 目录：777 - 022 = 755，即最终创建出来的目录权限；
  • 文件：666 - 022 = 644，即最终创建出来的文件权限。

结论：umask 表示要减掉的权限。

# 6.3 系统默认权限配置文件

为什么默认 root 用户的 umask 为 022？在系统中由如下配置文件设定：

  1. 用户登录系统时，会加载 /etc/profile 环境变量文件；
  2. 在该配置文件中有一条 umask 的判断语句；
  3. 如果用户 UID 小于 199，那么就将 umask 初始化为 022；
  4. 如果用户 UID 大于 199，并且组名称和用户名称一致，那么就将 umask 初始化为 022。

umask 判断语句如下：

[root@web ~]# vim /etc/profile
if [ $UID -gt 199 ] && [ `/usr/bin/id -gn` = `/usr/bin/id -un` ]; then
    umask 022
else
    umask 022
fi

# 6.4 默认权限的计算公式

核心公式：最终权限 = 默认权限 - umask（umask 中减掉的是哪些位，最终权限中对应位就没有）。

示例 1：假设 umask 为 022（所有人位为 0）

# 文件默认 666
666 - 022 = 644

# 目录默认 777
777 - 022 = 755

示例 2：修改 umask 为 045（用户位全有）

# 文件默认 666
666 - 045 = 621

# 目录默认 777
777 - 045 = 732

示例 3：umask 044

# mkdir dir44，目录权限
777 - 044 = 733

# touch f044，文件权限
666 - 044 = 622

示例 4：umask 023

# mkdir dir23，目录权限
777 - 023 = 754

# touch f023，文件权限
666 - 023 = 643 + 001 = 644

示例 5：umask 032

# mkdir dir32，目录权限
777 - 032 = 745

# touch f032，文件权限
666 - 032 = 634 + 010 = 644

示例 6：umask 035

# mkdir dir35，目录权限
777 - 035 = 742

# touch f035，文件权限
666 - 035 = 631 + 011 = 642

注意：文件的最终权限不会出现执行（x）位。当 umask 减去了执行位时，文件权限会在结果基础上把对应执行位补回（如 643 + 001 = 644），而目录则不做补回。
