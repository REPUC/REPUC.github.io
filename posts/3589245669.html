# Nginx 配置体系与核心模块

本文深入 Nginx 的核心配置体系：配置文件结构、全局配置与 http 配置块、虚拟主机、root 与 alias、以及最重要的 location 指令（匹配规则与优先级）。掌握这些，才能正确编写和调试 Nginx 站点配置。

# 一、配置文件说明

Nginx 官方帮助文档：http://nginx.org/en/docs/ ；Tengine 文档：https://tengine.taobao.org/nginx_docs/cn/docs/

配置文件组成部分：

  • 主配置文件：nginx.conf；
  • 子配置文件：include conf.d/*.conf；
  • FastCGI/uWSGI/SCGI 等协议相关配置文件（conf 目录）：fastcgi_params、uwsgi_params、scgi_params；
  • mime.types：支持的 MIME 类型。MIME（Multipurpose Internet Mail Extensions）多用途互联网邮件扩展类型，设定某种扩展名文件用何种应用程序打开，多用于指定客户端自定义文件名及媒体文件打开方式。

配置文件格式：

  1. 由"指令"与"指令块"构成；
  2. 每条指令以 ; 分号结尾，指令与值之间以空格分隔；
  3. 多条指令可放同一行（分号分隔），但可读性差，不推荐；
  4. 指令块以 { } 大括号组织多条指令，可嵌套；
  5. include 语句组合多个配置文件提升可维护性；
  6. # 符号添加注释；
  7. $ 符号使用变量；
  8. 部分指令参数支持正则表达式。

指令方式：directive value [value2 ...];

  • 指令必须以分号结尾；
  • 支持配置变量：内建变量（由 Nginx 模块引入，可直接引用）、自定义变量（用 set 命令定义，格式 set variable_name value;）、引用变量 $variable_name。

主配置文件结构（四部分）：

# 全局配置段（main block）：对 http、mail 都有效
user nginx nginx;
worker_processes auto;
pid /apps/nginx/run/nginx.pid;

# 事件驱动相关配置
events {
    worker_connections 1024;
}

# http/https 协议相关配置段（核心配置段，常用）
http {
    ...
}

# mail 协议相关配置段（默认不含）
# mail { ... }

# stream 服务器相关配置段（默认不含，1.9+ 支持 TCP 代理）
# stream { ... }

默认 nginx.conf 说明（去除注释空行）：

user  nginx nginx;              # worker 进程的运行用户/组
worker_processes  4|auto;       # 工作进程数，建议与 CPU 核心数一致（auto 自动识别）

events {                       # 影响 nginx 与用户的网络连接
    worker_connections  1024;  # 单个 worker 最大并发；Web 服务器为 worker_connections * worker_processes，反向代理为 (worker_connections * worker_processes)/2
}

http {                         # 缓存、代理、日志格式等绝大多数功能在此设置
    include    mime.types;
    default_type  application/octet-stream;
    log_format  main  '$remote_addr - $remote_user [$time_local] "$request" '
                      '$status $body_bytes_sent "$http_referer" '
                      '"$http_user_agent" "$http_x_forwarded_for"';
    access_log  /var/log/nginx/access.log  main;
    sendfile        on;         # 开启 sendfile 加快静态文件传输（零拷贝）
    keepalive_timeout  65;      # 长连接超时（秒）
    include /etc/nginx/conf.d/*.conf;

    server {                    # 虚拟主机
        listen    80;           # 监听端口
        server_name localhost;  # server 名称
        location / {            # location：基于请求字符串匹配处理
            root  html;         # 默认页面目录
            index index.html index.htm;   # 默认页面文件
        }
        error_page  500 502 503 504 /50x.html;   # 错误页面
        location = /50x.html {
            root  html;
        }
    }
}

# 二、Main 全局配置

全局配置段常见指令分类：正常运行必备、优化性能、调试定位问题、事件驱动相关。性能优化中至关重要的指令：

指令说明
worker_processes工作进程数量，是 Nginx 并发处理的关键，建议设为核心数或 auto
worker_cpu_affinity多 CPU 服务器上，将 worker 进程绑定到指定 CPU 核心，避免进程在核心间跳转，减少 CPU 资源分配与回收及内存管理的损耗，提升性能（建议 auto）
worker_priorityworker 进程优先级，类似 nice，范围 -20~19，数字越小优先级越高，默认 0；希望 Nginx 占更多资源可设更小值，但不建议小于内核进程的 nice 值（通常 -5）
worker_rlimit_nofileworker 进程可打开的最大句柄描述符数，设高可避免 too many open files，最好与 ulimit -n 或 limits.conf 一致
worker_connections每个 worker 的最大连接数，默认 1024；总连接数 = worker_processes × worker_connections，但连接数含与客户端及与代理后端的连接，不代表并发能力，具体按压测确定
accept_mutex多个 worker 时，使每个可用 worker 逐个接受新连接，防止多个睡眠进程同时被唤醒（惊群），提高稳定性
multi_accept使 worker 获得新连接通知时尽可能多接受连接（立即接受监听队列中所有连接），否则逐个接受

# worker_cpu_affinity（CPU 亲和性）

CPU MASK：00000001 0号CPU、00000010 1号CPU、10000000 7号CPU。

# 利用 auto 绑定 CPU，自动识别系统 CPU 核心数
worker_processes auto;
worker_cpu_affinity auto;

# 限制自动绑定的 CPU
worker_cpu_affinity auto 01010101;

# 验证 CPU 与 worker 进程绑定关系
ps axo pid,cmd,psr | grep nginx

# 错误日志与 pid

error_log /apps/nginx/logs/error.log error;   # 语法: error_log file [debug|info|notice|warn|error|crit|alert|emerg]
pid       /apps/nginx/logs/nginx.pid;         # 记录主进程 PID
worker_priority 0;                            # worker 优先级，-20~19
# 验证 worker 优先级（top 的 NI 列 / ps 的 ni）
ps axo cmd,pid,ni | grep nginx

# worker_rlimit_nofile（打开文件数上限）

worker_rlimit_nofile 65536;   # 所有 worker 能打开的文件数量上限（含与代理后端的连接），最好与系统 ulimit 一致
# 查看 nginx 主进程的最大打开文件数
cat /apps/nginx/logs/nginx.pid        # 获取主进程 PID
cat /proc/<PID>/limits               # 查看 Max open files
# 修改操作系统最大打开文件数
vim /etc/security/limits.conf
*               soft   nofile          1000000
*               hard   nofile          1000000

# 注意：nginx 为 systemd 启动时，需在 nginx.service 中加 LimitNOFILE=100000 才生效
vim /etc/systemd/system/nginx.service
LimitNOFILE=100000

daemon off;              # 前台运行，用于测试或容器场景（不常用）
master_process off|on;   # 是否开启 master-worker 模式，仅开发调试用，默认 on

# events 代码块

events {
    worker_connections  65536;   # 单个 worker 最大并发连接数，生产建议调大
    use epoll;                    # 事件驱动模型（select/poll/epoll），默认选系统最优
    accept_mutex on;              # 建议 on，防止惊群，提高稳定性
    multi_accept on;              # 建议 on，同时接受多个新连接
}

高并发配置示例：

ulimit -n 102400
yum install httpd-tools -y
while true;do ab -c 5000 -n 10000 http://192.168.80.8/;sleep 0.5;done

注意：CentOS7/Rocky8 默认 Max open files 较低（1024），需调整。systemd 启动的 nginx 需在 service 文件加 LimitNOFILE；非 systemd 启动则修改 limits.conf。

worker_rlimit_nofile 40000;     # 由 2 核 CPU × worker_connections 20000 得出
events {
    worker_connections  20000;
    use epoll;
}

# 四、常见核心模块配置

基于不同的 IP、端口、域名实现不同虚拟主机，依赖核心模块 ngx_http_core_module。

# 4.1 MIME

在响应报文中将文件扩展名映射至 MIME 类型：

include    /etc/nginx/mime.types;
default_type    application/octet-stream;   # mime.types 之外的默认 MIME 类型

types {
    text/html html;
    image/gif gif;
    image/jpeg jpg;
}

示例：设置默认识别格式为 text/plain

# 准备 PHP 文件
vim /apps/nginx/html/test.php
<?php phpinfo(); ?>

# 验证默认识别为 application/octet-stream（浏览器直接下载）
curl 192.168.80.8/test.php -I   # Content-Type: application/octet-stream

# 修改配置
vim /apps/nginx/conf/nginx.conf
http {
   include       mime.types;
   default_type  text/plain;    # 修改该行
nginx -s reload

# 再次验证
curl 192.168.80.8/test.php -I   # Content-Type: text/plain（浏览器显示文本内容）

# 4.2 指定响应报文 Server 首部（隐藏版本号）

# 是否在响应报文 Server 首部显示 nginx 版本：server_tokens on|off|build|string
server_tokens off;    # 隐藏 nginx 主版本号信息

扩展：修改源码中的 Server 字段

  • server_tokens on（显示版本）：修改 src/core/nginx.h 的 NGINX_VERSION、NGINX_VER；
  • server_tokens off（不显示版本）：修改 src/http/ngx_http_header_filter_module.c 的 ngx_http_server_string。
# 基于源码修改 nginx 版本信息
vim /usr/local/src/nginx-1.22.1/src/core/nginx.h
# define NGINX_VERSION     "1.66.6"
# define NGINX_VER         "custom-nginx/" NGINX_VERSION

vim nginx-1.22.1/src/http/ngx_http_header_filter_module.c
static u_char ngx_http_server_string[] = "Server: custom-nginx" CRLF;

# 重新编译
cd /usr/local/src/nginx-1.22.1
./configure --prefix=/apps/nginx ... 
make && make install
nginx -t && nginx -s reload

# 验证：Server: custom-nginx/1.66.6
# 再 server_tokens off 后：Server: custom-nginx

# 4.3 指定字符集

指定字符集 utf-8，防止网页乱码。UTF-8 是万国码，GB2312 是中国国家标准简体中文字符集。

# 是否在响应报文 Content-Type 显示指定字符集，默认 off 不显示
charset charset | off;
charset utf-8;   # UTF-8 世界通用，中日韩阿拉伯文均可正常显示

前端工程师一般会在 html 文件中配置好 utf-8，即使 nginx 未定义也不会乱码。

# 五、虚拟主机

# 5.1 新建 PC 端 Web 站点

基于 nginx 实现访问对应域名跳转对应站点目录。

# 创建子配置文件目录
mkdir /apps/nginx/conf/conf.d

# 在 nginx.conf 的 http 块末尾（不要放最前面，否则前面命令无法生效）添加 include
vim /apps/nginx/conf/nginx.conf
http {
    ...
    include /apps/nginx/conf/conf.d/*.conf;
}

# 创建 PC 网站子配置文件
vim /apps/nginx/conf/conf.d/pc.conf
server {
    listen 80 default_server;             // 监听 80，并定义为默认站点（IP 访问时跳转）
    server_name www.example.org example.org;   // 定义域名（可多个，指向一个站点目录）
    root /data/nginx/html/pc;             # 站点目录路径
}

# 创建站点目录、上传站点文件
mkdir -p /data/nginx/html/pc
cd /data/nginx/html/pc && rz

# 生效配置
nginx -t
nginx -s reload   # 或 systemctl reload nginx

访问 http://www.example.org/ 及 http://example.org/ 测试。

注意：基于本地 DNS（hosts）访问时，需关闭本地翻墙代理（如 V2rayN 等）；若自解析网址与公网重复，浏览器可能解析至公网站点（浏览器缓存原因），可用无痕模式访问。

# 5.2 新建 Mobile 端 Web 站点

大部分网站根据访问设备类型跳转对应站点。

# conf.d/mobile.conf
server {
    listen 80;
    server_name m.example.org;          # 第二个站点名称
    root /data/nginx/html/mobile;      # 站点目录
}
mkdir -p /data/nginx/html/mobile
cd /data/nginx/html/mobile && rz
nginx -s reload

访问 http://m.example.org 测试。

知识点：站点根据用户访问时发送的 Host 请求头（如 www.example.org、m.example.org）决定调度到哪个站点目录。通过 IP 访问 http://192.168.80.8/ 会优先跳转定义了 default_server 的站点；未指定 default_server 时，可用 nginx -T 查看站点优先级，默认优先访问配置在最上边的站点。

# 六、root 与 alias 指令

访问网站出现 404 时，可能是文件不存在，也可能是配置导致。需加深对 root 与 alias 的理解。二者都属于 ngx_http_core_module 模块，是核心功能指令。root 可用于 http/server/location，alias 仅可用于 location。

root：指定对应网站的根目录。定义 location 时，文件绝对路径 = root / location。

server {
    listen 80;
    server_name www.example.org;
    location / {
        root /data/nginx/html/pc;    # 站点根目录
    }
    location /about {
        root /opt/html;              # root 定义根目录，因此 about 目录必须存在于 /opt/html 下，否则报错
    }
}
echo 站点-根目录 > /data/nginx/html/pc/index.html
mkdir -p /opt/html/about
echo 站点-about目录 > /opt/html/about/index.html
nginx -t && nginx -s reload
# 访问：站点根目录 http://www.example.org/index.html；about 目录 http://www.example.org/about/

alias：定义路径别名，把访问路径重新定义到指定路径，是文档映射的另一种机制，仅用于 location，使用较少。

server {
    listen 80;
    server_name www.example.org;
    location / {
        root /data/nginx/html/pc;
    }
    location /about {              # 注意 about 后不要加 /，用 alias 时 uri 后加斜杠则下面路径必须加斜杠，否则 403
        alias /opt/html/about;     # 访问 about 时显示 alias 定义的 /opt/html/about 内容
    }
}

root 与 alias 的区别（重点）：

  • root 给定的路径对应 location 中 /uri 左侧的 /；
  • alias 给定的路径对应 location 中 /uri 的完整路径。

# 七、location 指令（重点）

在一个 server 中 location 配置段可存在多个，用于实现从 uri 到文件系统的路径映射。nginx 根据用户请求的 URI 检查所有 location，按优先级找出最佳匹配，应用其配置。

语法规则：

location [ = | ~ | ~* | ^~ ] uri { ... }
符号说明
=精确匹配，请求字串与 uri 完全一致（大小写敏感），匹配成功即停止向下匹配并立即处理
^~URI 以指定字符串开头，匹配以该正则开头的 uri 最左部分，不区分大小写，匹配则搜索停止
~区分大小写的正则匹配
~*不区分大小写的正则匹配
\转义字符，将 . * ? 等转义为普通符号

匹配优先级从高到低：= > ^~ > ~/~*（正则顺序） > 不带符号（完整路径） > 部分起始路径 > /

官方范例与匹配结果：

location = / { [configuration A] }
location / { [configuration B] }
location /documents/ { [configuration C] }
location ^~ /images/ { [configuration D] }
location ~* \.(gif|jpg|jpeg)$ { [configuration E] }
  • / → 匹配 A；/index.html → 匹配 B；/documents/document.html → 匹配 C；/images/1.gif → 匹配 D；/documents/1.jpg → 匹配 E。

location 优先级完整表述：

(location =) > (location ^~ 路径) > (location ~,~* 正则顺序) > (location 完整路径) > (location 部分起始路径) > (/)

# 7.1 精确匹配 =

一般用于匹配组织的 logo 等相对固定的 URL，匹配优先级最高。

location = /logo.jpg {     # = 精确匹配
    root /data/nginx/images;
    index index.html;
}
# 创建 images 目录，上传 logo.jpg，重启并访问 http://www.example.org/logo.jpg

# 7.2 区分大小写 ~

location ~ /A.?\.jpg {     # 匹配字母 A 开头的 jpg 图片，? 表示 A 后零次或一次字符
    root /data/nginx/images;
}
# ~ 区分大小写，只能访问小写 jpg 结尾，不能识别大写 JPG

# 7.3 不区分大小写 ~*

通常用此模式匹配用户 request 中的静态资源。注意：此模式忽略 uri 部分大小写，但 Linux 文件系统仍区分大小写，磁盘文件不存在仍提示 404。

location ~* /A.?\.jpg {
    root /data/nginx/images;
}
# 不区分大小写，可访问任意大小写结尾的图片（但要求磁盘上有对应文件）

# 7.4 URI 开始 ^~

表示 URI 以某字符串开头，匹配则搜索停止。可用于实现动静分离。

location ^~ /images {
    root /data/nginx/;
    index index.html;
}
location /api {
    alias /data/nginx/api;
    index index.html;
}
# 动静分离：访问 /images 和 /api 返回不同结果

# 7.5 文件名后缀匹配

location ~* \.(gif|jpg|jpeg|bmp|png|tiff|tif|ico|wmf|js|css)$ {
    root /data/nginx/static;
    index index.html;
}

# 7.6 优先级案例

location = /1.jpg { root /data/nginx/static1; }
location /1.jpg { root /data/nginx/static2; }
location ~* \.(gif|jpg|jpeg|bmp|png|tiff|tif|ico|wmf|js)$ { root /data/nginx/static3; }
# 匹配优先级：= > ^~ > ～/～* > /

# 7.7 生产使用案例

# 直接匹配网站根，加速访问处理
location = /index.html { ...; }
location / { ...; }

# 静态资源配置方法 1
location ^~ /static/ { ...; }
# 静态资源配置方法 2（应用较多）
location ~* \.(gif|jpg|jpeg|png|css|js|ico)$ { ...; }

# 多应用配置
location ~* /app1 { ...; }
location ~* /app2 { ...; }

# 7.8 Location @重定向

location @name 不用于常规请求处理，而是用于请求重定向。如访问 URL 找不到文件（404）时返回特定信息页面。

server {
    listen 80 default_server;
    server_name www.example.org example.org;
    location / {
        root /data/nginx/html/pc;
    }
    error_page 404 @error_404;       # 出现异常重新定向到 @error_404
    location @error_404 {
        default_type text/html;
        charset utf8;
        return 200 '你访问的页面可能走丢了!';
    }
}

# 7.9 自定义 404 页面

error_page 404 后跟 /error/404.html 相当于访问 http://localhost/error/404.html，被 location /error 捕获。

server {
    listen 80 default_server;
    server_name www.example.org example.org;
    location / {
        root /data/nginx/html/pc;
    }
    error_page 404 /error/404.html;      # 自定义 404 页面
    location /error {
        alias /var/www/html/error;
    }
}
mkdir -p /var/www/html/error
vim /var/www/html/error/404.html   # 编写 404 页面（HTML）
nginx -s reload
# 访问不存在的页面验证：http://example.org/1233322
